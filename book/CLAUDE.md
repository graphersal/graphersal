# Book (mdBook, `mdbook build book`)

Agent guidance. This file is outside `book/src/` and is not part of the book.

- Five parts plus Project: Getting Started (`getting_started/`: playground tour, CLI, dev server/MCP/AI Chat, screenshots in `src/images/getting_started/`), Graphs and Gremlin (`concepts/`), Using Graphersal (`library/`: the Rust quick start includes `crates/graphersal/examples/quick_start.rs` by its `ANCHOR`s, so keep that example running; Python; persistence), The Gremlin DSL (`dsl/` section pages over the topic pages in `users_guide/`, the section Dates and Times `dates/`, the step reference), Under the Hood (optimizer, format spec, compliance).
- Page files stay where they are (URLs and code references cite them); the part a page belongs to is decided in `SUMMARY.md` only.
- **Runnable examples:** a DSL example that runs on a sample graph is fenced ```` ```rhai,graph=<modern|empty|large|tree> ````. `book/playground-links.js` gives every statement a run button in the margin (one statement: a "Run in the playground" link under it; `playground/js/link.js` format). `graphersal-session`'s test `book_playground_examples` splits the block the same way and runs each statement on its sample: a statement whose comment says `error`/`fails`/`refused`/`denied` must fail, every other must succeed. Dependent statements (`let`, a write then a read) take `,script`: the whole block is one link and one run. **Never use the marker `playground`** (mdBook makes `.playground` a Rust playground).
- **The step reference is GENERATED** from the function catalogue (`views::completion_entries`, texts of `register/docs.rs`) by `graphersal-session`'s test `book_step_reference`: one page per step `traversal/steps/<name>.md` (a page without the generated first line is hand-written and kept), `traversal/functions/*.md` (predicates, tokens and values, `Fake`), the category index on `traversal/step_reference.md` and the alphabetical entries in `SUMMARY.md` (between `<!-- steps:begin -->` and `<!-- steps:end -->`). It fails on drift, a leftover generated page, or a step missing from its `CATEGORIES` table (add new steps there). Regenerate with `GRAPHERSAL_UPDATE_BOOK=1 cargo test -p graphersal-session --test book_step_reference`, never by hand.
- **Rust blocks are tested:** `book/test.sh` builds `graphersal` (all acceptance features) in `target/mdbook-test` (one rlib, git-ignored) and runs `mdbook test book` with `-L` plus a `rustdoc` PATH shim that adds `--extern graphersal=...` (mdbook has no such option; `book.toml` `[rust] edition = "2024"` is needed for the extern prelude). A block that cannot compile by nature is `rust,ignore` (today: needs `serde_json` in `transactions.md`, feature `model2vec` in `vectors.md`); verbatim program output is a `text` block, never a bare fence.
- Other generated blocks: TinkerPop compliance (`for_developers/tinkerpop_compliance.md`, `TINKERPOP_UPDATE_BASELINE=1`), the openCypher TCK compliance (`gql/tck_compliance.md`, `<!-- opencypher:begin/end -->`, `OPENCYPHER_UPDATE_BASELINE=1`), the store upgrade table (`<!-- upgrades:begin/end -->`, `GRAPHERSAL_UPDATE_BOOK=1`).
- `persistence/format.md` is the normative format spec ("format spec N" in code); `persistence/creation_parameters.md` holds the creation-parameter table (root rule 22); `for_developers/tinkerpop_deviations.md` the deviation list (root rule 18); `for_developers/test_coverage.md` the coverage recipe and last numbers.
- Never link `ai/` working files from published pages.
