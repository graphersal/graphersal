# graphersal-storage-tests

Conformance tests for implementations of the [`graphersal`](https://crates.io/crates/graphersal)
`GraphStorage` trait.

> **EXPERIMENTAL.** Like the `GraphStorage` trait itself, this suite may change in any minor
> release before 1.0 (also in a 0.2.x release): items may be added, renamed or tightened when the
> trait changes. Pin the exact version, the same as `graphersal`'s.

## Usage

In the crate that implements `GraphStorage`:

```toml
[dev-dependencies]
graphersal-storage-tests = "=0.2.0"
```

```rust
// tests/conformance.rs
use my_crate::MyStorage;

graphersal_storage_tests::conformance!(my_storage, base = MyStorage::new() => base);
```

expands to a module `my_storage` with one `#[test]` per contract item (`explicit_vertex_ids_are_preserved`,
`jpath_writes_create_append_and_fault`, ...), each running against a fresh storage, so a failure names the item.
The part after `=>` is the expression that yields the storage under test, which is how a wrapper is exercised:
`conformance!(by_mut_ref, base = MyStorage::new() => &mut base)`.

The suite uses only `graphersal`'s public API, so everything it checks can be implemented outside `graphersal`
(the write checks a storage needs are public: `graphersal::storage::{check_property_value, check_properties,
check_label, normalize_vertex_labels, write_path, ...}`).

- **Schemas are optional.** The schema items (`schema_application_failure_leaves_graph_and_schema_unchanged`,
  `schema_modes_enforce_declared_properties`, `add_applies_schema_defaults_insert_does_not` (the create path
  `add_vertex`/`add_edge` fills schema defaults, the primitive `insert_vertex`/`insert_edge` does not), and the
  schema write in `rollback_restores_everything`) check enforcement only for a storage that supports schemas:
  when `set_schema` returns `GraphError::Unsupported` (the trait default) they return early and pass. Schema
  enforcement is not reusable outside `graphersal` yet, so a storage in another crate keeps that default. `conformance_core!` is `conformance!` without the schema items,
  for a storage that accepts schemas but deliberately does not enforce them.
- The items are public functions in `contract` (`fn item<S: GraphStorage>(storage: &mut S)`), the invariant checker is
  `contract::assert_consistent`, and `contract::read_only_rejects_writes` covers read-only storages (it needs a
  populated storage, so it is not generated).
- `smoke` loads the TinkerPop "modern" graph through the trait only and compares eight traversals with a `TraversalGraph`.
- `extension` holds the capability-conditional items (`book/src/users_guide/transactions.md`), generated by both macros:
  `capabilities_are_consistent` (always), `rollback_restores_everything` and
  `savepoint_rollback_keeps_the_outer_unit`, `unit_changes_never_claims_an_undone_change` (all three when
  `capabilities().atomic`; `unit_changes` is part of the atomic contract: it must report a change of an open unit,
  never an absent or rolled-back one, and count savepoints correctly, so an atomic storage keeping the default `false`
  fails), `commit_hooks_follow_the_capability`
  (with `change_capture`: one change set per changing unit, monotonic `last_commit_seq`, empty units emit nothing,
  a veto rolls back and reaches `after_rollback`; without it: the registration is refused) and
  `applied_change_set_reproduces_the_unit` (with `change_capture`), `applied_change_set_raises_the_id_sequences`
  (with `writable`: after an apply, a new auto id never reuses an id of the change set's source, also one compacted
  away; `GraphStorage::raise_id_sequences`), `edge_label_change_rolls_back_and_is_captured`, and for a storage with
  a catalog of definitions `rollback_restores_definitions` (with `atomic`) and `definition_changes_are_captured`
  (with `change_capture`); for the `Transactional` units `discard_unit_restores_state_keeps_sequences` and
  `transaction_with_metadata_reaches_hooks` (both with `change_capture`: `discard_unit` restores data, schema and
  catalog, keeps the id sequences and calls no hook; `set_unit_metadata` follows the merge rule) and
  `transactional_panic_rolls_back` (with `atomic`).
- `mutation_outside_unit_records_nothing` (both macros, core contract): a mutation outside any unit calls no hook
  and does not move `last_commit_seq`.
- `definitions_are_stored_validated_and_removed` (both macros) checks the catalog of definitions (saved queries):
  insert/replace, order, validation, opaque definitions kept byte for byte, removal; a storage without a catalog
  keeps the trait defaults (nothing listed, writes `Unsupported`) and is checked for exactly that.

In this repository the suite runs against `TraversalGraph`, `&mut TraversalGraph`, `Box<TraversalGraph>`,
`Arc<TraversalGraph>`, the read-only `&TraversalGraph` and `&NoSchema<TraversalGraph>` (the blanket `&G` view), a wrapper outside `graphersal` that keeps the trait's
schema defaults (`tests/no_schema/mod.rs`), and `Forwarding` (also by `&mut`).

## The `Forwarding` helper (EXPERIMENTAL)

`graphersal_storage_tests::forwarding::Forwarding` is a test helper, not part of the contract: a `GraphStorage` that
forwards every method to a wrapped `TraversalGraph` (units, commit hooks, change capture, schema, catalog, statistics,
memory, path writes included; `vertex_has_label`, `infer_schema` and `apply_change_set` keep the trait defaults, as
`TraversalGraph` does), but with its OWN handle types `ForwardVertexId`/`ForwardEdgeId`. Code that silently assumes
`VertexHandle`/`EdgeHandle` does not compile for it, so it proves that a front end works over a storage other than
`TraversalGraph`: wrap it in a `graphersal::storage::Graph` and run the same scripts on both. It passes the full
`conformance!` suite, and `graphersal`'s own `tests/all/foreign_storage_tests.rs` runs every documented DSL example
plus curated mutating, whole-script, dry-run, saved-query, schema, catalog and GraphSON scripts on both storages and
requires identical results. With the feature `persist` it also implements `PersistentStorage` (forwarded), so it can
be written as a packed snapshot and loaded from one; the Store does not take it yet.

```rust
use graphersal::TraversalGraph;
use graphersal::storage::Graph;
use graphersal_storage_tests::forwarding::Forwarding;

let graph = std::sync::Arc::new(Graph::new(Forwarding::new(TraversalGraph::tinkerpop_modern())));
```

## The `Failing` helper (EXPERIMENTAL)

`graphersal_storage_tests::failing::Failing` wraps a `Forwarding` and fails on demand: its shared `Faults`
switches make the statistics, the property indexes, the index lookups, `begin_unit`, `rollback_unit` (after the
wrapped graph rolled back), the execution policy or the schema return `GraphError::StorageFailed`. The tests in
`tests/failing_storage.rs` check that the engine fails the query or unit with that error, never panics, never
answers with made-up data, reports a failed rollback as `GraphError::RollbackFailed`, and that the graph serves
the next operation normally.

## Contract points the trait documents

- `stale_handle_never_aliases`: a handle to a removed element never resolves to another element, also not after the
  backend reuses the slot (documented on `GraphStorage::VertexId`/`EdgeId`). Reads through it behave as "removed"
  (`contains_vertex`/`contains_edge` false, no id, label, properties or adjacency), writes fail with `ElementRemoved`.
  `TraversalGraph` meets it with generational handles (`VertexHandle`/`EdgeHandle`).

## Contract points where the trait is silent (decided by `TraversalGraph`)

- An explicit numeric id raises the auto-id sequence of its element kind; the next auto id is numeric and larger.
- `drop_vertex` / `drop_edge` of a stale handle succeed (idempotent); every other write on a stale handle fails with
  `ElementRemoved { kind }`.
- Removing the primary label makes the next label primary (order is kept).
- Re-adding or re-removing a label is `Ok(false)`, not an error.
- A read-only `&TraversalGraph` rejects writes with `InvalidElementState` (the tests only require an `Err`).
- `insert_edge` to a dropped vertex must return `Err` (the trait documents no error; a panic is never acceptable).

## Violations found and fixed

The first run found two bugs in `TraversalGraph`, both fixed (regression tests in
`crates/graphersal/tests/all/storage_contract_regression_tests.rs`): `add_edge` to a dropped vertex panicked inside
petgraph, and `drop_vertex` left the edge-id and edge-label index entries of its incident edges, so a stale id could
resolve to a different edge after slot reuse. The suite now runs with no ignored test.

## Not covered

- `MockStorage` (in `graph/storage.rs`) is a private `#[cfg(test)]` type and cannot be used from outside the crate.
- Running the vendored TinkerPop suite against a foreign storage: see the book page
  `book/src/for_developers/storage_conformance.md` in the repository.
