# graphersal-cli

Agent guidance for the REPL, the one-shot runner, the dev server, MCP, the AI Chat and `embed-model`. Not packaged (`include` lists the packaged files). Store commands: `crates/graphersal/src/persist/CLAUDE.md`.

## CLI and REPL

- REPL `graphersal>` (`src/repl.rs`): `/` commands (`/help`, `/set`, `/memory [max_elements]` (`memory_answer`: the session's `MemoryBar::text(80)` then the memory report), `/exit`); Tab completion and `/help <name>` read `graphersal_session::views::completion_entries`/`token_values` (the playground's catalogue), never a CLI list. `--repl` runs it on a piped stdin.
- Output only through `out!`/`outln!`/`errln!` (`src/out.rs`); `print!`/`eprintln!` are denied by clippy (they panic on a closed pipe). stdout = result only, stderr = diagnostics and truncation notices. Exit codes `0` ok, `1` script failed, `2` invalid invocation, `141` stdout closed early.
- ONE layout for what the CLI prints (issue #19): a short headline, one indented `key: value` per line, every shell command on its own line under a `# comment` (never inside a sentence), blocks set apart by a blank line; lists of records as one section per record (`src/sections.rs`: `store models`, `store attic`, `embed-model list`, the models a copy carries). Builders in `src/out.rs`: `Note` (`detail`, `command`, `text`, `help` = the engine's multi-line `Help:` layout for errors the CLI builds), `print_note` (stderr notes), `print_block` (stdout results of `store`/`embed-model`), `use_it` (the "open it in the REPL / serve it" commands), `usage_text` (a usage error ending with the help command). Column outputs (`store info`, tables of `store list`/`marks`/`attic changes`) put a command under the value column, below its `# comment`.
- `--server`, `graphersal store` and every mode on a `--graph <store>` install `src/log.rs`, a minimal stderr `tracing` subscriber (no `tracing-subscriber`; `GRAPHERSAL_LOG`, default `warn`; never stdout). SIGINT/SIGTERM (`signals.rs`, ONE `ctrlc` handler per process: `Stop` with a store and a cancel token filled in later): the server ALWAYS installs it (as PID 1 a process without a handler ignores SIGTERM): cancel, `/readyz` 503, close a Store, exit `EXIT_OK`; one-shot/REPL install it with a Store, without one only as PID 1 (`exit_on_signal_as_pid1`, exit 130). Second signal: exit 130.
- `--read-only` (`Cli::read_only`, `GraphSpec::open(.., read_only)`): the graph gets the vetoing commit hook `ReadOnlyGraph` (`HookRefusal`); a Store is loaded with `Store::open_read_only` (no lock, nothing written) + `Recovered::into_graph` (the view serves its models), `Opened.store = None`. A read-write open failing with an I/O `PermissionDenied`/`ReadOnlyFilesystem` falls back to it with a note (`StoreOpenError::NotWritable`). Excludes `--create-store`. The server: `Context.read_only`, `/api/info` `readOnly`, `POST /api/save` 409, MCP forced read-only, banner `READ_ONLY_BANNER` + Graph row `access`.
- `graphersal health [--ready] [--host] [--port] [--timeout]` (`src/health.rs`, dispatched in `main.rs` like `store`): one `std::net` HTTP/1.1 GET of `/healthz`/`/readyz`; exit 0 on 200, 1 otherwise (reason on stderr), 2 usage; nothing on stdout.
- Scripts evaluate on a 64 MiB stack thread (`main.rs`), which also installs the `alloc-tracking` allocator.

- `--args-file FILE` / `@FILE` (`src/args_file.rs`, JSON, `serde_json` always built): `Cli::parse` first translates the file into `--key=value` arguments PREPENDED to the real ones, then the one parser runs (the command line wins by position, repeatable flags concatenate, validation runs on the merged list). Keys = long flag names (`KEYS` table; a test checks each is in `HELP`: add a new flag there too); `_` keys silent, every other unknown key a hard error with a did-you-mean (unlike `--ai`: a dropped `mcp-read-only` must not go unnoticed); relative paths resolve against the file; `-e @x` is a script (the scan skips flag values via `VALUE_FLAGS`: add a new value flag there). Errors name the key, never echo values.

## Dev server (`--server`, feature `dev-server`, default on)

- Start order (`server::run`): signal handler, BIND (before loading: a taken port fails at once), accept threads (`Serving { context: OnceLock<Arc<Context>>, stop }`), load, banner, `serving.context.set`, THEN the stdout address line (tests read it as "ready"). Before the context is set every request but the probes gets 503 "still loading"; after a signal 503 "stopping". `GET`/`HEAD /healthz` (always 200) and `/readyz` (200 ready, 503 loading/stopping) are answered in `handle` BEFORE the Host/Origin checks, without lock or session (`health`), logged at trace only; described in `openapi.json` (outside `/api/`, so the router test only checks they answer). Book `persistence/docker.md` (repo `Dockerfile` + `.dockerignore`: alpine musl `dist` build with BuildKit cache mounts, distroless/static nonroot, `HEALTHCHECK graphersal health`, default CMD = read-only `.gstore` + `--mcp --mcp-read-only`).
- `tiny_http`, unstable. Bind: `src/server/bind.rs` `BindPlan` (`--host ADDR`; default 127.0.0.1 plus `[::1]` on the same port when available, but `0.0.0.0` in a container: `in_container` = `/.dockerenv`, `/run/.containerenv` or `KUBERNETES_SERVICE_HOST` (`kubernetes_detected`), decision tested through `container_detected`/`BindPlan::new(host, in_container)`, never the real probe). A non-loopback bind (`Exposure::Network`) prints the banner variant + a one-line `warning:` on stderr; stdout shows `http://127.0.0.1:<port>/` for `0.0.0.0` (`[::1]` for `::`). Host/Origin checks live in `BindPlan::is_own_host`/`is_own_origin`: loopback = exact own names + port (unchanged); network = any port, name an IP literal, `localhost`/`*.localhost`, a dotless name or the `--host` name (FQDNs refused against DNS rebinding), `Origin` must equal `http://` + `Host`. Invalid/unresolvable `--host` exits 2 (`server::run`); `--host` without `--server` is a parse error. Serves the playground embedded in the binary: `build.rs` generates an `include_bytes!` table from `ui/` (symlink to `../../playground`, followed by `cargo package`; entries `index.html`, `css/`, `js/`, `assets/`, `reset/`); a file of `--ui-dir` (default `./playground` if present) wins. `src/server/ui.rs`'s test fails when the embedded set differs from `playground/`.
- `src/server/`: `mod.rs` HTTP API + change feed `GET /api/changes`, `store.rs` `/api/store*`, `layout.rs` engine force layout `/api/layout*` (slices; Stop ends a running one), `mcp.rs`, `ai.rs`, the stderr start block under the warning box (`src/sections.rs`, shared with `store models`: sections Store / Graph / Embedding models / Server of `key: value` rows aligned in one column, wrapped at 78, `Section::unwrapped` never wraps (commands, paths), `Section::note` keeps a note's layout; stdout keeps only the address line), `start_stats.rs` (the Graph rows + load time, from `Session::statistics` with `process::add_to_statistics`; the memory row ends with `process N % of X (source)` from the bar keys). Models: `cli::served_models` (the `ServedModels` an open recorded: a Store's `models()` or a `.gsnap`'s `SnapshotLoadReport::models`, with their notes; licence via `cli::license_text`); `cli::defer_model_notes` keeps the open's model lines and notes for the banner instead of `note:` lines. `GET /api/info` `embedders` = `hash-ngram/1` + the database's models (`models_of`: the open Store's current ones, else the start's), `modelsNote` = `cli::no_default_note`. A `.gsnap` `--graph` is opened by the server like a Store (so its models serve). Book `persistence/dev_server.md`.
- CLI limit flags become `graphersal_session::SessionPresets` (`server::session_presets`); display flags are refused with `--server`. Exception: `--memory-limit <bytes|auto|none>`/`--memory-headroom` set the PROCESS memory ceiling once in `main.rs` (`Cli::apply_memory_limit`, before any graph or model loads; `0` = `none`), never a preset.
- "Save to file" (`POST /api/save`) writes the graph back to its `--graph` file and, with `--schema FILE`, the schema to that file (both atomic); without it a GraphML/GraphSON save of a graph with a schema answers a `warning`.
- Workload channels: `Context::call` runs every job in `workload::scope(channel, technical = true)` (client `mcp`/`ai` -> `mcp`, else `playground`); only `Session::execute*` counts (it re-scopes `current_channel()` non-technical). The session thread's default is `(playground, technical)`, the CLI script thread's `(cli, counted)` (`main.rs`). `GET /api/workload` = `Session::workload_report`; REPL `/workload` (`repl.rs` `workload_report`, the report's `Display`).
- Scheduled jobs: `start_job_ticker` ticks `Session::tick_jobs` every 5 s from a thread (`graphersal-jobs`) in the machine's zone (`cli::local_time_zone`: `TZ`, else the `/etc/localtime` link); `GET /api/jobs` = `Session::jobs_view`; `POST /api/jobs/define|drop|enable|schedule|run`, `GET /api/jobs/history` (define runs with `AccessPolicy::allow_all()`: the server's user owns its files, so backup jobs are allowed).
- System journal: `GET /api/journal` (`Session::journal`, query parameters = its request keys incl. `newest_first`/`before`), MCP tool `journal` (reading, default limit 100, `newest_first`/`before`), CLI `graphersal store journal <DIR> [--level] [--since] [--source] [--kind] [--after | --last N] [--limit] [--follow] [--json]` (`Store::journal_dir`, no lock; `--last` = one newest-first page printed oldest first; `--follow` polls once a second).
- Storage advisor: `POST /api/advise` (spec), `POST /api/advise/apply` `{id, spec}`, `/api/advise/dismiss` `{id, days?}`, `/api/advise/restore` `{id}` (`graphersal_session::advisor`); MCP tool `advise` (reading).
- OpenAPI 3.1 description `openapi.json` (crate root, packaged, EXPERIMENTAL, `info.version` = the crate version) served at `GET /openapi.json` and `/api/openapi.json` (`openapi()` sets the binary's version). **A new or changed endpoint updates `openapi.json`**: `server_tests.rs` `the_openapi_description_matches_the_router` reads the routes from `src/server/mod.rs`/`store.rs` and fails on an undescribed route, an operation the router does not answer, or a version mismatch (bump the file's version with the workspace's).
- `/api/queries*` saved queries, `/api/compression*` compression rules, `/api/indexes*` property indexes, `/api/catalog/export|load` the ONE catalog file (every kind).
- Every session job that moves the commit position is recorded in the change feed with its client (`X-Graphersal-Client` of a page, `mcp`, or `ai` + conversation id as `detail`); the playground polls it (`js/change-feed.js`) and reloads on changes it did not make.

- Memory report: `server::run` registers `ServerMemory` (a `MemorySource` over a `Weak<Context>`, alive while the server runs): `mcp` (`Mcp::memory_bytes`, client sessions) and `ai_chat` (`Ai::memory_bytes`, conversation histories), both `try_lock`.

## MCP (`--mcp [--mcp-read-only] [--mcp-token] [--mcp-query-tools] [--mcp-max-chars N]`, `POST /mcp`)

- Hand-written MCP Streamable HTTP (initialize-based revisions, JSON answers, no SSE, no `rmcp`/tokio). Tools wrap session methods and queue on the session thread like browser calls.
- `--mcp-instructions FILE`: operator text (UTF-8, 1..20000 chars, read and checked in `Cli::parse`, needs `--mcp`) appended to `initialize`'s `instructions` under "Notes from the operator of this server about this graph:" (`Mcp::with_operator_notes`). The AI Chat prompt uses the static `INSTRUCTIONS` only, never these notes (it has `system_prompt`), so nothing is added twice.
- Answers: compact JSON (`compact`, `compact_json` minifies the session's pretty display JSON keeping the key order; serde_json has no `preserve_order` here, so never round-trip result JSON through `Value`), header lines kept. `query`/`gql`/`run_saved_query`/per-query tools take `offset`, `max_rows`, `max_items` (`Page`, `page_of`; `offset` = `graphersal_session::RunOptions::offset`, display-level paging: `Display.offset`/`shown_rows`/`items_cut`). Limit `--mcp-max-chars` (default `MAX_TEXT_CHARS` 60000, min 1000; `ToolCaller.max_chars`, the AI Chat uses the default; `graph_info.answerLimitChars`): `query_text`/`fit_results` keep whole results and note `shown results a-b of N ... next page offset b`; `fit` is the rule for other tools and the safety net (leading whole items of the longest JSON line, else whole lines). Book: "Answer size and paging" in `persistence/dev_server.md`.
- Graph only: `query`, `gql` {query, params, profile, offset, max_rows, max_items} (writes like `query`, `Kind::Destructive`, kept by name in the read-only listing beside `query`/`run_saved_query` and refused there by the read-only authorizer: runs `graphersal_session::queries::gql_call_text`, i.e. `g.gql("..", #{..})` with the parameters as Rhai literals), schema tools, `statistics`, `graph_info`, saved queries (`list_saved_queries`/`run_saved_query` with `writes` + effect texts, resource `graphersal://saved-queries`; `--mcp-query-tools` lists each saved query as a tool with `readOnlyHint`/`destructiveHint` from its effects, `listChanged: false`; read-only mode hides writing queries and refuses their calls), compression (`list_compressions` and `estimate_compression`, both reading; `define_compression`/`drop_compression`/`recompress` refused read-only), indexes (`list_indexes`; `create_index`/`drop_index` refused read-only), `memory_report` (reading; `limit` default 50, `max_rows`/`max_labels` win over it), `workload_statistics` (reading; `Session::workload_report`, `max_rows` per list default 50, `<list>_omitted`), `list_jobs` (reading; `Session::jobs_view`; jobs are defined/changed only by the user). NO persistence tools (the Store menu is the user's).
- A committed data change appends the session's `change_summary` text (`+3 vertices, +2 edges`, net counts from the graph's statistics before/after the run, no commit hook) to the "committed as commit N" status.
- Read-only runs `query` and `gql` under `graphersal_session::read_only_authorizer` (denies every catalog write). A read-only view the browser opens is server-wide: `graph_info` and every tool error carry a `note` ("the served state is a read-only view at commit N ...").
- **Verify MCP changes end to end with curl** as a client (initialize -> tools/list -> tools/call).

## AI Chat (`--ai FILE`, feature `ai`, default on, needs `--server`, not `--mcp`; EXPERIMENTAL)

- `src/ai/`: `config.rs` (JSON checked at start; unknown keys lenient: `_` keys silent, others a warning, a near-typo of a known key an error with a hint; `system_prompt`/`system_prompt_file` custom text, appended after the agent rules under an operator heading and before the DSL reference; provider `openai`/`anthropic`, model, key from the variable `api_key_env` names, limits; the key is never logged or shown), `client.rs` (provider-neutral `Conversation` -> `Client::complete` -> `AssistantTurn`, `AiError` with `help()`), `openai.rs` (Chat Completions + tools; the answer message kept as `raw`, tool-call fields it does not rebuild such as Gemini's `extra_content` copied back by id, message-level only `extra_content`, never `reasoning_content`), `anthropic.rs` (Messages + tool use, `cache_control` on the system prefix, assistant content replayed unchanged); over `ureq` + rustls (synchronous, no tokio). Tested against a local `tiny_http` mock with recorded fixtures (`src/ai/fixtures/`), never a real provider.
- Agent loop `src/server/ai.rs`: conversations in memory (random 128-bit ids, owned by the creating `X-Graphersal-Client`, `403` for others), one turn at a time (`409`), each on its own thread. A `run_saved_query` of a writing query is refused in the turn that first asks it and runs once in the next turn (`State.asked`/`confirmed`, `unconfirmed_write`). Tool calls through `mcp::tool_listings`/`mcp::call_tool` (shared with MCP; `ToolCaller` carries read-only, the feed client, and the turn's own `CancelToken` via `Session::execute_with_cancel`, so Stop cancels only that conversation, never the session-wide token). System prompt = MCP instructions + agent rules (tool results are untrusted data, queries in ```` ```graphersal ```` blocks, GFM tables) + the operator text + DSL reference + a graph summary from the first turn (fixed for the prompt cache). Endpoints `/api/ai/conversations[/<id>[/messages|/events?after=N|/stop]]`, `GET /api/info` `ai`. History: `src/ai/history.rs` `History` (messages + events; the running turn plain, every finished turn sealed into one LZ4 block of JSON by `State::push_done`; a provider call decodes all; the system prompt is `Ai::prefix` (built once) + the conversation's own `summary`, never stored whole per conversation). Tool-call limit: calls beyond it get `limit_text`, then ONE more provider call with `Conversation.answer_only` (`tool_choice` "none", tools kept: Anthropic needs them for tool blocks in the history); a model still calling tools ends with the limit error; the prefix has `budget_rule`, results near the limit get `calls_left_note`. `GET /api/statistics` and the MCP `statistics` tool add `process.aiChat {conversations, historyBytes, historyUncompressedBytes}` (`ai::process_memory`, `State::history_bytes`) and, through `with_process_memory` (also the `graphersal://statistics` resource), `process.memory` of `graphersal_session::process`. The `done` event carries `elapsedMs` and `toolMs` (`State.timing`, measured around `run_call`; `toolMs <= elapsedMs`), `llmCalls`, `inputTokens` (`Usage::request_tokens`: cached included in both dialects), `outputTokens`, `cachedTokens` and `limitReached`, shown by the page under the answer (`timingText` in `playground/js/ai-chat.js`). Tests `tests/server_tests.rs` (`ai_chat`, scripted mock).
- User docs: "AI Chat" in `book/src/persistence/dev_server.md` (every key, provider examples, what leaves the machine); example configs `examples/ai-{anthropic,openai,ollama}.json` (no keys; `ai::config` tests parse them).

## Embedding models (feature `model2vec`, default on)

- `src/embed_model.rs`: `graphersal embed-model download <repo> [--revision] [--dir]` fetches the three files from `<endpoint>/<repo>/resolve/<rev>/<file>` (endpoint `GRAPHERSAL_HF_ENDPOINT` or `https://huggingface.co`; `HF_TOKEN` as bearer to the endpoint host only, never logged). Redirects by hand (`max_redirects(0)`) so `X-Linked-Etag` (SHA-256) or a 40-hex ETag (git blob SHA-1) is checked with `ring` while streaming to `.part` files in `.<name>.download-<pid>`; manifest `graphersal-embed-model.json` {format, repo, revision, commit, files, downloaded_at}; the model is loaded once as a check, then renamed to `<models-dir>/<repo>`; **any failure leaves no model**. `embed-model list [--dir]`. Models dir = `--dir`, `$GRAPHERSAL_EMBED_MODELS`, `%LOCALAPPDATA%`, `$XDG_CACHE_HOME`, `~/.cache` + `graphersal/embed-models`.
- Downloads also fetch `README.md`, `LICENSE*`/`NOTICE*` (from the Hub file list) and `<endpoint>/api/models/<repo>/revision/<rev>` (licence, base models + their licences, gated; best effort, missing = `unknown` + note) into a format-2 manifest; warnings for unknown/non-commercial/`other` licences and gated repos. `--into <store>` imports the model into a closed Store as one commit appended WITHOUT loading the graph (`Store::import_model_dir`, principal `cli`; format spec 12.12) instead of the models dir; `embed-model import <repo|dir> --into <store> [--repo] [--license] [--replace] [--default]` (the library's `ModelSource::Dir` + `ImportModelOptions`; a replace whose old revision vector rules name opens the store and re-embeds: `ImportModelReport::reembedded` note, K1); the models directory and the cache lookup are the library's `persist::ModelCache` (`models_dir`, `import_source`; the download's check load `ModelCache::check`, `list` identity `ModelCache::identity`); `list` shows licences. `store models [remove <dir> <repo> | default <dir> <repo>|--none]` (closed commits `Store::remove_model_dir` / `set_default_model_dir`; one section per model, `store_cmd::model_rows` / `model_sections`, licence wording `store_cmd::licence_rows`: never "written by Graphersal"), `store info` models block, `--without-models` on `store export` / `store backup --zip` (reports list models carried, `store_cmd::models_carried`). The models a database serves are the ENGINE's (the graph's registry: a Store's catalog, a `.gsnap`'s packed models through `persist::read_snapshot_file` in `GraphSpec::load`, `--read-only` through `Recovered::into_graph`); the CLI only lists them (`serve_models`: one note per model and the notes, all through `out::print_note` (the engine's note layout: headline, indented `key: value` details, each command on its own line under a `# comment`; notes set apart by a blank line; `out::Note` builds the CLI's own), e.g. `no_default_note` when the store holds models but none is the default, the `.gsnap`'s `SnapshotLoadReport::notes`). Scripts: `ScriptBudget::engine(limits, graph)` calls `script::set_engine_graph`, so `embed(text)` uses the graph's models. Book `persistence/store_models.md`.
- `--embedder` / `--default-embedder` (and the args-file keys) were REMOVED in 0.5.0: a usage error (exit 2) naming `graphersal embed-model import <repo> --into <store>` (`cli::removed_embedder_flag`; the args file answers it instead of a did-you-mean).
- Tests: `tests/cli_tests.rs` (`embed_models`: tiny model, raw-TCP mock of the HF endpoint: success, hash mismatches, broken body, 404/401, not a model, token only to the endpoint host; removed flags/keys, `--replace`/`--default`/`store models default`, `.gsnap` models), `tests/server_tests.rs` (`the_banner_lists_the_database_models`, `the_statistics_list_a_loaded_model_in_the_process_memory`).
