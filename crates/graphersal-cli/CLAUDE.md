# graphersal-cli

Agent guidance for the REPL, the one-shot runner, the dev server, MCP, the AI Chat and `embed-model`. Not packaged (`include` lists the packaged files). Store commands: `crates/graphersal/src/persist/CLAUDE.md`.

## CLI and REPL

- REPL `graphersal>` (`src/repl.rs`): `/` commands (`/help`, `/set`, `/memory [max_elements]` (`memory_answer`: the session's `MemoryBar::text(80)` then the memory report), `/schema [label ...]` (`schema_summary`: `AnyGraph::schema_summary`), `/exit`); Tab completion and `/help <name>` read `graphersal_session::views::completion_entries`/`token_values` (the playground's catalogue), never a CLI list. `--repl` runs it on a piped stdin.
- Output only through `out!`/`outln!`/`errln!` (`src/out.rs`); `print!`/`eprintln!` are denied by clippy (they panic on a closed pipe). stdout = result only, stderr = diagnostics and truncation notices. Exit codes `0` ok, `1` script failed, `2` invalid invocation, `141` stdout closed early.
- ONE layout for what the CLI prints (issue #19): a short headline, one indented `key: value` per line, every shell command on its own line under a `# comment` (never inside a sentence), blocks set apart by a blank line; lists of records as one section per record (`src/sections.rs`: `store models`, `store attic`, `embed-model list`, the models a copy carries). Builders in `src/out.rs`: `Note` (`detail`, `command`, `text`, `help` = the engine's multi-line `Help:` layout for errors the CLI builds), `print_note` (stderr notes), `print_block` (stdout results of `store`/`embed-model`), `use_it` (the "open it in the REPL / serve it" commands), `usage_text` (a usage error ending with the help command). Column outputs (`store info`, tables of `store list`/`marks`/`attic changes`) put a command under the value column, below its `# comment`.
- `--server`, `graphersal store` and every mode on a `--graph <store>` install `src/log.rs`, a minimal stderr `tracing` subscriber (no `tracing-subscriber`; `GRAPHERSAL_LOG`, default `warn`; never stdout). SIGINT/SIGTERM (`signals.rs`, ONE `ctrlc` handler per process: `Stop` with a store and a cancel token filled in later): the server ALWAYS installs it (as PID 1 a process without a handler ignores SIGTERM): cancel, `/readyz` 503, close a Store, exit `EXIT_OK`; one-shot/REPL install it with a Store, without one only as PID 1 (`exit_on_signal_as_pid1`, exit 130). Second signal: exit 130.
- `--read-only` (`Cli::read_only`, `GraphSpec::open(.., read_only)`): the graph gets the vetoing commit hook `ReadOnlyGraph` (`HookRefusal`); a Store is loaded with `Store::open_read_only` (no lock, nothing written) + `Recovered::into_graph` (the view serves its models), `Opened.store = None`. A read-write open failing with an I/O `PermissionDenied`/`ReadOnlyFilesystem` falls back to it with a note (`StoreOpenError::NotWritable`). Excludes `--create-store`. The server: `Context.read_only`, `/api/info` `readOnly`, `POST /api/save` 409, MCP forced read-only, banner `READ_ONLY_BANNER` + Graph row `access`.
- `graphersal health [--ready] [--host] [--port] [--timeout]` (`src/health.rs`, dispatched in `main.rs` like `store`): one `std::net` HTTP/1.1 GET of `/healthz`/`/readyz`; exit 0 on 200, 1 otherwise (reason on stderr), 2 usage; nothing on stdout.
- Scripts evaluate on a 64 MiB stack thread (`main.rs`), which also installs the `alloc-tracking` allocator.

- `--args-file FILE` / `@FILE` (`src/args_file.rs`, JSON, `serde_json` always built): `Cli::parse` first translates the file into `--key=value` arguments PREPENDED to the real ones, then the one parser runs (the command line wins by position, repeatable flags concatenate, validation runs on the merged list). Keys = long flag names (`KEYS` table; a test checks each is in `HELP`: add a new flag there too); `_` keys silent, every other unknown key a hard error with a did-you-mean (unlike `--ai`: a dropped `mcp-read-only` must not go unnoticed); relative paths resolve against the file; `-e @x` is a script (the scan skips flag values via `VALUE_FLAGS`: add a new value flag there). Errors name the key, never echo values.

## Dev server (`--server`, feature `dev-server`, default on)

- The hosting core is the crate `graphersal-serve` (guidance `crates/graphersal-serve/CLAUDE.md`): session thread + job queue, job workers, run registry, the playground HTTP API (`route`, `/api/store*`, `/api/layout*`, change feed), the Host/Origin checks, the embedded UI (`ui-assets`) and the MCP host glue (`mcp`). The CLI keeps (`src/server/dev_server.rs`, loaded by `#[path]` from `main.rs`): `run` (flags, bind, load, banner), the `tiny_http` accept loops and the request/response conversion (`handle`, `tiny_answer`), the health probes and the loading/stopping 503s, `MAX_DECLARED_BODY_BYTES`, `start_session` (graph loading over `graphersal_serve::spawn_session`), `CliHooks` (`graphersal_serve::Hooks`: the AI Chat endpoints, `ai`/`embedders`/`modelsNote` of `/api/info`, `process.models`/`process.aiChat` of the statistics), `impl JobQueue for Pool`, `ServerMemory`, `bind.rs` (address choice; the header checks are serve's `HostRules`/`HostCheck`, `BindPlan::host_check`), `mcp.rs` (banner rows), `cost.rs`, `start_stats.rs`, `pool.rs`, `ai.rs`. `src/server/mod.rs` and `src/server/store.rs` are SYMBOLIC LINKS to `graphersal-serve`'s `src/api/mod.rs`/`store.rs` and `openapi.json` one to `graphersal-serve/openapi.json`: `server_tests.rs` (unchanged in the move) reads them; edit the targets, never replace the links.
- Start order (`server::run`): signal handler, BIND (before loading: a taken port fails at once), accept threads (`Serving { context: OnceLock<Arc<Context>>, stop }`), load, banner, `serving.context.set`, THEN the stdout address line (tests read it as "ready"). Before the context is set every request but the probes gets 503 "still loading"; after a signal 503 "stopping". `GET`/`HEAD /healthz` (always 200) and `/readyz` (200 ready, 503 loading/stopping) are answered in `handle` BEFORE the Host/Origin checks, without lock or session (`health`), logged at trace only; described in `openapi.json` (outside `/api/`, so the router test only checks they answer). Book `persistence/docker.md` (repo `Dockerfile` + `.dockerignore`: alpine musl `dist` build with BuildKit cache mounts, distroless/static nonroot, `HEALTHCHECK graphersal health`, default CMD = read-only `.gstore` + `--mcp --mcp-read-only`). Self-contained KB image without compiling: `docker/prebuilt/` (`fetch-binary.sh` release/CI-run binaries into `~/.cache/graphersal/bin/<v..|run-<id>>/linux-<arch>/`, checksum-checked; `prepare-kb.sh` = `store fork` (latest state only, models carried) + verify + `mcp-cost` run by THAT binary in a distroless container; `Dockerfile` with named contexts `bin`/`kb`, `HEALTHCHECK health --ready`, CMD read-only serving + `--mcp-config /kb/mcp-config.json`); book `docker.md` "A knowledge base image".
- `tiny_http`, unstable. Bind: `src/server/bind.rs` `BindPlan` (`--host ADDR`; default 127.0.0.1 plus `[::1]` on the same port when available, but `0.0.0.0` in a container: `in_container` = `/.dockerenv`, `/run/.containerenv` or `KUBERNETES_SERVICE_HOST` (`kubernetes_detected`), decision tested through `container_detected`/`BindPlan::new(host, in_container)`, never the real probe). A non-loopback bind (`Exposure::Network`) prints the banner variant + a one-line `warning:` on stderr; stdout shows `http://127.0.0.1:<port>/` for `0.0.0.0` (`[::1]` for `::`). Host/Origin checks live in `graphersal_serve::HostRules` (`BindPlan::host_check` hands the decision over; `BindPlan::is_own_host`/`is_own_origin` delegate, test-only): loopback = exact own names + port (unchanged); network = any port, name an IP literal, `localhost`/`*.localhost`, a dotless name or the `--host` name (FQDNs refused against DNS rebinding), `Origin` must equal `http://` + `Host`. `--allowed-host NAME` (repeatable) + `GRAPHERSAL_ALLOWED_HOSTS` (comma-separated, read in `server::run`, `bind::allowed_hosts` validates: no scheme/port/path, exit 2) admit names in BOTH exposures on any port, and `http://`/`https://` origins of them whatever the `Host` (TLS-ending reverse proxy); banner row `allowed hosts`. Invalid/unresolvable `--host` exits 2 (`server::run`); `--host` without `--server` is a parse error. Serves the playground embedded in the binary through `graphersal-serve` (feature `ui-assets`: its `build.rs` generates an `include_bytes!` table from its `ui/`, a symlink to `../../playground` followed by `cargo package`; entries `index.html`, `css/`, `js/`, `assets/`, `reset/`); a file of `--ui-dir` (default `./playground` if present) wins. `graphersal-serve`'s `src/ui.rs` test fails when the embedded set differs from `playground/`.
- `src/server/`: `dev_server.rs` (above), `ai.rs`, the stderr start block under the warning box (`src/sections.rs`, shared with `store models`: sections Store / Graph / Embedding models / Server of `key: value` rows aligned in one column, wrapped at 78, `Section::unwrapped` never wraps (commands, paths), `Section::note` keeps a note's layout; stdout keeps only the address line), `start_stats.rs` (the Graph rows + load time, from `Session::statistics` with `process::add_to_statistics`; the memory row ends with `process N % of X (source)` from the bar keys). Models: `cli::served_models` (the `ServedModels` an open recorded: a Store's `models()` or a `.gsnap`'s `SnapshotLoadReport::models`, with their notes; licence via `cli::license_text`); `cli::defer_model_notes` keeps the open's model lines and notes for the banner instead of `note:` lines. `GET /api/info` `embedders` = `hash-ngram/1` + the database's models (`models_of`: the open Store's current ones, else the start's), `modelsNote` = `cli::no_default_note`. A `.gsnap` `--graph` is opened by the server like a Store (so its models serve). Book `persistence/dev_server.md`.
- **Read-only serving mode** = `--server --read-only` (`Cli::read_only_serving`; NOT a Store that fell back to read-only): `src/server/pool.rs` `Pool` (N workers `--workers`, default available parallelism; bounded queue `--queue` default 4 x workers; `--queue-timeout` s default 10, checked at submit (purge) and when a worker takes the job; `--max-inflight-per-client` default 4 per `Client::pool_key` = `mcp:<session id>` / `ai:<conversation>` / `page:<X-Graphersal-Client>`, waiting for a slot up to the queue timeout; refusals = `graphersal_serve::Busy` (`impl JobQueue for Pool` in `dev_server.rs`) -> 503 + `Retry-After: 1` in serve's `handle`, `McpError::Busy` for MCP). The context's runner = `Runner::Session` (the read-write session thread, unchanged) | `Runner::Queue(pool)`; `Context::call` dispatches. Start: the session thread loads the graph, calls `Session::set_read_only_runs(true)` (no whole-run unit: a unit holds the graph upgradable, one thread at a time, so runs would serialize) and `Session::template()`, becomes worker 0; workers 1..N build `SessionTemplate::session()` (same graph `Arc`, own engine/cancel token, shared layout jobs, limit `SHARED_LAYOUT_JOBS`). Cancellation is the run registry's (below), not the pool's. SIGTERM: `Stop::set_drain` -> `Pool::drain(--drain-timeout, default 20 s, || runs.cancel_all())` (no new job, wait, refuse the queued, cancel every run, 2 s grace; `Drained {cancelled, still_running}`, a stderr warning names jobs still running), then waits up to 2 s for the request threads, exit 0. `--max-connections` (default 512 here, no cap otherwise; needs `--server`): `Serving.connections` counted in `accept`, beyond it 503 from the accept loop (probes still answered). R3 defaults `Cli::with_serving_defaults` (SAFE limits, `--timeout 30000` unless given (`timeout_given`), `--max-materialized-bytes` 500 MiB unless given). MCP: `Mcp::with_session_key` (stateless HMAC ids; key `GRAPHERSAL_MCP_SESSION_KEY` 32..1024 bytes else random, never printed, bad value exit 2). No job ticker; `jobs/define|drop|enable|schedule|run` answer 409 `NOT_SERVING`; `GET /api/info` adds `serving` (`Pool::status`) only in this mode. Pool flags need `--server --read-only` (exit 2). Load harness `examples/serving_load.rs` (release, not in `cargo test`). Tests `server_tests.rs` `read_only_serving`. Book "Read-only serving mode" in `persistence/dev_server.md`.
- **Run registry** (`graphersal_serve::Runs`, `src/runs.rs` there; `Context.runs`, both modes; issues #29/#30/#31): every cancellable run (`/api/execute`, layout slices, MCP `query`/`gql`/saved queries and AI Chat tool calls through `Host::run_started`/`run_ended`) gets a `CancelToken` of its OWN, registered under the client's `pool_key` (+ the client's own id: a page's `runId`, an MCP JSON-RPC request id) BEFORE its job is queued (`Context::register_run`), removed when it ends; the AI Chat registers its conversation's token. Cancel by alias (`/api/cancel {runId}`, MCP `notifications/cancelled` via `Host::cancel_request`, only with an `Mcp-Session-Id`), by client (`/api/cancel` without body), all (`Runs::cancel_all`: the drain; the read-write server's SIGTERM via `Stop::set_on_stop`). Never reset, never shared: a cancel in the queue stops the run when it starts (`execute_with_cancel` runs nothing for a cancelled token), never reaches another client or the next job, never hits non-run work (drawing, memory report). Store view/live/rollback/attic restore WAIT for running queries (no cancel): stopping another client's query is a future administrative command, not cancel (user decision 2026-11-08). The session's own `cancel_token` stays for hosts without a registry.
- CLI limit flags become `graphersal_session::SessionPresets` (`server::session_presets`); display flags are refused with `--server`. Exception: `--memory-limit <bytes|auto|none>`/`--memory-headroom` set the PROCESS memory ceiling once in `main.rs` (`Cli::apply_memory_limit`, before any graph or model loads; `0` = `none`), never a preset.
- "Save to file" (`POST /api/save`) writes the graph back to its `--graph` file and, with `--schema FILE`, the schema to that file (both atomic); without it a GraphML/GraphSON save of a graph with a schema answers a `warning`.
- Workload channels: `Context::call` runs every job in `workload::scope(channel, technical = true)` (client `mcp`/`ai` -> `mcp`, else `playground`); only `Session::execute*` counts (it re-scopes `current_channel()` non-technical). The session thread's default is `(playground, technical)`, the CLI script thread's `(cli, counted)` (`main.rs`). `GET /api/workload` = `Session::workload_report`; REPL `/workload` (`repl.rs` `workload_report`, the report's `Display`).
- Scheduled jobs (issue #26: a running job holds up no request): `graphersal_serve::start_job_ticker` calls `Session::start_due_jobs` every 5 s from a thread (`graphersal-jobs`) in the machine's zone (`cli::local_time_zone`: `TZ`, else the `/etc/localtime` link), a short session job; `graphersal-serve`'s `src/job_workers.rs` runs each `JobRun` on its group's worker thread (one per group, 64 MiB stack like the session thread, lazily started), then `Context::finish_job_run` gives the result back in a short session job and records a commit made during the run in the change feed (a job's commit is in no session job's before/after); `POST /api/jobs/run` waits on the request thread, the work is on the same workers; `GET /api/jobs` = `Session::jobs_view`; `POST /api/jobs/define|drop|enable|schedule|run`, `GET /api/jobs/history` (define runs with `AccessPolicy::allow_all()`: the server's user owns its files, so backup jobs are allowed).
- System journal: `GET /api/journal` (`Session::journal`, query parameters = its request keys incl. `newest_first`/`before`), MCP tool `journal` (reading, default limit 100, `newest_first`/`before`), CLI `graphersal store journal <DIR> [--level] [--since] [--source] [--kind] [--after | --last N] [--limit] [--follow] [--json]` (`Store::journal_dir`, no lock; `--last` = one newest-first page printed oldest first; `--follow` polls once a second).
- Storage advisor: `POST /api/advise` (spec), `POST /api/advise/apply` `{id, spec}` or `{ids, spec}` (several in one commit, `Session::apply_recommendations`), `/api/advise/dismiss` `{id, days?}`, `/api/advise/restore` `{id}` (`graphersal_session::advisor`); MCP tools `advise` (reading) and `apply_recommendations` {ids, everything} (writing, not in read-only mode).
- OpenAPI 3.1 description `openapi.json` (`graphersal-serve`'s crate root, packaged there, a symlink here; EXPERIMENTAL, `info.version` = the crate version) served at `GET /openapi.json` and `/api/openapi.json` (`openapi()` sets the binary's version). **A new or changed endpoint updates `openapi.json`**: `server_tests.rs` `the_openapi_description_matches_the_router` reads the routes from `src/server/mod.rs`/`store.rs` (the symlinks to serve's router) and fails on an undescribed route, an operation the router does not answer, or a version mismatch (bump the file's version with the workspace's).
- `/api/queries*` saved queries, `/api/compression*` compression rules, `/api/indexes*` property indexes, `/api/catalog/export|load` the ONE catalog file (every kind).
- Every session job that moves the commit position is recorded in the change feed with its client (`X-Graphersal-Client` of a page, `mcp`, or `ai` + conversation id as `detail`); the playground polls it (`js/change-feed.js`) and reloads on changes it did not make.

- Memory report: `server::run` registers `ServerMemory` (a `MemorySource` over a `Weak<Context>`, alive while the server runs): `mcp` (`Mcp::memory_bytes` of `graphersal-mcp`, client sessions and the usage statistics) and `ai_chat` (`Ai::memory_bytes`, conversation histories), both `try_lock`.

## MCP (`--mcp [--mcp-read-only] [--mcp-token] [--mcp-query-tools] [--mcp-max-chars N] [--mcp-instructions FILE] [--mcp-config FILE]`, `POST /mcp`)

- The endpoint (protocol, tools, resources, answer shaping, instructions) is the crate `graphersal-mcp`: guidance in `crates/graphersal-mcp/CLAUDE.md`. Usage statistics: `GET /api/mcp/stats` (`mcp::stats`: `McpStats::to_json` + `readOnly`/`statelessSessions`; 404 without `--mcp`; memory only, nothing written; not in `/api/info`, whose `mcp` stays `{endpoint, readOnly, client}`); the pool's refusals of `mcp:*` keys (`Context::call` -> `mcp::record_refusal`) and `--max-connections` refusals of `/mcp` requests (`accept`) are counted there; playground dialog from the MCP badge. Tests `server_tests.rs` `mcp_usage_statistics` (incl. a read-only serving run on a `chmod -R a-w` store that leaves the listing unchanged). The CLI keeps the flags (`Cli::parse`: `--mcp-instructions` 1..20000 chars, `--mcp-max-chars` min 1000, `--read-only` forces `--mcp-read-only`) and the banner rows (`src/server/mcp.rs` `banner`); the host glue is `graphersal-serve`'s `src/mcp.rs` (feature `mcp`): `route` turns a serve `Request` into `McpRequest` and the `McpResponse` back (404 "the MCP endpoint is off" without `--mcp`), `impl Executor for Context` (`Context::call` under `as_client(client)`: the session-thread queue, the change feed, the workload channel), `impl Host for Context` (view, `with_process_memory`, `graph_info`'s `source`/`store`/`damageFound`/`mcpReadOnly`, the UI's `js/examples.json`, `run_started`/`run_ended`/`cancel_request` over the run registry), `status` (`/api/info`/`/api/changes` `mcp`), `current_client` (the AI Chat's DSL reference job).
- `--mcp-config FILE` (needs `--mcp`; args-file key `mcp-config`, a path): `Cli::parse` reads the file and the instructions `file` it names (relative to it) through `cli::read_mcp_config`; parsing and validation are `graphersal_mcp::McpConfig` (`parse`, `with_flags`: the shorthand flag and the key of the same setting together are an error, `check(read_only)`: a writing tool named on a read-only server is an error). `Cli.mcp_config` (feature `dev-server`; without it the flag is a usage error) is the folded configuration; `server::run` checks it again against the real read-only state (a Store that fell back to read-only) and builds `Mcp::new(.., false).with_config(..)`; without the file the endpoint is built as before (byte-identical answers). The AI Chat never reads it. Examples `examples/mcp-kb-readonly.json`, `examples/mcp-short.json` (parsed by `cli.rs` tests and `graphersal-mcp`'s budget test).
- `graphersal mcp-cost [--graph] [--mcp-config] [--read-only] [--mcp-query-tools] [--mcp-instructions]` (`src/server/cost.rs`, feature `dev-server`, dispatched in `main.rs` like `store`): reuses `Cli::parse` for the flags, opens the graph ALWAYS read-only (`GraphSpec::open(.., true)`, no lock), starts a session thread (`start_session`) with a minimal `Host`, prints `Mcp::prompt_cost` as two stdout blocks (totals; one row per tool, largest first); tokens = chars / 4, said in the output.
- **Verify MCP changes end to end with curl** as a client (initialize -> tools/list -> tools/call).

## AI Chat (`--ai FILE`, feature `ai`, default on, needs `--server`, not `--mcp`; EXPERIMENTAL)

- `src/ai/`: `config.rs` (JSON checked at start; unknown keys lenient: `_` keys silent, others a warning, a near-typo of a known key an error with a hint; `system_prompt`/`system_prompt_file` custom text, appended after the agent rules under an operator heading and before the DSL reference; provider `openai`/`anthropic`, model, key from the variable `api_key_env` names, limits; the key is never logged or shown), `client.rs` (provider-neutral `Conversation` -> `Client::complete` -> `AssistantTurn`, `AiError` with `help()`), `openai.rs` (Chat Completions + tools; the answer message kept as `raw`, tool-call fields it does not rebuild such as Gemini's `extra_content` copied back by id, message-level only `extra_content`, never `reasoning_content`), `anthropic.rs` (Messages + tool use, `cache_control` on the system prefix, assistant content replayed unchanged); over `ureq` + rustls (synchronous, no tokio). Tested against a local `tiny_http` mock with recorded fixtures (`src/ai/fixtures/`), never a real provider.
- Agent loop `src/server/ai.rs`: conversations in memory (random 128-bit ids, owned by the creating `X-Graphersal-Client`, `403` for others), one turn at a time (`409`), each on its own thread. A `run_saved_query` of a writing query is refused in the turn that first asks it and runs once in the next turn (`State.asked`/`confirmed`, `unconfirmed_write`). Tool calls through `graphersal_mcp::tool_listings`/`call_tool` (shared with MCP, host = the server's `Context`; `ToolCaller::new(ClientRef::new("ai", Some(id)), read_only).with_cancel(token)` carries read-only, the feed client, and the turn's own `CancelToken` via `Session::execute_with_cancel` (registered in the run registry, so the drain cancels it too), so Stop cancels only that conversation). System prompt = MCP instructions (`graphersal_mcp::instructions`) + agent rules (tool results are untrusted data, queries in ```` ```graphersal ```` blocks, GFM tables) + the operator text + DSL reference + GQL reference (`graphersal_mcp::gql_reference_text`: the short `gql` description points to a resource the chat cannot read) + a graph summary from the first turn (fixed for the prompt cache; `graph_summary_now` appends the schema summary, `Session::schema_summary_text`). Endpoints `/api/ai/conversations[/<id>[/messages|/events?after=N|/stop]]`, `GET /api/info` `ai`. History: `src/ai/history.rs` `History` (messages + events; the running turn plain, every finished turn sealed into one LZ4 block of JSON by `State::push_done`; a provider call decodes all; the system prompt is `Ai::prefix` (built once) + the conversation's own `summary`, never stored whole per conversation). Tool-call limit: calls beyond it get `limit_text`, then ONE more provider call with `Conversation.answer_only` (`tool_choice` "none", tools kept: Anthropic needs them for tool blocks in the history); a model still calling tools ends with the limit error; the prefix has `budget_rule`, results near the limit get `calls_left_note`. `with_process_memory` also fills an empty `process.models` when no Store is open (`--read-only`, `.gsnap`) from `cli::served_models` matched to the memory bar's `embedding_model` parts (`served_model_values`). `GET /api/statistics` and the MCP `statistics` tool add `process.aiChat {conversations, historyBytes, historyUncompressedBytes}` (`ai::process_memory`, `State::history_bytes`) and, through `with_process_memory` (also the `graphersal://statistics` resource), `process.memory` of `graphersal_session::process`. The `done` event carries `elapsedMs` and `toolMs` (`State.timing`, measured around `run_call`; `toolMs <= elapsedMs`), `llmCalls`, `inputTokens` (`Usage::request_tokens`: cached included in both dialects), `outputTokens`, `cachedTokens` and `limitReached`, shown by the page under the answer (`timingText` in `playground/js/ai-chat.js`). Tests `tests/server_tests.rs` (`ai_chat`, scripted mock).
- The chat's tools and instructions are the endpoint's DEFAULT (`ToolCaller` without a configuration, `graphersal_mcp::instructions`; the one, short, description set): `--mcp-config` does not apply to it.
- User docs: "AI Chat" in `book/src/persistence/dev_server.md` (every key, provider examples, what leaves the machine); example configs `examples/ai-{anthropic,openai,ollama}.json` (no keys; `ai::config` tests parse them).

## Embedding models (feature `model2vec`, default on)

- `src/embed_model.rs`: `graphersal embed-model download <repo> [--revision] [--dir]` fetches the three files from `<endpoint>/<repo>/resolve/<rev>/<file>` (endpoint `GRAPHERSAL_HF_ENDPOINT` or `https://huggingface.co`; `HF_TOKEN` as bearer to the endpoint host only, never logged). Redirects by hand (`max_redirects(0)`) so `X-Linked-Etag` (SHA-256) or a 40-hex ETag (git blob SHA-1) is checked with `ring` while streaming to `.part` files in `.<name>.download-<pid>`; manifest `graphersal-embed-model.json` {format, repo, revision, commit, files, downloaded_at}; the model is loaded once as a check, then renamed to `<models-dir>/<repo>`; **any failure leaves no model**. `embed-model list [--dir]`. Models dir = `--dir`, `$GRAPHERSAL_EMBED_MODELS`, `%LOCALAPPDATA%`, `$XDG_CACHE_HOME`, `~/.cache` + `graphersal/embed-models`.
- Downloads also fetch `README.md`, `LICENSE*`/`NOTICE*` (from the Hub file list) and `<endpoint>/api/models/<repo>/revision/<rev>` (licence, base models + their licences, gated; best effort, missing = `unknown` + note) into a format-2 manifest; warnings for unknown/non-commercial/`other` licences and gated repos. `--into <store>` imports the model into a closed Store as one commit appended WITHOUT loading the graph (`Store::import_model_dir`, principal `cli`; format spec 12.12) instead of the models dir; `embed-model import <repo|dir> --into <store> [--repo] [--license] [--replace] [--default]` (the library's `ModelSource::Dir` + `ImportModelOptions`; a replace whose old revision vector rules name opens the store and re-embeds: `ImportModelReport::reembedded` note, K1); the models directory and the cache lookup are the library's `persist::ModelCache` (`models_dir`, `import_source`; the download's check load `ModelCache::check`, `list` identity `ModelCache::identity`); `list` shows licences. `store models [remove <dir> <repo> | default <dir> <repo>|--none]` (closed commits `Store::remove_model_dir` / `set_default_model_dir`; one section per model, `store_cmd::model_rows` / `model_sections`, licence wording `store_cmd::licence_rows`: never "written by Graphersal"), `store info` models block, `--without-models` on `store export` / `store backup --zip` (reports list models carried, `store_cmd::models_carried`). The models a database serves are the ENGINE's (the graph's registry: a Store's catalog, a `.gsnap`'s packed models through `persist::read_snapshot_file` in `GraphSpec::load`, `--read-only` through `Recovered::into_graph`); the CLI only lists them (`serve_models`: one note per model and the notes, all through `out::print_note` (the engine's note layout: headline, indented `key: value` details, each command on its own line under a `# comment`; notes set apart by a blank line; `out::Note` builds the CLI's own), e.g. `no_default_note` when the store holds models but none is the default, the `.gsnap`'s `SnapshotLoadReport::notes`).
