# graphersal-mcp

Agent guidance for the MCP endpoint (`--mcp [--mcp-read-only] [--mcp-token] [--mcp-query-tools] [--mcp-max-chars N]`, `POST /mcp` of `graphersal --server`) and the tools the AI Chat shares with it. Publishable, internal, EXPERIMENTAL like `graphersal-session` (`#![warn(missing_docs)]`, no stability promise). No HTTP library, no tokio. The host today is the dev server (`crates/graphersal-cli/src/server/mcp.rs`: `tiny_http` <-> `McpRequest`/`McpResponse`, `Executor` = `Context::call`'s session-thread queue, `Host` over `Context`; CLI guidance `crates/graphersal-cli/CLAUDE.md`).

## Layout

- `lib.rs`: module doc (protocol, tools, host boundary) and the whole public surface: `Mcp`, `McpRequest`/`McpResponse`, `Executor`/`Host`/`Job`/`ClientRef`/`McpError`, `ToolCaller`/`ToolOutcome`/`CallRefused`, `tool_listings`, `call_tool`, `instructions`, `dsl_reference_text`, `MAX_TEXT_CHARS`, `PROTOCOL_VERSIONS`.
- `transport.rs`: `McpRequest` (method, headers, a lazily read body: the Content-Type `415`, the declared/real size `413` at 16 MiB and the UTF-8 checks run only for a `POST` that passed the header checks) and `McpResponse` (status, headers in order, body).
- `protocol.rs`: `Mcp` (options, MCP sessions, `status()`), `handle` (token `401`, `POST`/`DELETE`/`405`), `post` (Accept `406`, `MCP-Protocol-Version` `400`, unknown session `404`, JSON-RPC parsing), `dispatch`, `initialize`, the `INSTRUCTIONS` text (+ read-only note, operator notes).
- `host.rs`: `Executor::execute(client, job)` (the one extension point: `FnOnce(&mut Session)`, boxed), `Host` (view, process statistics, `graph_info` fields, examples JSON, `query_started`/`query_finished`), `ClientRef`, `McpError` (`#[non_exhaustive]`), and the crate-internal `Ctx` (host + client) whose `call` runs a typed job through the executor.
- `catalog.rs`: `Kind`, `Tool`, every built-in tool's description and input schema (`all_tools`), the read-only selection (`tools`).
- `tools.rs`: `ToolCaller` (builder), `call_tool`/`tool_listings`, `run_tool` (one arm per tool), saved queries (`saved_queries`, `list_saved_queries`, `run_saved_query`, `query_tool_listings`), `query`/`gql`/`run_script`.
- `answer.rs`: compact JSON, `fit`, `Page`/`page_of`, paging schema entries, `query_text`/`fit_results`, `profile_text`.
- `resources.rs`: `RESOURCES`, `read_resource`, the DSL reference (built once from the engine's completions) and the examples text.
- Tests: `src/tests.rs` (unit tests, moved from the dev server's `mcp.rs` unchanged in substance), `tests/handle_tests.rs` (the transport entry point with JSON and a test host on its own session thread, no HTTP). End to end over HTTP: `crates/graphersal-cli/tests/server_tests.rs`.

## Rules

- Hand-written MCP Streamable HTTP (initialize-based revisions, JSON answers, no SSE, no `rmcp`/tokio). Tools wrap session methods; every session job goes through the host's `Executor` for the caller's `ClientRef` (`mcp` for the endpoint, `ai` + conversation id for the AI Chat). The dev server queues them on its session thread like browser calls.
- `with_operator_notes` (`--mcp-instructions FILE`: operator text, UTF-8, 1..20000 chars, read and checked in the CLI's `Cli::parse`, needs `--mcp`) appends to `initialize`'s `instructions` under "Notes from the operator of this server about this graph:". The AI Chat prompt uses `instructions()` only (the static text), never these notes (it has `system_prompt`), so nothing is added twice.
- Answers: compact JSON (`compact`, `compact_json` minifies the session's pretty display JSON keeping the key order; serde_json has no `preserve_order` here, so never round-trip result JSON through `Value`), header lines kept. `query`/`gql`/`run_saved_query`/per-query tools take `offset`, `max_rows`, `max_items` (`Page`, `page_of`; `offset` = `graphersal_session::RunOptions::offset`, display-level paging: `Display.offset`/`shown_rows`/`items_cut`). Limit `with_max_chars` (`--mcp-max-chars`, default `MAX_TEXT_CHARS` 60000, min 1000 checked by the CLI; `ToolCaller::with_max_chars`, the AI Chat uses the default; `graph_info.answerLimitChars`): `query_text`/`fit_results` keep whole results and note `shown results a-b of N ... next page offset b`; `fit` is the rule for other tools and the safety net (leading whole items of the longest JSON line, else whole lines). Book: "Answer size and paging" in `persistence/dev_server.md`.
- Graph only: `query`, `gql` {query, params, profile, offset, max_rows, max_items} (writes like `query`, `Kind::Destructive`, kept by name in the read-only listing beside `query`/`run_saved_query` and refused there by the read-only authorizer: runs `graphersal_session::queries::gql_call_text`, i.e. `g.gql("..", #{..})` with the parameters as Rhai literals), schema tools, `statistics`, `graph_info`, saved queries (`list_saved_queries`/`run_saved_query` with `writes` + effect texts, resource `graphersal://saved-queries`; query tools (`--mcp-query-tools`) list each saved query as a tool with `readOnlyHint`/`destructiveHint` from its effects, `listChanged: false`; read-only mode hides writing queries and refuses their calls), compression (`list_compressions` and `estimate_compression`, both reading; `define_compression`/`drop_compression`/`recompress` refused read-only), indexes (`list_indexes`; `create_index`/`drop_index` refused read-only), `memory_report` (reading; `limit` default 50, `max_rows`/`max_labels` win over it), `workload_statistics` (reading; `Session::workload_report`, `max_rows` per list default 50, `<list>_omitted`), `list_jobs` (reading; `Session::jobs_view`; jobs are defined/changed only by the user), `journal`, `advise` (reading) and `apply_recommendations` {ids, everything} (writing, not in read-only mode; `Session::apply_recommendations`, one commit). NO persistence tools (the Store menu is the user's).
- A committed data change appends the session's `change_summary` text (`+3 vertices, +2 edges`, net counts from the graph's statistics before/after the run, no commit hook) to the "committed as commit N" status.
- Read-only runs `query` and `gql` under `graphersal_session::read_only_authorizer` (denies every catalog write). A read-only view the user opens is server-wide (`Host::view`): `graph_info` and every tool error carry a `note` ("the served state is a read-only view at commit N ...").
- A caller without its own cancel token runs `query`/`gql` under the host's session-wide token, bracketed by `Host::query_started`/`query_finished` (the dev server's `/api/cancel` reports it); `ToolCaller::with_cancel` (the AI Chat turn) uses `Session::execute_with_cancel` instead.
- No panics, no `unwrap`/`expect` outside tests; failures are tool errors (`isError`), `CallRefused` (JSON-RPC errors) or `McpError`. Logging only through `tracing`.
- **Behaviour is the dev server's contract**: a change to a text, a tool or an answer shows in `crates/graphersal-cli/tests/server_tests.rs` and in what agents see. **Verify MCP changes end to end with curl** as a client against `graphersal --server --mcp` (initialize -> tools/list -> tools/call, `Mcp-Session-Id` from the initialize answer's headers).
