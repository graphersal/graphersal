# graphersal-mcp

Agent guidance for the MCP endpoint (`--mcp [--mcp-read-only] [--mcp-token] [--mcp-query-tools] [--mcp-max-chars N] [--mcp-config FILE]`, `POST /mcp` of `graphersal --server`) and the tools the AI Chat shares with it. Publishable, internal, EXPERIMENTAL like `graphersal-session` (`#![warn(missing_docs)]`, no stability promise). No HTTP library, no tokio. The host today is the dev server (`crates/graphersal-cli/src/server/mcp.rs`: `tiny_http` <-> `McpRequest`/`McpResponse`, `Executor` = `Context::call`'s session-thread queue, `Host` over `Context`; CLI guidance `crates/graphersal-cli/CLAUDE.md`).

## Layout

- `config.rs`: `McpConfig` (the operator's `--mcp-config`: `parse(text, read_file)` with `_` comment keys and did-you-mean errors, `with_flags` (the shorthand flags; flag + key of one setting = error), `check(read_only)` (a writing tool named on a read-only server = error)), `McpConfigError`, `Descriptions` (`full`/`short`), the crate-internal selection helpers (`offers`, `override_of`, `lists_resource`, `SavedQueryTools::selects`: folder with subfolders, names, exclude; `saved_query_paging`: default on in full mode, off in short). No named built-in profiles: without a configuration everything is as before (`McpConfig::default()`).
- `lib.rs`: module doc (protocol, tools, host boundary) and the whole public surface: `Mcp`, `McpRequest`/`McpResponse`, `Executor`/`Host`/`Job`/`ClientRef`/`McpError`, `ToolCaller`/`ToolOutcome`/`CallRefused`, `tool_listings`, `call_tool`, `instructions`, `dsl_reference_text`, `MAX_TEXT_CHARS`, `PROTOCOL_VERSIONS`.
- `transport.rs`: `McpRequest` (method, headers, a lazily read body: the Content-Type `415`, the declared/real size `413` at 16 MiB and the UTF-8 checks run only for a `POST` that passed the header checks) and `McpResponse` (status, headers in order, body).
- `protocol.rs`: `Mcp` (options, MCP sessions, `status()`), `handle` (token `401`, `POST`/`DELETE`/`405`), `post` (Accept `406`, `MCP-Protocol-Version` `400`, unknown session `404`, JSON-RPC parsing), `dispatch`, `initialize`, the `INSTRUCTIONS` text (+ read-only note, operator notes).
- `sessions.rs`: MCP session ids. `Sessions::Table` (default: 64 ids, oldest evicted, unchanged) or `Sessions::Signed` (`Mcp::with_session_key(SessionKey)`, the CLI's read-only serving mode): id = hex(nonce 16 B || client digest 8 B (SHA-256 of clientInfo name+version) || HMAC-SHA256 tag 16 B over a domain string + both), verified without a table (constant-time compare); `DELETE` of a valid id = 200 and the id stays valid; client names in a bounded map (`ClientNames`, both modes, `MAX_CLIENT_NAMES` 4096, least recently initialized evicted with its counters; `Arc<RwLock<..>>` shared with the statistics; `client_of(id)` = the digest inside a signed id or the table entry's). `SessionKey::new` 32..1024 bytes, `Debug` never prints it. `ring` (already in the tree) for HMAC/SHA-256.
- Busy host: `McpError::Busy` from `Executor::execute` is noted per thread by `Ctx::call` (`host::BUSY`); `Mcp::post` answers that request `503` + `Retry-After: 1` (JSON-RPC error `-32603` with the request id) instead of a tool error. `ClientRef::with_key`/`key()`: the request's MCP session id, for a host's per-client fairness (the dev server's single session thread ignores it).
- `host.rs`: `Executor::execute(client, job)` (the one extension point: `FnOnce(&mut Session)`, boxed), `Host` (view, process statistics, `graph_info` fields, examples JSON, `run_started`/`run_ended`/`cancel_request`), `ClientRef` (`with_key` = MCP session id, `with_request` = the JSON-RPC id's JSON text), `McpError` (`#[non_exhaustive]`), and the crate-internal `Ctx` (host + client) whose `call` runs a typed job through the executor.
- `stats.rs`: `McpStats` (`Mcp::stats()`; in process memory only, never written, lost on restart): requests per JSON-RPC method, per tool and per saved query (`CounterMap`: `RwLock<HashMap>` read-locked to find the entry, atomics inside; at most `MAX_COUNTED_NAMES` 1024 names, then `(other)`; unknown tools `(unknown)`) calls, errors, total/max latency, a histogram over `LATENCY_BUCKETS_MS`, answer chars; per client (`ClientNames` counters); sessions initialized and active in about 5 min (`ActiveSessions`: one 64 Kibit linear-counting sketch per minute, 6 slots, `fetch_or`, estimate); refusals by `Refusal` (`UnknownSession`/`Unauthorized`/`InvalidRequest` counted by `Mcp::post`/`handle` from the answer's status; the host reports `QueueFull`/`QueueTimeout`/`ClientLimit`/`TooManyConnections`/`Stopping` with `record_refusal`). Recorded in `Mcp::post` (`record_request`, `record_initialize`, `record_busy`) and `dispatch`'s `tools/call` (timed around `call_tool`; `run_saved_query`'s `name` or a saved-query tool counts for the saved query too). `to_json` (the dev server's `GET /api/mcp/stats`), `summary`. The tool `usage_statistics` (reading) is OPT-IN: `config::OPT_IN_TOOLS`, `McpConfig::offers` lists it only when `tools.include` names it (never in the default listing, never for the AI Chat, whose `ToolCaller` has no `stats`). Tests `tests/stats_tests.rs`.
- `catalog.rs`: `Kind`, `Tool`, every built-in tool's description and input schema (`all_tools`), the read-only selection (`tools`), the configured selection (`offered_tools`: include/exclude, override > short > full description) and the hand-written `short_description` of every tool (a new tool needs one: `config_tests` checks it is non-empty and not longer than the full text).
- `tools.rs`: `ToolCaller` (builder), `call_tool`/`tool_listings`, `run_tool` (one arm per tool), saved queries (`saved_queries`, `list_saved_queries`, `run_saved_query`, `query_tool_listings`), `query`/`gql`/`run_script`.
- `answer.rs`: compact JSON, `fit`, `Page`/`page_of`, paging schema entries, `query_text`/`fit_results`, `profile_text`.
- `resources.rs`: `RESOURCES`, `read_resource`, the DSL reference (built once from the engine's completions), the examples text and `graphersal://gql-reference` (the full `GQL_DESCRIPTION`; always readable, listed only when the configuration's `resources` names it, so the default listing is unchanged).
- `protocol.rs` also: `Mcp::with_config`, `instructions_text` (builtin/append/replace + read-only note), `tool_listings`, `prompt_cost` -> `PromptCost` (chars of the instructions and of each `tools/list` entry; tokens = chars / 4), `serverInfo.name` from `server_name`.
- Tests: `tests/config_tests.rs` (configuration parsing and errors, a configured endpoint's listing/calls/resources, short descriptions, and the BUDGETS: the default listing per mode and the CLI's knowledge-graph example; a failing budget means a description grew), `src/tests.rs` (unit tests, moved from the dev server's `mcp.rs` unchanged in substance), `tests/handle_tests.rs` (the transport entry point with JSON and a test host on its own session thread, no HTTP). End to end over HTTP: `crates/graphersal-cli/tests/server_tests.rs`.

## Rules

- Hand-written MCP Streamable HTTP (initialize-based revisions, JSON answers, no SSE, no `rmcp`/tokio). Tools wrap session methods; every session job goes through the host's `Executor` for the caller's `ClientRef` (`mcp` for the endpoint, `ai` + conversation id for the AI Chat). The dev server queues them on its session thread like browser calls.
- `with_operator_notes` (`--mcp-instructions FILE`: operator text, UTF-8, 1..20000 chars, read and checked in the CLI's `Cli::parse`, needs `--mcp`) appends to `initialize`'s `instructions` under "Notes from the operator of this server about this graph:". The AI Chat prompt uses `instructions()` only (the static text), never these notes (it has `system_prompt`), so nothing is added twice.
- Answers: compact JSON (`compact`, `compact_json` minifies the session's pretty display JSON keeping the key order; serde_json has no `preserve_order` here, so never round-trip result JSON through `Value`), header lines kept. `query`/`gql`/`run_saved_query`/per-query tools take `offset`, `max_rows`, `max_items` (`Page`, `page_of`; `offset` = `graphersal_session::RunOptions::offset`, display-level paging: `Display.offset`/`shown_rows`/`items_cut`). Limit `with_max_chars` (`--mcp-max-chars`, default `MAX_TEXT_CHARS` 60000, min 1000 checked by the CLI; `ToolCaller::with_max_chars`, the AI Chat uses the default; `graph_info.answerLimitChars`): `query_text`/`fit_results` keep whole results and note `shown results a-b of N ... next page offset b`; `fit` is the rule for other tools and the safety net (leading whole items of the longest JSON line, else whole lines). Book: "Answer size and paging" in `persistence/dev_server.md`.
- Graph only: `query`, `gql` {query, params, profile, offset, max_rows, max_items} (writes like `query`, `Kind::Destructive`, kept by name in the read-only listing beside `query`/`run_saved_query` and refused there by the read-only authorizer: runs `graphersal_session::queries::gql_call_text`, i.e. `g.gql("..", #{..})` with the parameters as Rhai literals), schema tools, `statistics`, `graph_info`, saved queries (`list_saved_queries`/`run_saved_query` with `writes` + effect texts, resource `graphersal://saved-queries`; query tools (`--mcp-query-tools`) list each saved query as a tool with `readOnlyHint`/`destructiveHint` from its effects, `listChanged: false`; read-only mode hides writing queries and refuses their calls), compression (`list_compressions` and `estimate_compression`, both reading; `define_compression`/`drop_compression`/`recompress` refused read-only), indexes (`list_indexes`; `create_index`/`drop_index` refused read-only), `memory_report` (reading; `limit` default 50, `max_rows`/`max_labels` win over it), `workload_statistics` (reading; `Session::workload_report`, `max_rows` per list default 50, `<list>_omitted`), `list_jobs` (reading; `Session::jobs_view`; jobs are defined/changed only by the user), `journal`, `advise` (reading) and `apply_recommendations` {ids, everything} (writing, not in read-only mode; `Session::apply_recommendations`, one commit). NO persistence tools (the Store menu is the user's).
- A committed data change appends the session's `change_summary` text (`+3 vertices, +2 edges`, net counts from the graph's statistics before/after the run, no commit hook) to the "committed as commit N" status.
- Read-only runs `query` and `gql` under `graphersal_session::read_only_authorizer` (denies every catalog write). A read-only view the user opens is server-wide (`Host::view`): `graph_info` and every tool error carry a `note` ("the served state is a read-only view at commit N ...").
- Every `query`/`gql`/saved-query run (`run_script`) uses `Session::execute_with_cancel` with a token of its own (the caller's `ToolCaller::with_cancel` token, else a new one), registered BEFORE the job is queued through `Host::run_started(client, token)` and ended by `RunGuard` (`run_ended`). `notifications/cancelled {requestId}` calls `Host::cancel_request(client with the session key, id JSON text)`; ignored without `Mcp-Session-Id` (ids are per client); `202` always.
- No panics, no `unwrap`/`expect` outside tests; failures are tool errors (`isError`), `CallRefused` (JSON-RPC errors) or `McpError`. Logging only through `tracing`.
- **Behaviour is the dev server's contract**: a change to a text, a tool or an answer shows in `crates/graphersal-cli/tests/server_tests.rs` and in what agents see. **Verify MCP changes end to end with curl** as a client against `graphersal --server --mcp` (initialize -> tools/list -> tools/call, `Mcp-Session-Id` from the initialize answer's headers).
