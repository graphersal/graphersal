# Persistence (feature `persist`)

Agent guidance for `persist/`. Not packaged (`Cargo.toml` excludes `src/**/CLAUDE.md`). The normative byte-level spec is the PUBLIC book page `book/src/persistence/format.md`, cited in code as "format spec N" with its section numbers: keep it in sync with every byte-level change. Book part "Persistence" (`book/src/persistence/`): overview, Store pages, `store_cli.md` (every `graphersal store` command; update it with `crates/graphersal-cli/src/store_cmd.rs`), `dev_server.md`, `format.md`, `faq.md` (the `StoreFailure` cause table); user command list `book/src/users_guide/command_cheat_sheet.md`. Brings `lz4_flex` + `crc32c`; `persist-zstd` adds zstd chunks (`ruzstd`), `persist-zip` ZIP backups (own stored+zip64 writer/reader). All build for wasm32.

## Files and streams

- `codec.rs`: fixed LE ints, LEB128, the tagged value encoding (segments + journal), CRC-32C, chunk compression with size bounds.
- `segment.rs`: `ChunkEncoder` (id-sorted elements into self-contained chunks with their own string table), headers/footers, `frame_segment`/`decode_*_chunk`.
- `encoder.rs`: the ONLY snapshot encoder, streaming. `SnapshotEncoder` over any `S: PersistentStorage` sorts `(id, handle)` indexes via the read API (24 B/element for `TraversalGraph`; no petgraph fast path, measured equal) and runs two passes: `plan_kind` (each chunk encoded once, only offsets/ids/CRCs kept; file CRC via `crc_combine`, header last) and `emit` (re-encode from the element range, checked against the plan). Memory = index + one chunk. Byte identity with the former in-memory encoder is pinned by golden fingerprints. `KindPlanner`/`KindEmitter` = the same passes fed through `ElementSink` (merge checkpoint).
- `manifest.rs` (fixed part + variable part + tail copy), `snapshot.rs` (packed `write_snapshot`/`read_snapshot`/`read_snapshot_into(reader, options, empty: S)`/`read_snapshot_info`, `PackedReader`, `check_segment_stream`/`read_segment_stream`). A load goes into an EMPTY storage (else `Unsupported`) through the `PersistentStorage` load sink (schema, definitions, vertices, edges, `finish_load`), no schema validation, then restores `graph_id`, position/time and id sequences; chunks decode in parallel off wasm.
- `wal.rs` (journal header, record frame with sync marker, lossless `ChangeSet` payload, marks, `JournalReader`: torn tail vs damage incl. resync). Record frames have a header CRC separate from the body CRC, so a damaged length is damage, never a torn tail (9.6). A commit body <= `PART_BODY_BYTES` (64 MiB) is one Commit record (type 1, unchanged bytes); a larger one is written as consecutive Commit-part records (type 4, 9.3.1, file format 4 via `codec::COMMIT_PARTS_FORMAT_VERSION`): `encode_commit_body` -> `EncodedCommit` (body built once, `parts`, `single_payload`, `put_part`), `Journal::append_parts` (rotation once before part 0, one reused part buffer, ONE sync, a failure cuts back to part 0, `DurableEnd` only after the last part); `JournalReader` assembles parts through `CommitParts` (body grows per part under the ceiling, `"reading a commit in parts"`; encoding checks `"commit encoding"`) and returns ONE commit at the offset of part 0, so every reader (recover, rollback split, maintenance, merge, backup checks) stays right; `damage.rs` has its own walk (`assemble_parts`, `skip_later_parts`, `resync`; `CommitPos::parts`). Beyond `MAX_COMMIT_PARTS` (2^20) vetoed `PersistError::CommitTooLarge`. Test knob `#[doc(hidden)] with_commit_part_bytes` on `Journal` and `StoreOptions` (per open).
- `journal.rs` (`Journal`: write-ahead in `before_commit`, `Durability`, poisoning, lock-free `DurableEnd`, `SharedBuffer`), `recover.rs` (`Recovery<S = TraversalGraph>`, `Recovery::new_in(empty)`, `Recovered<S>`; targets `Latest`/`CommitSeq`/`Time`/`Mark`; continuity + lineage checks; every commit via `PersistentStorage::replay` with `verify_before_images`; `RecoveryReport`), `definitions.rs` (catalog records, see `graph/CLAUDE.md`).
- Every decoder is hostile-input safe (counts checked against remaining bytes before allocating). Tests `persist_tests.rs` (round trips, every flipped bit, every torn-tail cut, veto/poison, hook order, targets), `persist_robustness_tests.rs` (fuzz). DSL `g.export_snapshot(path)` (`Create` on the file); `.gsnap` in `GraphSource::from_file`.

## PersistentStorage and the journal slot

- `PersistentStorage` (`graph/persistent.rs`, EXPERIMENTAL, `graphersal::storage`): `graph_id`/`set_graph_id` (no inherent `TraversalGraph::graph_id`: import the trait), `last_committed_at`, `id_sequences`, `raise_position` (raise only), the load sink `load_vertex`/`load_edge`/`load_schema`/`load_definition`/`finish_load` (outside units, no hooks; `TraversalGraph`: compression load pass + shrink), `clear` (keeps hooks + journal), `attach_journal(JournalSlot)`; `set_graph_id`/`raise_position`/`reserve_load`/`finish_load`/`clear` return `Result<(), GraphError>`, propagated by every load, recovery and reload, `replay(&changes, verify)` (`TraversalGraph` overrides with `replay_verified`/`replay_in_place`). `Forwarding` implements it (feature `persist` of `graphersal-storage-tests`); tests `generic_persist_tests.rs`.
- `Graph::new_persistent(s)` keeps the snapshot writer that `AnyGraph::write_snapshot` (`g.export_snapshot`) calls. Plain `Graph::new` of `TraversalGraph` uses a downcast fallback; other storages: `Unsupported`.
- The journal has its own hook slot (`CommitHooks` journal slot, crate-internal `JournalHook` behind the opaque `JournalSlot`): its `before_commit` runs after every user hook, and nothing fallible follows it in `commit_undo_unit` (the seq is assigned before), so a journal never holds a vetoed unit. A panic in its write path (`Journal::guarded`) is handled like a failed write (record cut off or `wal_cut` recorded, journal poisoned), then resumed (book `journal_and_recovery.md` "Failures while committing"). Marks (`g.mark`, Python `graph.mark`) go only to the journal slot (`MarkUnavailable`/`MarkRejected`).
- Refused records (9.7): a failed write/fsync is truncated off and synced before the journal poisons itself (`JournalFiles::discard`, `Journal::with_truncate`/`for_file`); if the cut fails the Store records the valid end in `GRAPH` (`wal_cut`), the next open cuts there.

## Versions (format spec 15, 16)

- STORE format version (`GRAPH` offset 8, `files::STORE_VERSION` = `persist::STORE_FORMAT_VERSION` = 4 since P10 / 0.5.0 (blobs, models as definitions); 3 = 0.2.x-0.4.x; 2 = 0.1.x; 1 never released) is separate from the FILE format version (`codec::FORMAT_VERSION` = `persist::FORMAT_VERSION` = 4 since P4 / 0.5.0: blob reference tag 21 (`BLOB_FORMAT_VERSION`), the manifest's blob table (6.2 item 5), journal segments; 3 since temporal v2 / 0.3.0: nanosecond temporal tags 15-20 incl. `offsettime` and the zone NAME of a `datetime` as a key (string table in a chunk, inline in a record; unknown name = `DecodeError::unsupported`), version-guarded by `NANOS_FORMAT_VERSION`; the one form a v3 writer uses for each kind, `date` stays tag 9; 2 (0.2.x: µs tags 9-13, vector tag 14, `TEMPORAL_FORMAT_VERSION`) and 1 (0.1.x) still read, `MIN_FORMAT_VERSION`; tags 9-13 stay valid in a v3 file; each file carries its own). A file-version bump alone needs no store-version bump nor an `UPGRADES` row (0.2.x refuses a v3 file via `refuse_newer_version`; `UPGRADES_REVIEWED_FOR` = (4, 4)); golden 0.2.3 fixtures `tests/data/v0.2.3` (`make.sh`), tests `temporal_v3_format_tests.rs`. Store stamps (`committed_at`, `created_at`, `taken_at`, `started_at`) stay i64 µs.
- The guard `files::refuse_other_version` (newer half `refuse_newer_version`: preamble, both `GRAPH` copies, a header walk of every manifest/segment/WAL) runs FIRST on every operation on an existing store/backup/attic. **A future version is never damage and a store holding one is never worked on** (no write, lock, maintenance, upgrade): `PersistError::UnsupportedVersion`, `DecodeError::check_version`; tests `newer_format_tests.rs`. An older version is classified before the store id check (`GraphFile::older_version`, `files::decode_graph_copies`) and refused with `PersistError::OlderFormat` (never damage/`NotAStore`); its help names `graphersal store upgrade` when `upgradable_from`, else the `.gsnap` migration.
- **`UPGRADES`** (`store/upgrade.rs`, spec 15.1; `UpgradeMethod` `Nothing`/`InPlaceVersionWord` (unused since 4)/`Migrate`/`CopyOnly`/`Unsupported`; rows 2->4 and 3->4 `Migrate`) is the only source of which upgrades exist. `Store::upgrade(src, dst)`/`upgrade_in_place` (CLI `store upgrade <DIR> <NEW>|--in-place`, Python `Store.upgrade`; verified first; without `models/` only `GRAPH`+copy rewritten, no journal record; `CopyOnly` in place -> `StoreFailure::UpgradeNeedsCopy`). **Model migration** (`store/migrate_models.rs`, 0.4.0 `models/` -> blobs): `check_legacy` (every file hashed, BEFORE any write; `StoreFailure::UpgradeModelDamaged`) -> `INTENT` `upgrade_models` (`files` = model dirs, `from`) -> `GRAPH` v4 -> `complete`: tar blobs (`TarContent::Open` over `StoreDir`) + ONE `closed_commit::commit_catalog_locked` (no prelude: the caller holds the lock; principal `upgrade`, attribute `upgrade` = `3->4`; a model already defined (same 12 hex) is skipped; repo-less or repo-taken -> `local/<12hex>` + schema `embedder` renamed in the commit) -> model dirs renamed to `tmp-` and removed -> `INTENT` cleared. `complete_intent` completes it at open/closed ops, `upgrade_in_place` of a v4 store with that INTENT too. Copy upgrade migrates the copy before removing its marker. `upgrade::finish` fills `UpgradeReport::models_converted`/`migration_commit`/`models_missing`/`vectors_without_rule`/`saved_queries_using_removed` (feature `script`: `script::saved_queries_using_removed`, `catalog::RemovedFunctionUse`, `note(store)` the one text; never rewrites a query; fixtures `tests/data/v0.4.0/saved_queries*`, `make_saved_queries.sh`) (`VectorWithoutRule`: count via `merge::count_vectors` over the newest snapshot, `commits_not_counted` for the WAL after it; `note()`/`schema_patch()` are the one text of every front end) and writes `store.upgraded` only when models were migrated. Also migrated: ZIP restore (through `upgrade_in_place`), `.gsnap` kind-3 rows (`create_from_packed_at` -> `migrate_new_store`; `import_models_from_packed` imports each through `import_prepared`), repair of a v3 store (`migrate_new_store`, failure reported in `models_not_carried`). Golden 0.4.0 fixtures `tests/data/v0.4.0` (`make.sh`), tests `store_upgrade_tests.rs` module `v040`. Repair (`upgrade::older_view`) and ZIP restore read an upgradable version; the journal never continues an older WAL segment. A bump needs a table row: `the_upgrade_table_covers_every_version` (`UPGRADES_REVIEWED_FOR`) and `the_book_shows_the_upgrade_table` (`<!-- upgrades:begin/end -->` in `store_versions.md`, `format.md` 15.1, `store_cli.md`; `GRAPHERSAL_UPDATE_BOOK=1`). Golden 0.1.0 fixtures `tests/data/v0.1.0` (`make.sh`), tests `store_upgrade_tests.rs`.
- **A patch release never changes a format version; one changes only with a release that needs it.**
- **Newer content is never damage (16 rule 9).** Damage = checksum/length/byte structure (value tags, record types, ops: version-guarded, stay strict). Semantic content behind a valid CRC that this version cannot interpret is `DecodeError::unsupported` -> `PersistError::UnsupportedContent` (not `is_damage`: no maintenance, no repair; salvage refuses it; `verify` and backup checks note it and go on, `JournalReader::unsupported_seq`/`next_known_record`). A graph schema it cannot parse (`snapshot::parse_stored_schema`, snapshot + WAL op 9 + merge + salvage): strict everywhere except the Store open's own load (`ReadOptions::newer_schema` = `NewerContent`, set ONLY in `load_latest`), which loads no schema and opens read-only. Unknown `INTENT` op, unknown `GRAPH` state (`refuse_newer_version`), well-formed unknown ZIP entry: `UnsupportedContent`. Tests `forward_compat_tests.rs`, `merge_tests::a_schema_of_a_newer_version_*`.
- Extensibility (16): unknown definition kinds, payload keys, segment kinds (7.5: 3-127 ignorable, checked by length+CRC, not carried into a new snapshot; 128-255 critical) and packed section 5 need no new version. A critical opaque definition in the catalog, or a critical unknown segment kind in the base snapshot, opens the store READ-ONLY (`Store::open_read_only_mode`, vetoing `ReadOnlyHook`, `PersistError::ReadOnly`, `Store::read_only_reason`, `OpenReport::read_only`; `reload_in_place` too).

## Store (`persist/store/`, one directory = one graph)

- `Store<S: PersistentStorage = TraversalGraph>` is a thin shell (typed `Arc<Graph<S>>` + `Arc<StoreCore>`). `impl Store` keeps constructors/dir functions (no turbofish); `impl<S: PersistentStorage + Default>` adds `open_in`/`create_in`/`create_from_packed_in`/`open_backup_in`/`open_read_only_in` (precondition `atomic` + `change_capture` checked before any file, `GraphMaker::check`). Files are storage-independent. Book `store_own_storage.md`; tests `foreign_store_tests.rs` on `Forwarding`.
- `StoreCore` (crate-internal, non-generic) works on `Arc<dyn StoreGraph>` (`store/graph.rs`, blanket for `Graph<S>`; boxed guards `LiveRead`/`LiveWrite`: position, definition kinds, `write_snapshot_live`, `backup_from_memory`, `mark`, `reload(&LoadPlan)`, `attach_journal`, `register_guard_hook`). `GraphMaker`: `TraversalGraphs` or `Storages(empty)`; maintenance mode copies the salvaged `TraversalGraph` into a new `S` through a packed snapshot.
- The journal lives in `JournalCell`: its forwarding hook is put into the journal slot ONCE at open (`attach_journal` checks capabilities, else `StoreFailure::MissingCapability`); a reload replaces the journal in the cell (an empty cell refuses commits and marks).
- Every file operation goes through a `StoreDir` (`persist/dir.rs`, EXPERIMENTAL; its rustdoc is the implementer's guide: logical `/` names, files only appended or replaced whole, logical lengths, per-method atomicity, writer lock + backup pin; optional `space_usage`/`compact`/`free_space`/`check`, all `io::Result` (a failing `free_space`/`space_usage` fails the compaction advice and `Store::info`; a failing `check` is backend damage through `dir::backend_check`, maintenance mode); an encryption decorator is anticipated), inside the Store via `files::DirPath`: **never `std::fs` in `persist/store/`**. Backends: `FsDir` (native, `fd-lock`; never resolves symlinks, parts may live on other disks; `EXDEV` -> copy+rename+remove; no file records a path, stores are relocatable), `SingleFileDir`, `MemDir` (all targets; the playground keeps every graph as one).
- Accessors of the open store's shared state (`read_only_reason`, `stopped_reason`, `damage_policy`, `store_id`, `damage_found`, `last_auto_checkpoint_error` -> `Arc<PersistError>`) return `Result`: a poisoned internal lock is `StoreFailure::LockPoisoned` (`poisoned_or`), never a default; `is_store`/`SingleFileDir::is_single_file` tell missing (`Ok(false)`) from unreadable (`PersistError::Io`); `info` fails on an unreadable attic or models directory; a fork lists the marks it does not carry before writing, a repair reports unreadable marks in `RepairReport::marks_unreadable`; `run_due_checkpoint` keeps a copy of its error (`PersistError::duplicate`; a graph error as `StoreFailure::AutoCheckpointFailed`).
- Refused operations: `PersistError::Store { operation, cause: StoreFailure, reason }` (`persist/error.rs`, closed `#[non_exhaustive]` causes, one `help()` arm each, stable `name()` = Python `err.cause`). A new refusal picks a cause or adds one with help, test (`store_error_tests.rs`) and a row in `faq.md`.
- `files.rs`: `GRAPH` + `GRAPH.copy`, lineage chain, `LOCK`/`BACKUP` locks, `INTENT`, write order file -> fsync -> rename -> fsync dir. `GRAPH` records `wal_head` (newest segment, flag bit 3; `wal_files::record_wal_head`) and `closed_at` (clean close, bit 4); `wal_files::wal_set_problems` makes a missing/emptied/replaced newest segment, a header not matching its name, or a clean close the files do not reach DAMAGE (9.8). Rollback/attic restore move `wal_head` and clear `closed_at`. `store_id` (5.5): made by create, renewed by fork/attic fork/repair/convert, kept by rollback/attic restore/restored backups.
- `snapshot_dir.rs`: `NewSnapshotDir` (`tmp-*`, removed on drop unless finished, verified as streams, renamed), `write_graph_snapshot`, `import_packed`, `DirSnapshotReader` (a directory snapshot read as the equivalent packed stream). `wal_files.rs`: `JournalFiles` (lazy rotation before a record, `marks` file). A snapshot dir without manifest is a HOLDER of referenced files (`files::list_holders`; prune keeps them via `maintenance::referenced_files`/`spare_retained`; `segment_path` resolves attic references; packed exports are self-contained, `self_contained_manifest`). Store segments default 64 MiB (`DEFAULT_STORE_SEGMENT_BYTES`).
- **Closed-store catalog commits** (`closed_commit.rs`, spec 12.12): `closed_store_prelude` (shared with `checkpoint_dir` and `restore_blobs_from`: version guard, lock, container check, `GRAPH`, backup refused, INTENT, tmp) -> `read_view` (newest snapshot's catalog+schema via `merge::base_catalog`, the WAL tail replayed with `Recovery::catalog_only` + `verify_before_images`; read-only, a damaged record refuses) -> the caller's plan (may write a blob) -> nothing planned = nothing written -> clock (WAL tail, manifest, system journal tail read-only) -> the ChangeSet verified against the view -> what an open does (`apply_wal_cut` + `GRAPH`, unstarted segment, torn tail, `sync_marks`, `sync_ledger`) -> `new_journal` (the open's journal builder: rotation, older-version segment, cut on failure, ledger frames) `before_commit`, always synced -> `GRAPH` `closed_at` forward when clean -> journal `catalog.closed_commit` + `model.*` with `closed: true`. K1: a replace stays a closed commit when no property uses the old revision; when vector rules name it (`ImportPlan::New { replaces_rules: true }`) `import_model_dir` opens the store and runs `Store::import_prepared` (P7's re-embed unit), `ImportModelReport::reembedded` + a first warning say so; vectors without a rule refuse with `ModelInUse` (K3) on both paths. Tests `closed_commit_tests.rs` (crash after every write, all backends), `closed_commit_fuzz_tests.rs` (oracle + backups), `foreign_store_tests.rs`.
- **Blob recovery** (`blob_restore.rs`): `Store::restore_blobs_from(dir, BlobSource::store|zip|packed)` (closed store, lock): every referenced blob checked with its hash, faulty ones copied back (`copy_blob`; ZIP via `zip::check_entries`, `.gsnap` via `PackedReader` kind-4 rows, both `stage` + `install_staged`), never a healthy one; `RestoreBlobsReport`; journal `blob.repaired` `how=restored` + `source`. `RepairOptions::with_drop_damaged_blobs` (`repair_dir_with`/`repair_to_with`): `drop_damaged_blobs` removes the definitions referencing faulty blobs from the salvaged catalog (refused with `BlobUnavailable` naming the properties while the schema needs one), `RepairReport::blobs_dropped/definitions_dropped`, `blob.dropped` in the new store's journal. CLI `store restore-blobs`, `store repair --drop-damaged-blobs`. Tests `blob_recovery_tests.rs`.
- `Store::open` runs recovery (INTENT, tmp cleanup, latest snapshot + WAL replay, torn-tail cut, marks rebuild) and primes the journal (`Journal::continuing`). `close()`/Drop syncs, marks clean, makes the journal refuse commits. The CLI closes an open store on SIGINT/SIGTERM (`signals.rs`, `ctrlc`). Without threads (wasm32) the automatic checkpoint runs in `Store::run_due_checkpoint` (the session calls it after every run; 4 MiB default there).

## Workload sidecar (`store/workload.rs`, spec 4.4)

`WORKLOAD` at the store root: `open_stats` reads it at open (writable store, level `persisted`; else empty in memory), `Shared::flush_workload` writes it (`write_atomic`, only when dirty) from the system job `stats_flush` (`Store::system_jobs()`, also `compact`, off by default) and at `shutdown` (best effort, logged). NEVER copied by backups/ZIP/fork/repair/convert (user decision: instance data); never damage; the version guard ignores it (its magic is no segment/WAL magic). Per-open option `StoreOptions::with_workload_level` (`creation_parameters.md` open-options table). Tests `workload_store_tests.rs`.

## System journal (`graph/system_journal/`, `store/system_journal.rs`, spec 4.7, book `system_journal.md`)

`SystemJournal` (facade `graphersal::system_journal`, NOT feature-gated: every `Graph` has one, `Graph::system_journal()`, an in-memory ring of `MEMORY_CAPACITY` records until a Store attaches its own in `from_core`): declared events only (`catalogue.rs` `EVENT_KINDS`, each with source/level/fields/collapse form; the book's catalogue is generated by the unit test `the_book_shows_the_event_catalogue`, `GRAPHERSAL_UPDATE_BOOK=1`); written by the crate only (`emit(&KIND, Event)`); collapsing of repeats/states before writing (`collapse.rs`); every written record mirrored to `tracing` target `graphersal::journal`; sinks after the lock; the clock is the graph's (`ClockObserver` -> `clock.step_back`; the journal tail raises the floor at open). Store side: `INSTANCE` (instance data, never copied: `copy_tree` skips it) + `journal/<20 digits>.jnl` (64-byte header `GRSLJRNL` with the FILE format version, 26-byte frames, sync marker `0x4A525347`). **The journal never writes in the middle of another store operation:** below `error` records are buffered and written by `stats_flush`, `SystemJournal::flush`, close (`detach_writer`) and with an `error` record (crash/fault-injection tests count every write; a write after an operation would look like an unnoticed failure); damage found while open (`report_damage`, either policy) drops the writer first (`drop_writer`: backups from memory and the fuzz oracle allow no write to a damaged store), read-only opens have none. Never store damage (`report_damage` filters `journal/`, `INSTANCE`; verify `journal_notes`); the version walk reads its headers. Copies: full/ZIP backups copy every segment (`plan_copy`, frame-checked, warnings; `BackupReport::journal_files`, not in `files`/`bytes`), increments append inside `apply_increment` before `GRAPH` (rolled back by `restore_lengths`), from memory leniently, convert via `copy_tree`; fork/attic fork/repair start a new journal whose first record is `store.created` (`record_created` in `create_lineage` before `GRAPH`). Emission sites: open (all modes), close, checkpoint, backup, prune, verify, damage, maintenance, read-only, rollback, attic restore/remove, repair, creation; `auth.denied` from `Restrictions::authorize` (script sources of a host graph). Front ends: `Store::journal`, `Store::journal_dir` (closed store, no lock), CLI `store journal`, `GET /api/journal`, MCP `journal`, session `Session::journal`, wasm `journal`; reading is `Resource::Journal`. Tests `system_journal_store_tests.rs`, `system_journal_copy_tests.rs`, crate units in `graph/system_journal/tests.rs`, `store/system_journal.rs`.

## Embedding models (`store/model_catalog.rs`, `persist/model_tar.rs`, `value/vector/embed/registry.rs`, `graph/model_definition.rs`, spec 4.5, 6.3 kind 5)

A model is ONE blob (a deterministic ustar tar, `model_tar.rs`: `TarStream` writer over `TarFile`s (sorted, per-file SHA-256 re-checked while streaming), `read_tar` over `&[u8]` (hostile input: checksums, bounds, names, sorted/unique, <= 64 files + manifest `graphersal-model.json` format 3, compact canonical JSON, no `added_at`)) referenced by a catalog definition of kind 5 (`ModelDefinition`, facade `catalog`, name = identity, payload `blob`/`family`/`repo`/`revision`/`commit`/`dimension`/`load_bytes`/`license`/`license_text`/`base_models`/`gated`/`default` + unknown keys kept; unknown family or blob algo: `original` written back, `unserved_reason`; catalog invariants in `model_definition::check_conflict` (one per repo, one default) -> `DefinitionError::Conflict { kind: "model" }`). Public (facade `persist`): `Store::models/import_model/set_default_model/remove_model` (+ `models_dir` and the closed-store forms `import_model_dir`, `remove_model_dir`, `set_default_model_dir` (`ClosedCommitOptions`), which append ONE commit without loading the graph: `closed_commit.rs`, below; the planner `plan_import`/`import_changes`/`default_changes`/`plan_remove`/`remove_changes` + `*_event` is shared by both paths, the open path re-plans inside its unit), `ModelSource` (`Dir` native / `Files(NewModel)` read into memory under the ceiling), `ImportModelOptions`, `ModelInfo`, `ModelState`, `ImportModelReport`, `ModelChangeReport`, `StoreInfo::models/default_model`, `VerifyReport::models` (`verify_models`: each model blob read as the tar of its identity), copy reports' `models` = `infos_in_files` of the copy. Import = `prepare` (licence templates `licenses.rs`, safetensors header -> dimension/`load_bytes`) + `write_blob(TarStream)` + check load (model2vec) + ONE `transaction_with` unit (replace drops the old definition in it; vector rules naming the old revision are switched and re-embedded in it, P7; vectors of it without a rule refuse with `ModelInUse`, K3). Refusals: `StoreFailure::ModelUnavailable/ModelDoesNotFit/ModelInUse/ModelRevisionExists` (+ `UnknownModel/InvalidModel`). Registry (`registry.rs`): `ModelRegistry` held by `Graph<S>` (`model_registry`/`attach_model_registry`; every lock guard attaches its `Embedders` to the thread: `registry::attached`, read by `Embedders::current`; no host registry since 0.5.0), one `StoredModelEmbedder` per served definition (lazy load, process-wide `LoadedModels` cache of `Weak`s by blob hash, `loaded_model_bytes` added to the estimated budget, `MemoryStats::model_bytes` via `AnyGraph::memory_usage`), rebuilt by the commit hook `RegistryHook` (never loads), `StoreCore::refresh_models` after a reload, `models_of_view` for views (crate field `Recovered::models`; the public `Recovered::into_graph()` returns the `Graph<S>` with it attached; `Store::embedders`/`Recovered::embedders` were removed in 0.5.0). ## Blobs (`store/blobs.rs`, spec 4.6, 10.1, 12.4; book `store_blobs.md`)

`blobs/<2hex>/<sha256 hex>` (other algos `blobs/algo-<n>/<2hex>/<hex>`), `blobs/tmp-*` (removed at open by `blobs::remove_tmp`), `ledger` at the root. `BlobRef` (`value/blob.rs`, facade `graphersal::blob` with `BlobHashAlgo`, `BlobRefError`, and with `persist` `PendingBlob`, `BlobUsage`, `BlobCopy` (`ModelCopy` = its alias)) is value tag 21 (`codec::put_blob_ref`/`read_blob_ref`, version-guarded); `ElementProperty::Blob(Box<BlobRef>)`, refused as element data by `element_ref_kind` ("blob reference"); in this version blobs are referenced ONLY from catalog definitions (`Definition::blob_refs`: opaque payloads decoded as maps, known kinds via `to_value`), so `blob_table(definitions)` is a state's table (encoder AND merge use it: equal by construction) and `commit_deltas(ChangeSet)` looks only at `SetDefinition`. Write: `write_blob` (tmp + SHA-256/CRC/len streamed, sync, dedup by length+CRC or replace a damaged one, rename, sync both dirs); `Store::write_blob` registers the blob in `Shared::blob_gate` (`BlobGate`) before the rename and returns a `PendingBlob` (drop = release); `Store::read_blob` (length, `ensure_room("blob read")`, CRC). `BlobError` -> `StoreFailure::BlobUnavailable|BlobDamaged` only where the bytes are needed; never store damage (`report_damage` filters `blobs/` + `ledger`; `report_blob_damage` -> journal `blob.damaged`). Ledger: `StoreWalFiles::commit_written` (new `JournalFiles` hook after the WAL append) appends frames under `WalShared::ledger_lock`; a failed append removes the file and sets `ledger_stale` (consumers scan the WAL); open `sync_ledger`: damaged, or missing while `blobs/` holds files -> rebuilt (warning + `ledger.rebuilt`), after a crash the replayed tail is merged in and frames past the end dropped; a store without blobs writes none. Referenced set R (`referenced`): tables of all store + attic snapshots, ledger frames on the chain, frames of every attic entry's WAL (scanned; no attic ledger slice is written), pending. Collection (`collect`, under `ledger_lock` + the gate): `maintenance::prune` (after the file removals: `rewrite_after_prune` then collect; `PruneReport::blobs_removed/blob_bytes_removed`, `prune_estimate` counts them), `attic_remove`, rollback `Delete` (`Shared::collect_blobs`). Copies: full backup (`BackupPlan::blobs`, source + copy checks, not-carried = warning), increment / from memory `sync_into`, from-memory full `copy_state_blobs`, fork/attic fork/repair `carry_state` (repair hashes; its verify ignores the not-carried ones), convert/upgrade `copy_tree` (skips `blobs/tmp-*`), ZIP entries `blobs/..` (`zip::allowed`, `check_archive` streams `check_stream`; restore `check_foreign_dir` hashes every blob), `.gsnap` rows of kind 4 (`PACKED_BLOB_KIND`, path = hash hex, first id `sha256`; `import_packed` stages + `install_staged` with SHA check, rows stripped). Verify: `verify_blobs` (`blobs_checked`, strays = problems, unreferenced = notes; without blobs/ledger only tables are read). A blob of an unknown hash algorithm is never read (`read_blob`: unsupported) but carried BY NAME by every copy (`copy_blob` by-name branch, `.gsnap` row first id `algo-<n>`), checked by length + CRC-32C only. Version walk skips `blobs/` and `ledger`. Tests `blob_store_tests.rs`, `blob_collection_tests.rs`, `blob_copy_paths_tests.rs`, `blob_damage_tests.rs`, `blob_fuzz_tests.rs`, crate units in `store/blobs.rs`.

## Checkpoints (`store/merge.rs`, spec 12.3)

`Store::checkpoint`, the automatic one (background thread past `checkpoint_after_bytes`, also right after an open past it; `run_due_checkpoint` on wasm) and `Store::checkpoint_dir` (`graphersal store checkpoint`, CLOSED store, writer lock) MERGE without the graph lock: read the WAL after the newest snapshot up to the durable end, collect touched ids (+ edge endpoints), decode their base chunks into a delta graph, replay the WAL onto it (`Recovery::start_graph`, `verify_before_images`; a WAL not continuing the base is damage), merge touched runs on the sorted id via `KindPlanner`/`KindEmitter`; memory = the delta. **Donor rule:** the new snapshot never uses a file the base uses, so the previous snapshot stays an independent donor of every id range: an untouched segment is referenced (incremental snapshot, manifest flag bit 0, `<seq>/<file>`, 6.2) only through a *twin* in the snapshot before the base (`merge::twin`), else copied byte for byte (`copy_segment`, `CheckpointReport::segments_copied`); verify reports a shared newest/previous file as the warning `VerifyReport::without_donor`. Beyond `with_checkpoint_merge_bytes` (1 GiB, 64 MiB wasm; 0 = never) the live graph is encoded under the read lock (`checkpoint_from_graph`). Damage stops it with nothing visible written; then a Checkpoint record (write lock, briefly) and a new segment. Tests `store/merge_tests.rs`, `merge_checkpoint_tests.rs` (CP2 matrix), `merge_checkpoint_fuzz_tests.rs`, `graphersal-wasm/tests/merge_parity.rs`.

## Maintenance, backups

- `maintenance.rs`: prune with donor retention under an INTENT, `verify` scrub, file-level backup up to `DurablePosition` pinned by the shared `BACKUP` lock, `changes_since`. `zip.rs` (`persist-zip`).
- `backup.rs` (12.6, 12.7): a backup's `GRAPH` has a marker (flag bit 2): `Store::open` refuses it (`IsBackup`), `Store::open_backup` is read-only (no lock, vetoing `BackupHook`), `restore_backup` clears the marker in place, `restore_zip` yields a live store. `backup()` into an existing backup is an INCREMENT (prefix check of its last WAL segment, tail appended, new snapshots/segments via `tmp` names, re-read, renamed, continuity checked, under an `INTENT` op `backup_increment` in the backup, rolled back when interrupted); it follows an in-place rollback at/after the backup's position. `BackupRefused`: another graph, another store (`store_id` must be equal), a rollback behind it (behind the earliest branch point after its lineage), a pruned gap (no WAL pinning). `BackupMode::Full`, `prune_backup`.
- **Every backup verifies** (`backup_check.rs`, 12.6): full, increment and ZIP check every checksum they copy in the SOURCE before writing (both `GRAPH` copies, `marks`, snapshot incl. referenced files and both manifest fixed copies, every WAL record via `check_segment`, the 9.8 segment set, continuity) and again in the COPY (`check_copy`, increment `read_back`, ZIP `zip::check_entries`). Damage -> `PersistError::BackupDamaged(BackupDamage { side, problems, from_memory })`: a new backup removed, an increment rolled back (`roll_back_increment` writes the old `GRAPH` first). Redundant-copy damage is a `BackupReport::warnings` entry (healed in the copy, marks rebuilt).
- Backup from memory (`from_memory.rs`, 12.11): `Store::backup_from_memory` only after damage was found while open; the streaming encoder writes under the read lock, nothing read/written in the store's dir.
- Damage policy (`files::DamagePolicy`, `GRAPH` bit 5, a creation parameter, see root rule 22): damage found while open (backup, checkpoints, verify; `Shared::report_damage`, attic-only problems excluded) is kept in `Store::damage_found()`; `maintenance` (default) freezes the store read-only (`WalShared::frozen`, `DamageGuard`, `writable()`, `before_record`, `PersistError::DamageFound`, close writes no `GRAPH`); `continue` only reports. Damage at OPEN is maintenance mode regardless.
- Tests: `backup_tests.rs` (crash after every write via a failing `StoreDir`), `verified_backup_tests.rs` (BK1 matrix), `backup_fuzz_tests.rs`.

## Rollback and attic (`rollback.rs`, spec 11, 12.5)

`rollback_to(target, Move|Delete)` plans an `INTENT` (op `rollback`), moves later snapshots and WAL (splitting the segment at the first commit after the target) into `attic/<time>-<seq>/` with an `ATTIC` file, adds a lineage entry and a new segment, then `reload_in_place` clears the graph and loads the store into the SAME instance under the write lock (`LiveWrite::reload` -> `recover::recover_into`: hooks stay), and puts a new journal into the cell (same `DurableEnd`). A failed reload EMPTIES the graph (`LiveWrite::clear`, never a partial state), leaves the cell empty: `StoreFailure::ReloadFailed`. `attic_list/changes/restore/fork/remove`; every step idempotent, `open` completes an interrupted one; recovery follows `Recovery::chain`. **Every attic entry is self-sufficient given the store** (11.2): base snapshot (`ATTIC` `base_snapshot`) + store WAL up to its prefix end + own WAL; a rollback before an older entry's history first copies the WAL it needs into it (`rollback::plan_entries`: INTENT params `copies`/`rebase`/`drop`), rebases it and drops its snapshots that reference moving files; unused holders go (`maintenance::remove_unused_holders`). A rollback/restore failing past its INTENT stops the store (`stop_after_failed_change`/`stop_after_failed_reload`, `Store::stopped_reason`, `StoreInfo::stopped`, session JSON `stopped`; every change `StoreFailure::Stopped`, no `GRAPH` on close). Prune keeps attic bases; verify rebuilds every entry. Tests `store/tests.rs` (interrupted after every step), `donor_attic_tests.rs`, the attic oracle of `merge_checkpoint_fuzz_tests.rs`.

## Damage (`damage.rs`, spec 13)

A load that fails with damage opens READ-ONLY in maintenance mode (`Store::maintenance() -> DamageReport`, vetoing `MaintenanceHook`, `PersistError::Maintenance`, nothing written). `salvage` checks chunks against the manifest's chunk index, reads the WAL with resync, rebuilds damaged base chunks from an older snapshot + WAL for that id range, replays later WAL leniently (`TraversalGraph::replay_lenient`, before images checked -> DIVERGED); `repair_to`/`repair_dir` write that state as a new verified store (new lineage). Both `GRAPH` copies damaged: lineage rebuilt from manifests and WAL headers, `DamageReport::lineage_approximate_before` + `lineage_note()`. Fork, attic fork and repair never copy marks (`marks_not_carried` in reports, CLI, Python, session JSON `marksNotCarried`). Crash/fault tests needing internals are crate unit tests (`store/tests.rs`). Tests `store_tests.rs` (crash images, cuts at every offset, flips per region, split over linked dirs, moved store), `mem_store_tests.rs` (same on `MemDir`, crash images via `MemDir::deep_copy`).

## Single-file store (`persist/single_file.rs`, spec 14, book `single_file_store.md`)

`SingleFileDir`: log-structured `.gstore` container (preamble, two header slots with generation + CRC -> extents table; every change an appended framed record, never overwritten). Each record carries the durable end (torn tail cut at the next write vs damage: `StoreDir::check()` -> maintenance, `DamageKind::Container`); data records with a bad payload pass through to the Store's CRCs. One in-memory container per path per process, writer lock = OS lock on the file, a non-writer refreshes before each operation, a backup pin freezes the view; free space via `rustix` `statvfs` on Unix. `store_dir_at` auto-detects (existing file or new `.gstore` path). `Store::compact()` = prune(current) + backend compaction (new file, atomic rename, lock moved first). `Store::compaction_advice()` (`store/compaction.rs`, `CompactionPolicy`, `AdviceRule`) reads no element data: `space_usage`, free space and a prune plan sized by file lengths (`maintenance::plan_prune`/`prune_estimate`, equals what prune removes). `StoreOptions::with_auto_compact`. **A mark is never lost without a question:** library `prune`/`compact` never ask, the front ends do from `Store::prune_estimate_dir` / `marks_unreachable` (CLI exit 1 without `--drop-marks`; `POST /api/store/compact` 409 without `{"dropMarks": true}`; the playground always asks). `Store::convert(from, to)` copies a closed store name by name between backends. Tests `persist/single_file/tests.rs`, `single_file_store_tests.rs` (every operation on all three backends and mixed).

## Memory ceiling check points

Every data-proportional allocation checks the process ceiling (`traversal/memory_budget.rs` `ensure_room`; book `resource_limits.md` "What the ceiling covers"). `load_snapshot`: `check_fits` (manifest `memory_bytes` vs the lower of `effective_limit()` (+ live heap when tracked) and `ReadOptions::with_memory_limit`) -> `PersistError::MemoryBudget { operation, in_use, setting }` BEFORE the schema is read; each segment (bytes + decoded chunk sizes) pre-checked; `UnitBudget::start_with_element_bytes` ticked per chunk -> `Graph(ResourceLimitExceeded)` while reading. `ReadOptions::operation` (crate-internal) names it: `"store open"` (`load_latest`), `"checkpoint"` (merge replay), default `"snapshot load"`/`"recovery"`. `replay_journals`: `UnitBudget` per replayed mutation; `JournalReader` checks each record length. `FsDir::read_range` checks the range against the file length FIRST, then `ensure_room_io` (`io::ErrorKind::OutOfMemory` carrying the `GraphError`; the `PersistError::Io` help forwards its help); `SingleFileDir` `read`/`read_range`/`read_table` (outer `io::Result` = refusal, never a damaged table). Merge: `read_chunk` and the delta graph (`CHECKPOINT_OPERATION`); `SnapshotEncoder::new(.., operation)` pre-checks index + one chunk; `salvaged` 2x the graph (`"maintenance copy"`); ZIP read-back `"backup verify"` (`check_archive` returns `Result`). `is_damage` treats `Graph(ResourceLimitExceeded)` (like `MemoryBudget` and an `OutOfMemory` `Io`) as a refusal: a store that does not fit refuses the open, never maintenance mode. All checks run on the calling thread (the decode threads never check).
