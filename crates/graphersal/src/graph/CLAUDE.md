# Graph layer (`graph/`)

Agent guidance for storage, units, change capture, catalog, compression, indexes and permissions. Schema: `graph/schema/CLAUDE.md`. Persistence: `persist/CLAUDE.md`. Not packaged.

## Storage and handles

- `TraversalGraph` (`graph/mod.rs`): `Topology` (`graph/topology.rs`, own slot store replacing petgraph's `StableGraph` with its exact observable behaviour: stable indices, LIFO free lists, linked adjacency lists newest first, self-loop in both lists; capacity control `reserve_exact`/`shrink_to_fit`, bounded growth `reserve_one`/`growth_step` (a full slot vector grows by 1/8, doubling only below 512 slots; user decision 2026-11-04: the first insert after a load no longer doubles the slots; `Generations`, the label index's member lists and positions follow it, the hash tables stay power-of-two), exact vacant counts; model test `random_operations_match_a_plain_model`) + property maps + indexes (`graph/index.rs`). No petgraph dependency. Slots: vertex `(id, LabelSetId, PropertyMap, generation)` 96 B, edge `(id, LabelId, Option<PropertyMap>, EdgeGenerations)` 112 B (`PropertyMap` stays 56 B: boxing its `Indexed` form saved 24 B per element but cost 3-10 % on map-building steps and builds; user decision 2026-10-25: not boxed); a materialized element keeps its stored map's shape (`logical_element`); labels interned in `TraversalGraph::labels` (`graph/labels.rs`: every edge label and every ordered vertex label SET once, `Labels::set`/`name`/`name_str`/`name_slice`; hash tables hold numbers only); read a weight's labels through it, intern before taking a `&mut` weight (split field borrows). A load reserves the slots from the manifest counts (`PersistentStorage::reserve_load`) and every load ends in `shrink_to_fit` (no spare slots); a graph built by queries keeps them until `Graph::shrink_to_fit` (DSL `g.shrink_to_fit()`, Python, the Store job `compact`; outside a unit it forgets the footprint cache (inside one the budget keeps extrapolating from the pre-shrink walk; live GraphSON/GraphML imports shrink inside their unit); never automatic in the unit path: batched loads would turn quadratic). `Graph<S = TraversalGraph>` (`graph/shared.rs`) is a lock newtype over `parking_lot::RwLock<S>` (`read()`/`write()`/`try_write()` -> `GraphRead`/`GraphWrite` deref to `S`; `try_write_checked()` -> `Result<Option<GraphWrite>, GraphError>`: `Ok(None)` busy, `Err(GraphViewHeld)` forbidden on the owning thread; no `parking_lot` type in the API). Units across locks: `Graph::begin_unit` (-> `Result<UnitMark, _>`, mark = level index)/`commit_unit`/`commit_unit_with`/`rollback_unit`/`discard_unit`/`unit_changes`/`holds_unit` (owner = the opening thread, raw lock UPGRADABLE until the owner's first `write()`, then exclusive until the outermost close; NO exclusive moment at begin or at the close of a never-written unit: the storage's units open lazily at the first upgrade, `HeldUnit::marks`, the outermost with `begin_unit_at(pinned)`; the time is pinned at begin from `next_unit_started_at` and reaches the owner's read views through the thread-local `held_unit_clock` (read by `TraversalGraph::unit_started_at`) and script terminals through `with_now` in `run_plan_on`; a never-written dry run still opens the storage unit for its change set; the owner's `read()`/`write()` return held views counted in `HeldUnit`; an aliasing view = `GraphError::GraphViewHeld` from `read_checked`/`write_checked`/`try_read`/`begin_unit`/closes, a documented panic only in public `read()`/`write()`; every engine path (`run_plan_on`, `run_unit_on`, `AnyGraph` methods, session `SessionGraph`) uses the checked forms; closing elsewhere = `GraphError::UnitNotHeld`). A unit opened through a `write()` guard must close under that guard. Tests `graph_unit_lock_tests.rs`.
- `AnyGraph` (`graph/any_graph.rs`, `graphersal::storage`, EXPERIMENTAL): the sealed dyn boundary front ends hold (`Arc<dyn AnyGraph>` via `IntoAnyGraph`), blanket for `Graph<S>` with `S: Default + Send + Sync + 'static`, one coarse operation per method (identity/capabilities/statistics/memory, seven schema methods, catalog incl. `set_definitions`, `mark`, io, `write_snapshot`, with `script` `run_plan`/`run_unit`). Every method that reads or writes the graph returns a `Result` (`GraphError` for the reads: a forbidden held view is `GraphViewHeld`, never an empty answer); the script layer looks saved queries up through `StoredQueries`/`GraphCatalog`, which keep a failed catalog read for `finish()`.
- The pipeline is generic over `GraphStorage` (`graph/storage.rs`, EXPERIMENTAL in 0.5.x; its trait rustdoc is the implementer's guide); every method returns a `Result` (a host backend reports `GraphError::storage_failed`, the engine fails the query/unit with it; non-element methods read once per run, never per traverser; element reads `Result<Option<_>>` / `Result<impl Iterator>` (one `Result` per call, never per item; a step maps the error with `?`; the source step's per-element reads go through its `located!` macro, a plain `match` that calls `with_step_frame` only on `Err` (calling `with_step_frame` per element measured +15 % on `v().has(k, v).count()`), and a `PropertyFilter` check runs only when filters exist (+85 % on `v().range()` without that guard); an out-of-line `#[cold]` `with_step_frame` measured slower and was not kept); `TraversalGraph`'s impls `#[inline]`; internal `TraversalGraph` code uses its index/topology directly where a caller cannot fail; proof storage for the failures `graphersal-storage-tests` `failing::Failing`, switches `element_scan`/`element_read`/`adjacency`/`unit_started_at` among others), implemented for `TraversalGraph`, `&mut`/`Box`/`Arc` wrappers, the read-only view `&G` (`&` and shared `Arc` claim no capabilities) and a test-only `MockStorage`. Conformance suite: `graphersal-storage-tests`.
- Label index (`graph/index.rs` `LabelIndex<H>`, one per kind; stage L9): per label a `Vec` of handles (bucket order = insertion order with `swap_remove`, exactly the former `IndexSet` order: scans must keep it), per slot one `u32` position of its first membership, further memberships of multi-label vertices in `extra: (slot, label number) -> position` (asked FIRST; a position entry is confirmed by the member's slot at that position). Every member is live (raw helpers of `undo.rs`), so its handle is current; removal by slot, no graph read. Bare slots + generations at scan time saved 11 MB more on the real graph but cost 6-10 % on label scans (rejected). `LabelIndex::heap_bytes` exact. Model test `label_index_tests::random_operations_keep_the_order_of_index_sets`.
- Id index (`graph/index.rs`): `hashbrown::HashTable<(u32 slot, u32 FNV hash)>` (9 B per bucket with its control byte; stage L9), the id and the generation stored once (in the weight); lookups take the graph, confirm the id at the slot and take the handle's generation from the weight; removal by slot, growth from the cached hash. Invariant and layout: `GraphIndex` docs, book `for_developers/storage_internals.md`.
- Handles (`graph/handle.rs`): `VertexHandle`/`EdgeHandle` = slot + `NonZeroU32` generation, no public constructor. A handle to a removed element never aliases: reads are "removed" (`contains_*` false, no properties, empty adjacency, filters drop it), `id()`/`label()`/materialization/writes fail with `GraphError::ElementRemoved` (deviation, `dropping_elements.md`), a second drop is a no-op. A new handle-taking method validates through `resolve_vertex`/`resolve_edge` or `vertex_weight(_mut)`/`edge_weight(_mut)`.
- Steps carry lazy handles (`TraverserValue::Vertex`/`Edge`, `VertexProperty`/`EdgeProperty`, `Record { keys: Arc<..>, values }`); `size_of::<TraverserValue>()` stays 64.
- A vertex has a label SET (`Vec<CompactString>`, ordered, deduplicated; empty = unlabeled); the first is primary (`vertex_label()`/`label()`/`elementMap()` single-valued like TinkerPop), `vertex_labels()`/`labels()` the full set. Edges have one label; `GraphStorage::set_edge_label` (checked under the new label; `UndoEntry::EdgeLabel`, `Mutation::SetEdgeLabel`, WAL op 11).
- **Property shapes** (`graph/shape.rs`, `value/property_map.rs`; book `for_developers/storage_internals.md`, keep it in sync): every stored map is `PropertyMap(Repr::Shaped { shape: Arc<Shape>, values: Vec<ElementProperty> })` (or `Repr::Coded` under top-level `dedup` rules: "Compressed properties" below; the writers `insert_full`/`shift_remove_full`/`shift_insert` turn it plain first, `adopt` keeps an owned one) (values exact when built or grown, a removed key's slot kept as capacity); the `ShapeTable` (`TraversalGraph::shapes`, a `hashbrown::HashTable` by key-sequence hash) interns key sequences without allocating on a hit (the last shape tried first). Lookup: `KeyPrint` (len + first/last 8 bytes, exact up to 16 bytes) scan for <= 16 keys, an `IndexSet` above: no `memcmp` per candidate. Transitions `(shape, position, key)`/`(shape, position)` in `MixHasher` maps (never FNV over words: it cost more than the transition) behind one-entry memos. Choke points: `insert_vertex_raw`/`insert_edge_raw` `adopt` every entering map; in-graph key-changing writes go through `shapes.insert_full`/`shift_remove_full`/`shift_insert` (`with_vertex_map`/`with_edge_map` split the borrow), a generic-helper write (jpath) re-`adopt`s. A shape carries its table's id (adopt = one compare); a foreign shape is re-interned (memo `last_foreign`). Snapshot chunks decode maps `Shaped` directly (`persist::codec::ChunkShapes`, by key-reference sequence; no `IndexMap`). The importers do too: GraphSON/GraphML collect keys and values in a `MapBuilder` (`shape.rs`; a repeated key = `insert`'s first position/last value, merged at `finish`) interned in importer-own tables (one per element kind; the graph adopts via `last_foreign`, any storage takes them); change sets copy each added map with `TraversalGraph::stored_copy` (`ShapeTable::shaped_copy`, own table) in `TraversalGraph::apply_change_set` (override of the default's body `apply_change_set_with`) and every replay path, other storages clone (`replay::clone_map`). Tests `import_shape_tests.rs`, `shape.rs` `import_tests`; benches `imports::*`. Sweep (drops shapes only the table holds; clears caches and memos) on table doubling, `shrink_to_fit`, loads; never under `&self`. Free-standing maps stay `Indexed` (hot paths match `Indexed` first, the `Shaped` arm out of line); a key change through the public API converts a `Shaped` map to `Indexed`. **Nested maps (stage V3):** objects inside stored values (also inside arrays) are `Shaped` in the same table down to `shape::NESTED_DEPTH` (8) container levels (bounded recursion: the 2 MiB debug test stack; deeper maps stay `Indexed`), at the SECOND sighting of a key sequence (`ShapeTable::seen_once` hash set, max 65 536, cleared on `shrink_to_fit`, so a never-repeating key set stays `Indexed`, smaller than an own shape); own memo `last_nested`; never the transition caches (a key insert inside a nested map unshapes it, the next write of the property reshapes). Entry points: `adopt_slow`, `insert_full_plain`/`insert_full_coded`, `shaped_copy`, `shape_value` (jpath `write_path_stored`, `store_coded_value`). Snapshot bytes unchanged except the manifest's `memory_bytes` estimate; `PropertyMap::eq_mixed` compares two maps of one shape by their value vectors. Tests `shape.rs` `nested_tests`, `nested_shape_tests.rs`; benches `nested_values::*`. Real graph: property -91 MiB. **Decoded nested maps (stage V3b):** snapshot chunks build a nested map `Shaped` over a chunk shape (owner `shape::DECODED` = 0) from the second sighting of its key-reference sequence in the chunk (`ChunkShapes::nested_shape_of`, own `nested_seen` hashes and `nested_last` memo; first sighting, empty and deeper maps `Indexed`); the graph (`ShapeTable::shape_decoded_map`) applies the SAME second-sighting rule (`nested_shape(.., false)`) and turns the map `Indexed` when it disagrees (e.g. `{a:{a:1}}`, `seen_once` cleared), so the stored form never depends on the decode; a 64-entry memo `decoded` (decoded shape address -> ours, holds both, cleared by `sweep`) makes repeats one pointer compare. Test hook `TraversalGraph::with_nested_maps_decoded_indexed` (doc-hidden, thread-local `codec::NESTED_INDEXED`, carried into the decoder threads by `snapshot::decode_chunks`): the reference of `nested_decode_tests.rs`. Real-graph open +0.5-1 % over c3311b32 (V3 alone +2-3 %); caller-built nested maps (`insert_build`, `write_object`) are still converted at adoption. The trait is unchanged. Tests `shape.rs`, `property_map.rs` `shaped_tests`/`key_print_tests`, `codec.rs` `chunk_shape_tests`, `property_order_tests.rs`, `property_shape_tests.rs`; benches `element_properties::*` (incl. `insert_build`, `bulk_build`, `get_key`).
- **Insert vs add:** `insert_vertex`/`insert_edge` are the required primitive (store exactly what is given, coercing + validating; imports, change sets, replay, loads, copies use them; never generate a value). `add_vertex`/`add_edge` (never override) create like a query: the override point `add_vertex_with`/`add_edge_with(.., &CreateContext)` applies schema create-time defaults, then calls `insert_*` (conformance `add_applies_schema_defaults_insert_does_not`).

## Custom storages

A host's `GraphStorage` (+ `Default + Send + Sync + 'static`; `PersistentStorage` to be stored) runs under every generic front end; book `for_developers/custom_storage.md` (example `crates/graphersal-session/tests/custom_storage_example.rs`, included by anchors). Engine monomorphised per storage; one dyn boundary per layer: `AnyGraph` (script, saved queries), `SessionGraph`/`SessionStore`/`GraphFactory` (session), crate-internal `StoreGraph` (Store). `TraversalGraph`-only: script scratch graphs (`GraphSource::*`, `__`, `_g`, `subgraph`/`cap`/`toGraph`), a `withSideEffect` subgraph target, compressed properties (`recompress` `Unsupported` elsewhere), the undo log, merge checkpoint/salvage/repair working graphs, the shipped front ends. An unimplemented operation is `GraphError::Unsupported { operation }`. Proof storage `Forwarding`: `foreign_storage_tests.rs`, `generic_persist_tests.rs`, `foreign_store_tests.rs`, session `storage/tests.rs`, TinkerPop with `GRAPHERSAL_TEST_STORAGE=forwarding`.

## Units (undo log)

- `begin_unit() -> Result<UnitMark, GraphError>` / `commit_unit(mark)` / `rollback_unit(mark, &RollbackReason) -> Result<(), GraphError>`; units nest (inner = savepoint); defaults are no-ops (non-atomic storage). A failed `rollback_unit` still closes the unit: openers report it through `storage::rollback_failed_unit` (`GraphError::RollbackFailed` naming the cause), unwinding through `storage::rollback_unwound` (logged). **A failed rollback poisons the `Graph`** (user decision 2026-10-28): every engine rollback path calls `shared::note_failed_rollback` (also `Transactional::transaction_with`/`dry_run` and the held-unit closes; a failed `discard_unit` counts unless `shared::close_failed` says it is the no-change-capture `Unsupported`), which names the failing storage by `GraphStorage::storage_identity` (opaque `StorageIdentity`, default `StorageIdentity::of(self)`; wrappers forward it; `held_unit_clock` matches the pinned unit clock the same way) and marks the innermost `RollbackWatch` OF THAT STORAGE on the thread (one per `GraphWrite` and per held-unit storage close, recording the graph's storage identity and the memory of its `S`): exactly that graph is poisoned, never another one (nested/out-of-order views of several graphs, a bare storage beside them), nothing for a bare storage; the watch's end sets `Graph::poison` (atomic flag + cause) before the lock is released. A poisoned graph: `GraphError::Poisoned` from `read_checked`/`write_checked`/`try_write_checked`/`begin_unit`/closes (a close still releases the level and the lock, no storage call), `None` from `try_read`/`try_write` (the same as busy, for good: documented on both with how to tell them apart, `is_poisoned`/`try_write_checked`), panics in `read()`/`write()`; one atomic load per lock acquisition (after acquiring, so a waiting reader sees the poison); diagnostics `is_poisoned`/`poison_cause`; `into_inner`/`get_mut` allowed; no unpoison. A bare storage is never poisoned. A new rollback path calls `note_failed_rollback(storage.storage_identity(), ..)` on failure. A storage read that fails while building the diagnostic of another error (value origin, type names: `observed_type_name`, `kind_name`, `ValueSource::origin`) leaves the detail out (`error::UNREADABLE_DETAIL`), never replaces the error. Tests `graphersal-storage-tests/tests/failing_storage.rs`; `Graph`'s held units open the storage's units at a write and a failed open is that write's error (`open_storage_units` retries at the next write). `TraversalGraph`'s private undo log (`graph/undo.rs`) records inverses (string ids and element images, never handles; old value with position, old label set, old schema) and replays them in reverse via raw helpers (`insert_vertex_raw`, `remove_vertex_raw`, `insert_edge_raw`, `remove_edge_at`), restoring structure, indexes, statistics, schema (not iteration order; new handles; auto-id sequences never rolled back).
- One unit each: every traversal (`run()` and every terminal inside `GraphTraversalSource::atomically`; a failing traversal leaves nothing, deviation `transactions.md`), `set_schema` and a catalog change outside a unit, a live GraphML/GraphSON import, `apply_change_set`. Loading an unpublished graph (`from_graphml`, `from_graphson`, `GraphSONImport::load`, `TraversalGraph::replay`) runs outside units (`load_outside_units`). Direct trait calls outside a unit record nothing (conformance `mutation_outside_unit_records_nothing`).
- `Transactional` (`graph/transaction.rs`, blanket, prelude + `storage`): `transaction(|g| ..)`/`transaction_with(CommitMetadata, ..)` (panic rolls back; `E: From<GraphError>` carries a veto; nested metadata merged via `set_unit_metadata`, outer wins), `dry_run(|g| ..) -> (T, ChangeSet)` (always `discard_unit`: no hooks, `commit_seq` 0; needs `change_capture`). `unit_changes(mark) -> UnitChanges { data, schema, definitions }` makes `Execution::mutated()`/`changes()` right inside an outer unit.
- Panic safety: a unit unwinding rolls back first (`graph::storage::close_on_unwind`; every opener uses it, a new one too). `commit_undo_unit` covers the commit once: a panic while deriving the change set or in `before_commit` rolls back, sends `after_rollback`, resumes; a panic in `after_commit` leaves it committed.
- **A new mutating `GraphStorage` method of `TraversalGraph`** records an `UndoEntry` only when it changed something, keeps statistics exact, and gets a case in `graph/capture.rs`. If it writes a property it calls `check_derived_vertex`/`check_derived_edge`/`check_derived_map` (vector rules).
- **Vector rules** (`graph/vector_rules.rs`, book `vector_rules.md`): `TraversalGraph::vector_rules` (compiled at every schema write: `refresh_vector_rules` at each `schema.write()` site; `None` = one branch). `commit_undo_unit` runs the rule pass at depth 1 BEFORE the budget check and the seq (`run_vector_rules`: touched set from the undo log, full fills for rules added/changed since the unit's first `Schema` entry, one batch per model, `write_derived` with `rules_off`), and `discard_undo_unit_with_changes` for dry runs (no journal). A failure rolls the unit back (`VectorRuleFailed`, `ResourceLimitExceeded` via `unit_check_adding`). Direct writes of a rule's `to` in a live unit: `GraphError::DerivedProperty`. Exempt: outside units (replay, loads), `apply_change_set` (`rules_off` + `UndoLog::exempt_from`). Models: `hash-ngram/1` or the attached registry (`registry::attached`, set by a `Graph` guard and `close_held_unit`); test hook `with_test_models`. A `Graph` write guard attaches `WriterContext` (journal cell, clock, `ProgressCell`): full fills journal `vector_fill.started`/`done`/`failed` (`emit_op`) and report `Graph::vector_fill_progress`. Model replacement: `Store::import_model` with replace rewrites the rules (`replace_model_in_schema`) in the replacing unit after rebuilding the registry; rule-less properties of the old model refuse (`places_without_rule`, `ModelInUse`).

## Change capture and hooks

- `ChangeSet`/`Mutation` (`graph/change.rs`, public, `#[non_exhaustive]`, `compact()`, serde behind `serde`): one committed unit: `commit_seq`, `committed_at` (i64 µs from the instance `CommitClock` (`graph/clock.rs`, inside `CommitHooks`, `commit_time`) shared with marks, Store checkpoint records and the system journal: `max(now, floor)`, floor raised by every commit/replay/`raise_position`/`with_last_committed_at`, by recovery to `RecoveryReport::clock_floor` (marks and checkpoints included) and by the Store open to the snapshot's `created_at`; `GraphStorage::commit_clock` hands it out (default `None`; `Graph<S>` keeps it, else its own, `pub(crate) Graph::clock`); step back > 1 s = `tracing::warn` / `ClockObserver`; 0 for a dry run), `node_sequence`/`edge_sequence` AFTER the unit, `CommitMetadata`, mutations in order with before/after values (cascaded `DropEdge`s before their `DropVertex`; a jpath write is a `SetProperty` of the top-level key; `SetSchema` in the same stream).
- Built at the outermost commit only while a hook is registered, by `derive_mutations_since` (`graph/capture.rs`: backwards walk of the undo log over a shadow), so nothing is paid without hooks.
- Hooks (`graph/hooks.rs`, `CommitHook`): `before_commit` may veto -> rollback + `GraphError::CommitRejected { hook, source }` (help from a `HookRefusal { message, help }` or `PersistError` source), `after_commit`, `after_rollback`; `register_commit_hook` (default `Unsupported`, never removable); registration order, `commit_seq` order, only the `ChangeSet`. Empty units emit nothing, except a sequence-only commit (`raise_id_sequences`).
- Foreign code: `ChangeSet::builder(seq, at)` (`build()` -> `GraphError::InvalidChangeSet`), one constructor per `Mutation` kind, embedded public `CommitHooks` (ordering contract documented there; `set_journal(JournalSlot)`).
- `last_commit_seq()` + an export under one read lock = a snapshot with position; `with_last_commit_seq(n)`. `apply_change_set` (one captured, vetoable unit) then raises id sequences (`raise_id_sequences`, never lowered); `TraversalGraph::replay(self, &ChangeSet)` raises seq, time and sequences. Counters never wrap: `GraphError::SequenceOverflow` (rolled back).
- Serde of a `ChangeSet` tags non-JSON types per value (`g:UUID`, `gx:OffsetDateTime`/`gx:ZonedDateTime`/`gx:OffsetTime`/`gx:LocalDate`/`gx:LocalDateTime`/`gx:LocalTime`/`gx:Duration`/`gx:Period`/`graphersal:Interval`, `graphersal:Vector`, user objects with `"@type"` escaped as `graphersal:Object`; strict reading; `value/physical.rs` `Tagged`/`TaggedOwned`). GraphML and the rest of the codec stay untagged.
- `StorageCapabilities` (`graph/capabilities.rs`, facts not permissions; `TraversalGraph`: `atomic`, `change_capture`, `writable`): `change_capture` requires `atomic` (debug assertion in `GraphTraversalSource::new`). Docs `book/src/users_guide/transactions.md`.

## Statistics and memory

- `GraphStorage::statistics() -> Result<Option<&GraphStatistics>, GraphError>` (`graph/statistics.rs`): totals, vertex counts per label and per primary label, edge counts per label. `TraversalGraph` maintains them in the raw helpers + every label-set change; a new mutation path updates them too (`statistics_tests.rs`, compared with `GraphStatistics::from_storage`). The executor reads label counts only here and scans on `None`. Limits never go in (session `Session::statistics()` = `{statistics, memory, limits}`).
- `memory_usage() -> Result<Option<MemoryStats>, GraphError>` (`graph/memory.rs`, trait method, default `Ok(None)`): on-demand footprint (`structure_bytes`/`index_bytes`/`property_bytes` (incl. `shape_bytes`: each shape once; a stored map counts its value slice), compression and `property_index_bytes` fields); unrelated to execution. Profiling memory: `traversal/CLAUDE.md`.
- Memory report (`graph/memory_report/`, facade `storage`, book `memory_and_profiling.md`): `GraphTraversalSource::memory_report(&MemoryReportRequest)` (Read on Data, `CancelToken` -> `Cancelled`) runs `walk::compute`, ONE generic walk over the read API (labels, maps, degrees, `property_indexes()`, `compression_stats()`): rows per `(kind, primary label, top-level key)` = `PropertyTarget` (shared with the planned workload statistics), aggregated by shape pointer (memo; `Indexed` maps by key), HLL distinct strings (`hll.rs`), stratified sampling per label (first element always read, scale = seen / read). Storage-only part: trait `memory_structure() -> Result<Option<StructureMemory>, GraphError>` (default `Ok(None)`; `Forwarding` deliberately does not forward it). Invariant tested: `MemoryReport::property_bytes() == memory_usage().property_bytes` for `TraversalGraph`. Row caps: `MemoryReportRequest::DEFAULT_LIMIT` (500) property rows and label rows by default (`with_limit`, `with_max_rows`/`with_max_labels`; `usize::MAX` = all, used by the advisor), chosen in `walk::fold` by one selection pass BEFORE the kept rows are built (a full build + sort of 333k rows of the `large` graph made 207 MB of JSON); the rest counted (`rows_omitted(_bytes)`, `labels_omitted(_elements/_bytes/_property_bytes)`), totals complete. Forms: `to_property()`/`to_json()` (`property.rs`, the one map every front end shows), `Display` (`text.rs`, REPL `/memory`). Tests `memory_report_tests.rs`. Process components (`components.rs`, R0 2026-11-04): `MemoryReport::components` (`MemoryComponent {name, detail, bytes, exact}`), `attributed_bytes()`, `unattributed_bytes()` = tracked (read at the START of the walk) minus their sum (`None` without tracker or structure). Filled at report time only, NEVER on read/write/commit/query paths: `graph` (walk), `workload_statistics` (`AnyGraph` path), `embedding_model` (process cache `registry::loaded_models`; bytes counted ONCE at load by the thread-live delta when tracked), `script_engine` (the per-thread `SHARED` registrations, counted once per thread at build), registered `MemorySource`s (process-wide `register_memory_source`, held weakly): the Store's `Shared` (`store`, `store_files` for a `StoreDir::memory_bytes` dir, `store_graph` = its live graph when the reported graph is another, compared by `Graph::storage_address`, read with `try_read`), the session (`session`), the dev server (`mcp`, `ai_chat`). `AnyGraph::memory_report` collects AFTER releasing the read lock (a Store source locks its own graph); the bare `GraphTraversalSource::memory_report` passes no address, so no Store lists its graph there. Sources must never block or call a report. `AnyGraph::process_memory_components` = the same process parts (`components::process_components`, everything but `graph`/`workload_statistics`) WITHOUT the walk: the session's process memory bar reads it on every statistics refresh. Tests `memory_components_tests.rs`, CLI `the_memory_report_attributes_the_process_heap`, server `the_memory_report_names_the_servers_components`.

## Workload statistics and scheduled jobs (`graph/workload/`, `graph/jobs/`; facades `workload`, `jobs`; books `persistence/workload_statistics.md`, `scheduled_jobs.md`)

- `WorkloadStats` (instance data, never WAL/commit): series `SeriesKey { kind: SeriesKind, channel: Channel }` in three tiers (minute x 60, hour x 48, day x 90; every sample adds to each tier's current bucket, no roll-up; sparse), `Counters` (count, failed, items, total/max µs), `WorkloadLevel` off/memory/persisted, `record`, `record_job_run` (job block), `report(now)`, `clear`/`clear_before`. ## Compressed properties (`value/compressed.rs`, `graph/compression.rs`, book `compressed_properties.md`)
