# Rhai DSL (`script/`)

Agent guidance for the Rhai DSL, its tokens, saved queries, limits and the script entry's permissions. Not packaged. Root rule 2 (DSL parity) applies to every change here.

## Layout

`ScriptGraphTraversalSource` wraps the Rust API; the layout comment at the top of `script/mod.rs` lists the modules (none above ~1k lines): `eval.rs` (`graph_scope*`, `eval_*`, parameters), `engine.rs` (`engine_with_limits`: limits, authorizer, keyword-token rewriting), `access.rs` (session authorizer, private graphs, `import` resolver), `register/` (registrations by category: `types.rs`, `tokens.rs`, `terminals.rs`, `steps.rs`, `register_variadic!`; via `registry.rs`'s `Registry`, which mirrors the `Engine` API into `rhai::Module`s built once per thread; `new_engine()` attaches them and a shared standard library by pointer, so `engine()` costs microseconds), `tokens/` (one file per token class), `step.rs` (the `Step` AST), `source/` (builder methods by family), `convert.rs`, `terminals.rs`, `mutating.rs` (`is_mutating()`), `plan.rs` (script group of `AnyGraph`), `dynamic.rs`, `render.rs`, `tests.rs`. Public items are re-exported from `script/mod.rs` as `graphersal::script::X`.

## Any storage

A source holds `Arc<dyn AnyGraph>` (`ScriptGraphTraversalSource.g`; `None` = scratch `TraversalGraph`); `graph_scope*`, `eval_*`, `ScriptGraphSource::graph` take `impl IntoAnyGraph`. A terminal is ONE `AnyGraph::run_plan(&ScriptPlan, Terminal)` call; schema/catalog/statistics/memory/`mark`/io/`export_snapshot` go through other `AnyGraph` methods. `eval_value_atomic`/`eval_value_dry_run` use `AnyGraph::run_unit` (write lock, `std::mem::take` into a private `Graph<S>`, swapped back on return and unwind; a returned traversal is retargeted via `plan::same_graph`; a returned closure/`FnPtr` -> `ScriptError::ReturnedClosure`, rolled back). The playground runs every script as one unit (commit iff `ok`); CLI and Python keep per-traversal units. Graphs a script builds stay `Graph<TraversalGraph>`; a `withSideEffect(name, g)` target is downcast (`into_any_arc`), a foreign one is `GraphError::Unsupported` (`error::SUBGRAPH_TARGET`).

## Lowering

`convert.rs`'s `lower()` turns the `Step` AST into engine steps with the `AnonymousTraversal` builders for `g` (`ast_convert_to_gts`) and `__` (`ast_convert_to_anonymous`) alike: **a new step gets exactly one arm there.** The root differs in four hooks only: source steps (`Step::Source`: `withSack`, `withSideEffect`; inside `__` a marker failing with `TraverserError::SourceStepInChild`), a leading `mergeV()`/`mergeE()` (`merge_*_lowered(.., start)`), a no-step `by()`/`from()`/`to()` naming `g` (`adopt_lowered`), and a leading `gql()` (feature `gql`, `source/gql.rs`): `gql_start` lowers it with `GraphTraversalSource::gql_with` (it needs the storage) and `lower_onto` continues those steps; the builder refuses `gql()` on `__` or after non-source steps at the call (GQL error, kind `NotYet`), the `lower()` arm keeps a `gql:error` marker as a fallback. A builder that differs at the root needs such a hook; `source_step_tests.rs` guards that `g.X` and `__.X` lower to the same plan.

## Registration and docs

- Every step in both spellings, snake_case and camelCase, from ONE entry (`registry.register_fn_as(&["has_label", "hasLabel"], f)`, `register_variadic!(registry, ["has_label", "hasLabel"], ..)`), one overload per arity. `script/surface_tests.rs` snapshots the surface into `tests/snapshots/script_surface.txt` (`GRAPHERSAL_UPDATE_SURFACE=1`, review the diff) and checks both spellings have the same overloads (exceptions in `SINGLE_SPELLING` with reasons).
- `register/docs.rs`: one entry per DSL function (receiver + spelling-independent key: one sentence in canonical snake_case style, a runnable modern-graph example and its result), attached as `docComments` to every overload/spelling (`#[export_module]` functions carry it as `///`). Read by playground completions, MCP `graphersal://dsl-reference` and the generated book step reference. `register/docs_tests.rs` fails on a missing/stale/unused entry or a wrong example result.
- Never compare a script type by a type-name literal: use `Dynamic::is::<T>()` or `std::any::type_name::<T>()`. A diagnostic never names a Rust type: `type_name_of`/`dynamic_text` (`dynamic.rs`, `register::display_type_name`: `int64`, `float64`, `Predicate`, `GraphTraversalSource`); Rhai's own errors go through `script::map_eval_error`.
- Data terminals (`toList()`, `next()`) return native Rhai values; a traversal without terminal is rendered by the session visualizer. UUID literals: `UUID.fromString(..)`/`UUID.from_string(..)`/`UUID::…`, carried natively (`ScriptUuid`).

## Tokens

Pattern (`Column`, `Scope`, `Cardinality`, `Direction`, `Merge`, `Operator`, `Barrier`, `Pop`, `SchemaMode`, `DT`): a Rust enum registered as a type, `register_static_module("X", ..)` for `X::y`, and a marker `ScriptX` pushed in `graph_scope()` with getters for `X.y`. Provide both spellings and add the global to `RESERVED_PARAM_NAMES`; `reserved_param_names_match_graph_scope` (`script/tests.rs`) fails otherwise (also covers `T`, `By`, `Order`, `Pick`, `GType`, `CastPolicy`, `ProfileType`). Bare constants exist only for `Column` (`keys`/`values`, reserved), `Pop` (`first`/`last`/`all`/`mixed`) and `DT` (`second`/`minute`/`hour`/`day`), via plain `push`, never `push_constant` (Rhai folds `${const}` with the Rust type name); of `Pop`/`DT` only the class name is reserved, so `let first = ..` shadows. Every token value, marker, `Set.of(..)`, predicate and anonymous traversal prints as its DSL literal through `value::literal::TokenLiteral` (`to_string`/`to_debug` and `script::render::token_literal`; a new token type is added there); `every_graph_scope_token_renders_as_its_dsl_literal` checks round trips. Predicates: `P.x(..)`/`TextP.x(..)` plus lowercase bare globals (`gt(30)`, `within(1, 2)`), `By.X(..)`, `jpath(..)`; PascalCase twins (`P::Eq`, `TextP::StartingWith`, `By::Property`) only in static modules (`tokens/predicate.rs`). `select` dispatches on a leading `Pop`. Map keys mirroring tokens are reserved STRINGS in `mergeV()`/`mergeE()` maps: `"T.id"`, `"T.label"`, `"Direction.OUT"`, `"Direction.IN"`, `"Merge.outV"`, `"Merge.inV"` (book `upserts.md`).

## Saved queries (`script/saved_query.rs`, book `saved_queries.md`)

Source methods, both spellings (`query`/`queries` one word): `g.define_query(#{name, body, folder?, description?, params?, meta?})` (body = ONE Rhai function named like the query; params = name -> type name or `#{schema, default}`, equal to the signature as a set, stored in signature order; description defaults to the doc comment), `g.define_queries(folder, source[, params_by_fn])` (each function a query, text cut by span, one transaction), `g.query(name[, #{args}])`, `g.queries([folder])`, `get_query`, `drop_query`, `move_query`, `describe_query`. A call: start position only (`QueryNotAtStart`), `Execute` on the query first, depth <= `MAX_QUERY_DEPTH` 16 (`QueryDepthExceeded`), arguments via `QueryParam::check_value`, body compiled through a per-thread cache keyed by name + dialect + params + source (`InvalidQueryBody`; the `Compiled` entry also holds the body's own effects). Dialects: `QUERY_DIALECT` `graphersal-rhai/1` read-only, `WRITING_QUERY_DIALECT` `/2` may write; EVERY save (`define_query`, `define_queries` with batch-local callees, session `with_inferred_dialect`) recomputes it from the effects, opens never change it, the Rust API/catalog import keep it. Effects (`effects.rs`, issue #11): `analyze(ast)` walks the AST, folds each method chain with the SAME flow rules as `GraphStep::access_flow_after`/`for_each_access_in` (table `CLASSES`, both spellings), sound over-approximation; `Fn`/`call`/`curry`/`eval`/`import`/a computed `g.query(name)` make a body dynamic (refused only together with writes), schema/catalog/file/`mark` methods are refused at define; `transitive` adds called `/2` queries. `g.gql(literal)` (feature `gql`, `StepClass::Gql`, matched in `classify` outside the table) lowers the query on a scratch graph with placeholder parameters (`gql::lower::planned_writes`, walked by `permission_check::plan_write_requests`, the same flows as the check); a computed text, or a plan that needs a parameter's value (`LIMIT $n`) under every placeholder, claims Create/Update/Delete on any data. `effects_tests.rs` checks the table names are registered, exact equality with the authorization check on curated chains, and coverage of every write of every `docs.rs` example. A `/1` call (or any call from a read-only body) runs with `g` under `ScriptAccess { read_only: true }` (the `ReadOnly` authorizer denies Create/Update/Delete on Data, Schema, Definition, File: `error::SAVED_QUERY_READ_ONLY`); a `/2` call with effects asks every effect of the caller's authorizer first, then runs as ONE `AnyGraph::run_unit(UnitKind::Call(CommitMetadata{saved_query, saved_query_args}))` under the `Effects` authorizer (`read_only: false`; data writes outside the effects `SAVED_QUERY_OUTSIDE_EFFECTS`, others `SAVED_QUERY_DATA_ONLY`), a returned non-anonymous writing traversal is run inside that unit and replaced by `inject(results)` (`run_returned_writes`; an anonymous one is refused), and `seal_returned` retargets what it returns to the caller's graph with the read-only access. The access travels with every source built in the body; a returned writing traversal is refused (`QueryReturnedWrite`; `plan_writes()` is the raw mapping). Public `saved_query_effects`/`SavedQueryEffects` and `with_inferred_dialect` back the session; `g.queries()` entries carry `writes`, `effects`, `denied_writes`. Body errors get a line `in saved query: "name"` before `Help:`. `default` is rewritten from a reserved word (`engine.rs`). GQL bodies (feature `gql`, `saved_query_gql.rs`): `define_query(#{.., language: "gql", body: "<GQL text>"})` (`language` default `"rhai"`; `define_queries` stays Rhai), dialects `GQL_QUERY_DIALECT` `graphersal-gql/1` / `GQL_WRITING_QUERY_DIALECT` `/2` from the plan's writes (`gql::lower::saved_query_plan`: parse + bind + lower on a scratch graph with placeholders, params in first-use order, writes exact per label); `$name` declared/used checks (`ScriptError::UndeclaredQueryParameter` / `UnusedQueryParameter`); `Compiled.body` is `Body::Rhai(ast)` | `Body::Gql`; a call runs no Rhai: `run_body` returns `g.gql_step(source, args).stamped(ctx)` under the call's access, a read-only call runs a writing plan at once through `run_returned_writes` (denied by `ReadOnly`), a writing one inside the call's unit like a Rhai body; `with_inferred_dialect` keeps the language of the dialect it is given (`graphersal-gql/..`). Entries carry `language` (`QueryDefinition::language()`) and `dialect`. Tests `saved_query_tests.rs` (GQL: `mod gql`), `saved_query_effects_tests.rs`, `permission_tests.rs` (`saved_queries`), `error_diagnostics_tests.rs`, `forward_compat_tests.rs` (a newer `graphersal-gql/3`), `script_tests.rs`, `script/effects_tests.rs`.

## Limits (`script/limits.rs`)

`ScriptLimits` (`#[non_exhaustive]`, `with_*`, `Default` = SAFE, `unlimited()` for trusted local front ends) installed by `engine_with_limits`; `engine()` and `eval_*` use SAFE, `eval_value_with_limits` takes explicit ones; Rhai limit errors -> `TraverserError::ResourceLimitExceeded` (`resource_limit_from_rhai`). `max_value_depth` also covers script ingress and parameters. `engine_with_options(limits, authorizer, options)` puts host presets on every source (`g`, `_g`, `__`, `GraphSource::*`). Hosts stop pure Rhai loops with `on_progress`. Native front ends evaluate on a 64 MiB stack thread (Rhai recurses on nested values). Rhai measures arrays per call (quadratic `push`), so keep array/map defaults modest.

## Script-entry permissions

`engine()`/`graph_scope(g)`/`eval`/`eval_value`/`eval_*_params` allow everything; `engine_with_limits(limits, Arc<dyn Authorizer>)`/`engine_with_options`, `graph_scope_with_options`, `eval_value_with_limits`/`_atomic`/`_dry_run` take one (`import` resolver: `Execute` on the module `File` via `resolve_file`). A graph the script built is private (`ScriptGraphTraversalSource.private`): data/schema writes (`writes_graph`) are allowed without asking, unless the plan writes a subgraph into a host graph (`withSideEffect(name, g)` asks `Create` on `Data`). Non-step source methods ask themselves (`require`/`require_file`): `export_graphml` = Read Data + Create File, `import_graphml` = Create Data + Read File, `set_schema`/`patch_schema` = Update Schema, the other schema methods Read Schema, `GraphSource::file` = Read File, `statistics`/`memory_usage` = Read Data. Integration tests import the script API from `tests/all/script_host.rs` (AllowAll), except `permission_tests.rs`.
