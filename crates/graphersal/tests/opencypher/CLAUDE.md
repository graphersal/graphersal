# openCypher TCK 2024.3

Agent guidance (also see `README.md` here; the compliance page `book/src/gql/tck_compliance.md` comes with the runner). Commands are in the root `CLAUDE.md`.

- `--test opencypher_tck` (separate target, rule 17 exception; feature `gql` only, the Rust GQL API, no Rhai) runs the vendored openCypher TCK scenarios (`features/`, named graphs in `graphs/`) and gates them against the ratchet `baseline.toml`. Harness in `harness/`. Every run writes `target/opencypher-report.md`: the fix backlog. Built so far: the Gherkin parser `harness/gherkin.rs` (typed `Step` model, outline expansion, Background, tags, CRLF; an unknown step text is a parse error with file:line); the target parses the whole tree. The value notation `harness/values.rs` (`parse_value` -> `TckValue`, parameters via `to_element_property`; a test parses every result cell and parameter value of the tree) and the comparison `harness/compare.rs` (`materialize` rows of `gql()` through `GraphStorage`, then `compare_result`: column names in order, ordered / multiset rows, list order only where stated, elements by labels + properties, paths by the edges' ends, integer vs float distinct, floats within 1 ulp, `NaN` = `NaN`). The runner, baseline and report are being built (3b.T4-T5).
- `features/`, `graphs/`, `LICENSE` and the upstream part of `NOTICE` are vendored verbatim at tag `2024.3` (commit `677cbafabb8c3c5eed458fd3b1ec0daec8d67d23`): never edit them; a change comes only from an upgrade (`README.md`, "Upgrade procedure"). Nine feature files use CRLF upstream and stay byte-identical (`.gitattributes` `-text`), so the parser accepts both line endings. Copy data files only from an upstream clone; never run anything from it.
- **Attribution Notice (licence requirement):** never describe Graphersal or its GQL as "Cypher", "a Cypher implementation" or "openCypher" in any artifact (code, comments, book, reports, commit messages, release notes). Say "measured against the openCypher TCK" and "Cypher compatibility forms". Cypher® is a registered trademark of Neo4j Inc.
- **Principle W43 (user decision):** an unimplemented construct is fine (class `missing`, the backlog); a supported construct follows the TCK (Neo4j Cypher 25 semantics) unless a user decision says otherwise. **"Wrong behaviour of supported constructs"** (`wrong_result`, `wrong_columns`, `wrong_side_effects`, `wrong_error`, `unexpected_error`, `timeout`, `panic`) is driven to 0: fix the engine, or exclude the case with a user decision and a reason (documented in the book's "differences from Neo4j"). Errors match by type and phase only; detail text is not chased.
- Scope: exclusions are an explicit reviewed table of scenario ids grouped by reason (`harness/scope.rs`; ids only, never tags or content). Merely unimplemented constructs (temporal types, `shortestPath`, `FOREACH`, ...) are never excluded. Live numbers live only in the generated page blocks and the report; never repeat counts elsewhere.
- The page's generated blocks (`<!-- opencypher:begin NAME -->` .. `end`) are compared on every run (fails on drift); `OPENCYPHER_UPDATE_BASELINE=1` rewrites them with the baseline (root rules 16, 19, 23 apply in the same way as for TinkerPop).
- Setup queries (`having executed`, named graphs) run through Graphersal's own GQL writes; a setup that fails is class `setup` (Unsupported), never wrong behaviour.
