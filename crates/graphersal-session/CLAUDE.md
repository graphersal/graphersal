# graphersal-session

Agent guidance. The playground session logic, JSON in, JSON out, shared by `graphersal-wasm` and the dev server so both answer with the same structures (the server's `/api/store*` endpoints are thin wrappers). Publishable (the CLI depends on it) but internal, no stability guarantees; denies `missing_docs`. Not packaged.

## Modules

- execute, schema methods, views. The Graph panel's drawing is the columnar `display::CompactGraph`; properties come per clicked element from `Session::element`. `views::completion_entries`/`token_values` are the function catalogue (REPL, playground completion, generated book step reference).
- `layout.rs`: the Graph panel's force layout (ForceAtlas2-style, Barnes-Hut quadtree, no dependency, deterministic from a seed), run in slices with a time budget and the session's cancel token; jobs and a cache of finished layouts keyed by the drawn topology; `Session::layout_start/step/cancel/positions`.
- `Session::statistics()` = `{statistics, memory, process, limits}`; `process` (`Session::process_memory`) is the memory beside the graph (the active store's LOADED models: the size measured at the load, the `embedding_model` component when `exact` (`measured: true`, user decision 2026-11-04), else `ModelInfo::shown_bytes()`; never the definition's `load_bytes`); store JSON `model_value` adds `memoryBytes` and `sizeText` (`model_size_text`: "X in memory" when loaded, else the size on disk; the playground Store menu shows it), never part of `GraphStatistics`; the session's engine gets the served graph through `script::set_engine_graph` on every run (no presets embedders since 0.5.0: the graph's database serves its models); store JSON `modelsNote` / `store_models().note` (`store::models_note`: models but none the default); the dev server adds `process.aiChat`. `process.memory` (`process.rs`: `liveHeapBytes` from `alloc_tracking::global_live_bytes` (0 = not installed, omitted), Linux `/proc/self/status` RSS/peak, macOS `ps` RSS with a process-wide max as peak, wasm32 `wasmMemoryBytes`; all optional, no failure; plus the ceiling bar `MemoryBar` (`memory_bar(graph_memory, models_bytes)` / `memory_bar_with(.., components)` over `exec::memory_room`; with the process's components (`AnyGraph::process_memory_components`, no report walk) the segments `live_graph` (`store_graph`), `store` (`store` + `store_files`) and `engine` (workload bytes + every other component) join, `models` = the `embedding_model` components, each segment's `parts` listed: `usedBytes`/`usedTracked`/`limitBytes?`/`limitSource`/`usedPercent?`/`segments`/`compression?`/`estimateAboveHeap?`, `limitError` instead on failure; the segment formulas live ONLY here, the playground's `js/memory-bar.js` renders them, `MemoryBar::text` is the REPL's `/memory` bar; the dev server's banner reads the JSON keys) is volatile, so `Session::statistics()` stays deterministic (tests compare two reads) and the hosts (`graphersal-wasm`, the dev server's statistics routes, MCP and banner) call `Session::statistics_with_process` (= `statistics` + `process::add_to_statistics_with` the components; `add_to_statistics` without them stays for callers without a graph).
- `jobs.rs`: the scheduled jobs of the ACTIVE store (`SessionJobs`: one `Scheduler` rebuilt when the active store changes, from `SessionStore::system_jobs`, recording into `workload_stats`; its user jobs synced from `SessionStore::user_jobs` whenever the graph's `job` definitions differ from the ones last synced); `Session::set_time_zone`, `tick_jobs(now µs)` (runs them here: playground worker timer), the two phases `start_due_jobs`/`start_job_now` + `finish_job_run` (dev server; the schedulers of stores left with runs out are `SessionJobs::parked`, found again on the way back, so no overlap; `running_user_job` makes `store_checkpoint/rollback/attic_restore/attic_remove/compact/backup/close` answer 409 while a user's job runs: `refuse_while_job_runs`, a new store operation that moves or writes files adds it); the job API (module docs = the JSON forms): `jobs_view()` (system jobs then the catalog's user jobs, with `scheduled`/`reason`, `runs` from the workload report, a system job's `setting`), `define_job` (spec -> field checks -> `g.define_job(#{..})` run with the playground authorizer, no files; `define_job_with_authorizer` for the dev server; remaining engine errors mapped to a field by `define_error`), `drop_job`, `set_job_enabled` (user job: catalog definition rewritten, effects kept; system job: `WorkloadStats::set_job_override`), `set_job_schedule` (system jobs only), `run_job_now`, `job_history(name, tier)`; `workload_report()` (the served graph's `WorkloadReport::to_property` as JSON, level `off` without statistics). Workload channels: `execute_with_cancel` runs in `workload::scope(current_channel(), false)`, so a host marks the session's other work technical (wasm: thread default `(playground, technical)`; dev server: per request) and only user queries count.
- `advisor.rs`: the storage advisor (`advise(spec)`, spec = thresholds or `everything`; `apply_recommendation(id, spec)` recomputes, finds the id and runs the session's own `create_index`/`drop_index`/`define_compression`/`drop_compression`, then records `AppliedAdvice` in the store's stats; `apply_recommendations(ids, spec)` (stage V1b) = `AnyGraph::apply_recommendations` (core `Graph::apply_recommendations`: one unit, one walk, records each, all or nothing; an id not advised -> "not advised any more"); `dismiss_recommendation(id, days)`, `restore_recommendation(id)` need a store); module docs = the JSON forms.
- `filter.rs`: the Graph panel filter (`{vertices?, edges?: {label: [{key, op, value?}]}, hiddenVertices?, hiddenEdges?: [label], otherVertices?, otherEdges?: "visible"|"hidden", hideIsolated?}`; `other*` defaults to `"hidden"` with a map (the allow list) and `"visible"` without; the playground sends the "others visible" form, which is evaluated by ONE scan of the elements against the hidden set and the passing sets of the conditioned labels, never enumerating the graph's labels), evaluated by read-only engine traversals per conditioned label over `&S` (allow-list labels without conditions from the label index; values of declared keys coerced by `GraphSchema::coerce_value`), applied before the limits in `views::graph_view_request` (`matchedNodes`/`matchedEdges`; no filter = exactly `graph_view`) and as a display filter after `selection::neighbourhood` (adds `unfiltered: {nodes, edges, vertexIds}`; `hiddenEdges` then counts only what the filter shows; the page keeps `unfiltered.vertexIds` for expansions and redraws); `filter_query` = the equivalent Rhai text (`.not(__.has_label(..))`, `.or(__.not(__.has_label(L)), __.has(..))`, more than `MAX_LABEL_ARGS` labels as `P.within([..])`; tests `tests/graph_filter.rs` compare both). `degrees: true` (graph view, neighbourhood, sample; `RunOptions::subgraph_degrees`) adds `vertexInDegree`/`vertexOutDegree` (`CompactGraph::add_degrees`, whole-graph adjacency counts).
- `selection.rs`: bounded, cancellable selections: `Session::neighbourhood` (centre, depth 1-5, direction, `keep` for an expansion, `leftOut` when cut), `label_sample`, `meta_graph`. The result subgraph limit is `RunOptions::subgraph_max_elements`.
- load/save; `queries.rs` saved queries (list with `writes`/`effects`/`denied_writes`/`language`/`dialect`, get, define/replace with field errors and the inferred dialect, spec `language` `rhai`|`gql` (GQL params kept in the editor's order), drop, move, call text, `preview_query` = dry run of a call with change counts; the catalog file `save_catalog_text`/`load_catalog` holds every kind; a GraphML/GraphSON load keeps the catalog); `compression.rs` (list with stats, define/replace with field errors, drop, recompress, the read-only `estimate_compression` with field errors); `indexes.rs` (list with stats, create with field errors (`label` absent or null: a label-less index, kind `property_index_ext`), drop over both index kinds); `store.rs` the Store menu's operations with a registry of databases (the menu loads in two calls: `store_summary` = `store_info` without `STORE_DETAIL_KEYS`, `detailsPending: true`, over `Store::quick_info` (no WAL, attic WAL, blob or graph read; test `tests/store_menu_reads.rs` counts the bytes read), then `store_details` (compaction advice, store size, graph footprint via `AnyGraph::memory_footprint_bytes`, cached per commit); `store_info` = both, what the actions answer; `tests/store_info_timing.rs` is the ignored timing harness; store models: `store_value` `models`/`missingModels`, `store_models`, `store_snapshot_with(commit, ModelCopy)`; `load_snapshot` keeps a `.gsnap`'s models in the memory store via `SessionStore::import_models_from_packed`).
- Helpers are generic over `S: GraphStorage` (`views`, `display`, `selection`, `edit`'s `element_view`, `create`'s `label_choices_in`/`drawn_in`/`delete_in`, `queries`' `*_in`/`catalog_text`, `compression`'s and `indexes`' `*_in`: trait read API, `Transactional::dry_run`/`transaction`), tested against `Forwarding` of `graphersal-storage-tests` (dev-dependency). A compression entry's `stats` is `null` where the storage reports none; `recompress` there is `Unsupported`.

- Every value the session serializes goes through `display::json_safe`/`values_json`/`json_safe_map` (results, Table cells via `table_cell`, the JSON tab, the inspector, schema/param values): a non-finite float becomes `{"@type": "g:Double", "@value": "NaN"}` (the plain serde of a value refuses it); display logic keeps working on the raw values (playground `js/util.js` `isNonFiniteCell`).

## Errors (`error.rs`)

`SessionError` (`#[non_exhaustive]`: `Graph(Box<GraphError>)`, `Persist(Box<PersistError>)`, `Invalid(String)` a request it cannot serve, `Failed(String)` an engine diagnostic; `Display` = the text the front ends show (deliberately not `Serialize`, so a `Result` can never be put into a JSON answer by mistake), `From<String>` = `Failed`) is the error of every public method that does not answer in-band JSON; every method that reads the graph or a store returns a `Result` (the `SessionGraph` reads `GraphError`, the `SessionStore` ones `PersistError`), never an empty answer. The JSON wire methods keep `{ok, error}` and put these errors there. `StoreError` is `#[non_exhaustive]` (constructors `new`/`bad_request`/`conflict`/`refused`/`internal`, `From` the session's and the engine's errors). `Session::write_refusal` turns a failing `read_only_reason` into a refusal.

## Any storage (`storage.rs`)

The graph is an `Arc<dyn SessionGraph>` (`AnyGraph` by upcasting + one method per view/selection/edit/create/queries/compression/index/run-unit operation, blanket for `Graph<S>`, each calling the generic helper), stores are `Arc<dyn SessionStore>` (blanket for `Store<S>`). Every graph it builds (samples and GraphML/GraphSON loads read into a `TraversalGraph` then `GraphFactory::adopt`ed; `.gsnap`; memory stores; forks) comes from the host's `GraphFactory`: `Session::with_storage(Arc::new(StorageKind::<S>::persistent()))` (lossless copy through the load sink in source order, `.gsnap`, stores) or `StorageKind::<S>::new()` (copy through the write API; no `.gsnap`, no stores, the Store menu says so). `Session::new()` = `TraversalGraph` (nothing copied), used by wasm, the dev server and MCP. `load_shared` takes any `IntoSessionGraph`. Tests over `Forwarding` and a `NoCompression` wrapper: `storage/tests.rs`; host example `tests/custom_storage_example.rs` (included in the book by anchors).

Several sessions over one graph (the dev server's read-only serving mode): `Session::template()` -> `SessionTemplate` (`Send + Sync`: graph `Arc`, factory, name/kind, presets, warnings, the SAME `layouts` and memory source, `read_only_runs`) and `SessionTemplate::session()` on each worker thread (own engine and cancel token; no stores, no jobs; the memory source is not registered again). `Session::set_read_only_runs(true)`: `execute_in_scope` opens no whole-run unit (`begin_run` holds the graph's lock upgradable, one thread at a time, which would serialize the sessions); only for a graph that refuses every write (each traversal stays its own unit). `Session::set_layout_job_limit(n)` / `LayoutJobs::set_limit` (default 4) for shared layout jobs. Cancellation from a host that queues work (the dev server): a token per run, `execute_with_cancel` (a token already cancelled runs nothing and answers "cancelled") and `layout_start_with_cancel`/`layout_step_with_cancel`; the session's own `cancel_token` is reset by every operation (`reset_cancel`), so a cancel before the run starts is lost there. Tests `tests/session_template.rs`.

Memory report: every `Session` registers a `SessionMemory` source (`session`: its layout jobs and cached layouts, `layouts` is an `Arc<Mutex<LayoutJobs>>` for it, read with `try_lock`); the graph, Stores and the script engine report themselves (`graph/CLAUDE.md`).
