# graphersal-session

Agent guidance. The playground session logic, JSON in, JSON out, shared by `graphersal-wasm` and the dev server so both answer with the same structures (the server's `/api/store*` endpoints are thin wrappers). Publishable (the CLI depends on it) but internal, no stability guarantees; denies `missing_docs`. Not packaged.

## Modules

- execute, schema methods, views. The Graph panel's drawing is the columnar `display::CompactGraph`; properties come per clicked element from `Session::element`. `views::completion_entries`/`token_values` are the function catalogue (REPL, playground completion, generated book step reference).
- `layout.rs`: the Graph panel's force layout (ForceAtlas2-style, Barnes-Hut quadtree, no dependency, deterministic from a seed), run in slices with a time budget and the session's cancel token; jobs and a cache of finished layouts keyed by the drawn topology; `Session::layout_start/step/cancel/positions`.
- `Session::statistics()` = `{statistics, memory, process, limits}`; `process` (`Session::process_memory`) is the memory beside the graph (embedder `memory_bytes()`), never part of `GraphStatistics`; the dev server adds `process.aiChat`. `process.memory` (`process.rs`: `liveHeapBytes` from `alloc_tracking::global_live_bytes` (0 = not installed, omitted), Linux `/proc/self/status` RSS/peak, macOS `ps` RSS with a process-wide max as peak, wasm32 `wasmMemoryBytes`; all optional, no failure) is volatile, so `Session::statistics()` stays deterministic (tests compare two reads) and the hosts (`graphersal-wasm`, the dev server's `with_process_memory`) call `process::add_to_statistics`.
- `jobs.rs`: the scheduled jobs of the ACTIVE store (`SessionJobs`: one `Scheduler` rebuilt when the active store changes, from `SessionStore::system_jobs`, recording into `workload_stats`; its user jobs synced from `SessionStore::user_jobs` whenever the graph's `job` definitions differ from the ones last synced); `Session::set_time_zone`, `tick_jobs(now µs)` (the host ticks: dev server thread, playground worker timer); the job API (module docs = the JSON forms): `jobs_view()` (system jobs then the catalog's user jobs, with `scheduled`/`reason`, `runs` from the workload report, a system job's `setting`), `define_job` (spec -> field checks -> `g.define_job(#{..})` run with the playground authorizer, no files; `define_job_with_authorizer` for the dev server; remaining engine errors mapped to a field by `define_error`), `drop_job`, `set_job_enabled` (user job: catalog definition rewritten, effects kept; system job: `WorkloadStats::set_job_override`), `set_job_schedule` (system jobs only), `run_job_now`, `job_history(name, tier)`; `workload_report()` (the served graph's `WorkloadReport::to_property` as JSON, level `off` without statistics). Workload channels: `execute_with_cancel` runs in `workload::scope(current_channel(), false)`, so a host marks the session's other work technical (wasm: thread default `(playground, technical)`; dev server: per request) and only user queries count.
- `filter.rs`: the Graph panel filter (`{vertices?, edges?: {label: [{key, op, value?}]}, hiddenVertices?, hiddenEdges?: [label], otherVertices?, otherEdges?: "visible"|"hidden", hideIsolated?}`; `other*` defaults to `"hidden"` with a map (the allow list) and `"visible"` without; the playground sends the "others visible" form, which is evaluated by ONE scan of the elements against the hidden set and the passing sets of the conditioned labels, never enumerating the graph's labels), evaluated by read-only engine traversals per conditioned label over `&S` (allow-list labels without conditions from the label index; values of declared keys coerced by `GraphSchema::coerce_value`), applied before the limits in `views::graph_view_request` (`matchedNodes`/`matchedEdges`; no filter = exactly `graph_view`) and as a display filter after `selection::neighbourhood` (adds `unfiltered: {nodes, edges, vertexIds}`; `hiddenEdges` then counts only what the filter shows; the page keeps `unfiltered.vertexIds` for expansions and redraws); `filter_query` = the equivalent Rhai text (`.not(__.has_label(..))`, `.or(__.not(__.has_label(L)), __.has(..))`, more than `MAX_LABEL_ARGS` labels as `P.within([..])`; tests `tests/graph_filter.rs` compare both). `degrees: true` (graph view, neighbourhood, sample; `RunOptions::subgraph_degrees`) adds `vertexInDegree`/`vertexOutDegree` (`CompactGraph::add_degrees`, whole-graph adjacency counts).
- `selection.rs`: bounded, cancellable selections: `Session::neighbourhood` (centre, depth 1-5, direction, `keep` for an expansion, `leftOut` when cut), `label_sample`, `meta_graph`. The result subgraph limit is `RunOptions::subgraph_max_elements`.
- load/save; `queries.rs` saved queries (list with `writes`/`effects`/`denied_writes`/`language`/`dialect`, get, define/replace with field errors and the inferred dialect, spec `language` `rhai`|`gql` (GQL params kept in the editor's order), drop, move, call text, `preview_query` = dry run of a call with change counts; the catalog file `save_catalog_text`/`load_catalog` holds every kind; a GraphML/GraphSON load keeps the catalog); `compression.rs` (list with stats, define/replace with field errors, drop, recompress, the read-only `estimate_compression` with field errors); `indexes.rs` (list with stats, create with field errors, drop); `store.rs` the Store menu's operations with a registry of databases.
- Helpers are generic over `S: GraphStorage` (`views`, `display`, `selection`, `edit`'s `element_view`, `create`'s `label_choices_in`/`drawn_in`/`delete_in`, `queries`' `*_in`/`catalog_text`, `compression`'s and `indexes`' `*_in`: trait read API, `Transactional::dry_run`/`transaction`), tested against `Forwarding` of `graphersal-storage-tests` (dev-dependency). A compression entry's `stats` is `null` where the storage reports none; `recompress` there is `Unsupported`.

- Every value the session serializes goes through `display::json_safe`/`values_json`/`json_safe_map` (results, Table cells via `table_cell`, the JSON tab, the inspector, schema/param values): a non-finite float becomes `{"@type": "g:Double", "@value": "NaN"}` (the plain serde of a value refuses it); display logic keeps working on the raw values (playground `js/util.js` `isNonFiniteCell`).

## Any storage (`storage.rs`)

The graph is an `Arc<dyn SessionGraph>` (`AnyGraph` by upcasting + one method per view/selection/edit/create/queries/compression/index/run-unit operation, blanket for `Graph<S>`, each calling the generic helper), stores are `Arc<dyn SessionStore>` (blanket for `Store<S>`). Every graph it builds (samples and GraphML/GraphSON loads read into a `TraversalGraph` then `GraphFactory::adopt`ed; `.gsnap`; memory stores; forks) comes from the host's `GraphFactory`: `Session::with_storage(Arc::new(StorageKind::<S>::persistent()))` (lossless copy through the load sink in source order, `.gsnap`, stores) or `StorageKind::<S>::new()` (copy through the write API; no `.gsnap`, no stores, the Store menu says so). `Session::new()` = `TraversalGraph` (nothing copied), used by wasm, the dev server and MCP. `load_shared` takes any `IntoSessionGraph`. Tests over `Forwarding` and a `NoCompression` wrapper: `storage/tests.rs`; host example `tests/custom_storage_example.rs` (included in the book by anchors).

## Book tests that live here

`book_playground_examples` runs every `rhai,graph=<sample>` block of the book; `book_step_reference` generates the step reference (see `book/CLAUDE.md`).
