# graphersal-serve

Agent guidance for the hosting core of the dev server: ONE graph, no HTTP library. Publishable, internal, EXPERIMENTAL like `graphersal-session` (`#![warn(missing_docs)]`, no stability promise; Apache-2.0 via the workspace; native only, never wasm32). Not packaged (`include` lists the packaged files). Today's only host is `graphersal --server` (`crates/graphersal-cli/CLAUDE.md`, "Dev server"); the dev server's behaviour (answers, status codes, headers, MCP) is this crate's contract, tested end to end by `crates/graphersal-cli/tests/server_tests.rs`.

**Crate role (user decision 2026-11-09):** a MINIMAL core with extension points, not a server. Never add here: several databases in one process, run administration (list/kill of other clients' runs, issue #32), authentication, quotas, bounded queues or fairness beyond what exists, an HTTP library. Those belong to graphersal-memory / a future graphersal-server (design `ai/roadmap/memory-daemon.md` sections 6-6.4; plan `ai/serve-mcp/PLAN.md`).

## Extension points

Each point has a core default (what a host gets without it); the crate docs (`lib.rs`) hold the same table, each item's rustdoc explains its point. A new point needs a user decision; never grow a point into the functionality it exists to keep out (a registry of graphs, an admin list/kill endpoint, authentication).

| Point | Core default | Items | CLI dev server |
|---|---|---|---|
| Graph resolver: which context serves a request / MCP connection | one graph | `GraphResolver`, `Server::ready_with`; `OneGraph`, `Server::ready` | default (`Server::ready`) |
| Run observer + cancel handle: every run's start/end (client key, alias, `RunKind` Query/Layout/Tool/Other, text head `RUN_TEXT_HEAD_CHARS`, identity, start time, duration) with a `RunHandle` that cancels it | none | `RunObserver`, `Runs::with_observer`, `RunInfo`, `RunHandle` | none |
| Request filter: sees each request the checks accepted, before routing (after the lifecycle answers), refuses it or attaches an identity (`Request::set_identity`) | none beyond the context's `HostCheck` (`HostCheck::check`: loopback/Host/Origin), which ALWAYS runs first and cannot be replaced or skipped by a filter (user decision 2026-11-09; a relaying host forwards the original `Host` or configures its own `HostRules`) | `RequestFilter`, `ContextBuilder::filter` | none |
| Extra routes: `/api/` endpoints the core does not answer | `404 unknown endpoint` | `Hooks::route` (+ `add_info`, `add_process_statistics`), `ContextBuilder::hooks` | `CliHooks`: AI Chat `/api/ai/conversations*`, `ai`/`embedders`/`modelsNote`, `process.models`/`process.aiChat` |
| Activity / lifecycle hooks: ready, stopping, activity | none | `LifecycleHooks`, `Server::with_hooks`, `Server::idle_for` (probes and 503s are no activity) | none (the CLI only calls `ready`/`stop`) |
| Executor policy: how jobs reach the session | one session thread, unbounded queue (`Runner::Session`) | `Runner::Queue(Arc<dyn JobQueue>)`, `JobQueue::{submit, status, scheduled_jobs_refusal}` (default text `SCHEDULED_JOBS_REFUSAL`), `Busy`/`BusyReason`, `spawn_session`'s `takeover` | reader pool of `--server --read-only` (`impl JobQueue for Pool`, refusal text `NOT_SERVING`) |

Lifecycle (user decision S1b-2): `Server` exists before the graph (created by the host, loading) and answers in `Server::handle`: `GET`/`HEAD /healthz` 200 `{"status":"ok"}`, `/readyz` 200 ready / 503 loading / 503 stopping (stop wins; other methods 405), all before the resolver and the filter, no lock, no session, trace log only; then 503 "still loading" without a resolver (also after a stop: the old order), 503 "the server is stopping" after `stop()`; then the resolver's context through `handle`. `Server::probe(method, url)` answers the probes alone (the CLI's connection cap). The listener, bind, accept loop, conversion, `--max-connections`, signals and banner stay in the host. `ContextBuilder::memory_tracked` (default false; the CLI true) is `GET /api/info` `memoryTracked`.

Host-specific texts still in the core (pinned by tests or by `server_tests.rs`, kept byte-identical): the CLI flag names in the 403 of `HostCheck::unknown_host_message` (`--allowed-host`, `--host`), `the MCP endpoint is off: start the server with --mcp`, `(--graph <file>)` of `POST /api/save`, `--schema FILE` of the save warning, `(--ui-dir)` of `Ui::resolve`.

## Layout

- `lib.rs`: crate docs and the whole public surface (`pub use` list).
- `http.rs`: the boundary types `Method` (case-sensitive `parse`, `Other(name)`), `Request` (method, request target, headers, declared body length, body reader; `text_body`/`json_body`: `Content-Type: application/json` or 415, `MAX_BODY_BYTES` 16 MiB or 413 both declared and read), `Response` (status, ordered headers, body; `text`/`json` add `Content-Type`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`), `HttpError` (status + message, answered `{"error"}`; private tuple fields inside the crate, `new`/`bad_request` outside).
- `server.rs`: `Server` (lifecycle, probes, resolver, activity), `Lifecycle`, `GraphResolver`/`OneGraph`, `LifecycleHooks`.
- `api/mod.rs`: `handle` (sets the thread's client from `X-Graphersal-Client`, `mcp` for `/mcp`; runs the context's `HostCheck::check`, then its request filter if any, and puts the identity on the client; failures through `error_response`: a 503 gets `Retry-After: 1`) and `route` (`/mcp`, `/openapi.json`, static files, `/api/*`; unknown `/api/` endpoints go to `Hooks::route`, else 404), `info`/`changes`, save to file, query helpers, static files. `api/store.rs` `/api/store*`, `api/layout.rs` `/api/layout*`. **Route arms stay one per line as `(Method::Get, "endpoint")`**: the CLI's `server_tests.rs` `the_openapi_description_matches_the_router` reads the routes from these two files and checks them against `openapi.json` (this crate's root); a new or changed endpoint updates `openapi.json`.
- `context.rs`: `Context` (built by `Context::builder(Runner, HostCheck)`: runs, UI, source/schema files, presets, read-only, Store, commit position, MCP, hooks, filter, memory_tracked), `RequestFilter`, `Context::call` (the job queue + change feed + workload channel), `call_fallible` (422), `spawn_session` (the session thread: 64 MiB stack, `(playground, technical)` thread default, setup closure, optional `takeover` for a host queue's first worker, panics caught and logged through `tracing`), `start_job_ticker` (5 s), `Runner` (`Session(Sender<Job>)` | `Queue(Arc<dyn JobQueue>)`), `JobQueue` + `Busy`/`BusyReason` (a queue context answers jobs/* 409 `scheduled_jobs_refusal` and adds `serving` to `/api/info`), `Hooks`, `ServeError`, the change feed and the thread-local client (`Client`: name, detail, key, identity).
- `runs.rs`: the run registry (one `CancelToken` per run, registered before the job is queued; cancel by alias, by client, all) and its observer point (`RunObserver`, called outside the lock; `Context::register_run(alias, token, kind, text)` for execute/layout, `Host::run_started_with_text` for MCP/AI Chat tool runs; the public `start`/`register` register `RunKind::Other`).
- `job_workers.rs`: one worker thread per job group for the scheduled jobs (issue #26).
- `host_check.rs`: `Exposure`, `HostRules` (borrowed rules: loopback exact names + port; network any port, IP/localhost/dotless/`--host` name; allowed names on any port, `http(s)` origins) and `HostCheck` (owned, with port and URL; the 403 texts). Where to listen stays the host's (CLI `bind.rs`).
- `ui.rs`: `Ui` (a UI directory over the embedded copy; traversal refused); embedded table from `build.rs` (feature `ui-assets`; reads `../../playground` in a checkout, else `ui/`: a git-ignored copy that `prepare-package.sh` makes before `cargo package`/`publish`; entries `index.html`, `css/`, `js/`, `assets/`, `reset/` = `include` = the script's list; no symlinks in the repository, user decision 2026-11-09); its test (with the feature) fails when the embedded set differs from `playground/`.
- `mcp.rs`: `POST /mcp`, `/api/mcp/stats`, `impl Executor/Host for Context`, `current_client` (feature `mcp`; without it the endpoint answers 404 and `Mcp` is an empty enum).

## Rules

- No HTTP library, no async runtime (`cargo tree -p graphersal-serve` must show no `tiny_http`/`hyper`/`ureq`/`tokio`). The host converts its requests: keep the boundary types small and owned by this crate.
- Behaviour moves here unchanged: texts of errors (incl. the CLI flag names they mention), status codes, headers. A change shows in the CLI's `server_tests.rs`.
- Logging through `tracing` only (target `graphersal::server`); the host owns stdout/stderr.
- Tests: `src/api/boundary_tests.rs` (routing, body limit, Host/Origin, cancel, hooks, a refusing queue, MCP through the boundary; a real session thread on the `modern` sample, no HTTP), `src/extension_tests.rs` (one test per extension point: two graphs behind a resolver, observer + cancel handle incl. MCP tool runs, a token filter with identity, extra routes, lifecycle probes/503s/hooks/idle, a host queue with takeover), plus the moved unit tests of `runs.rs`, `ui.rs`, `api/store.rs`, `api/mod.rs`. Run `cargo test -p graphersal-serve --all-features` (without features the UI and MCP tests are skipped).
