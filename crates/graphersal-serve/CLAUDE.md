# graphersal-serve

Agent guidance for the hosting core of the dev server: ONE graph, no HTTP library. Publishable, internal, EXPERIMENTAL like `graphersal-session` (`#![warn(missing_docs)]`, no stability promise; Apache-2.0 via the workspace; native only, never wasm32). Not packaged (`include` lists the packaged files). Today's only host is `graphersal --server` (`crates/graphersal-cli/CLAUDE.md`, "Dev server"); the dev server's behaviour (answers, status codes, headers, MCP) is this crate's contract, tested end to end by `crates/graphersal-cli/tests/server_tests.rs`.

**Crate role (user decision 2026-11-09):** a MINIMAL core with extension points, not a server. Never add here: several databases in one process, run administration (list/kill of other clients' runs, issue #32), authentication, quotas, bounded queues or fairness beyond what exists, an HTTP library. The launch and open helpers (`launch.rs`, `open.rs`) start or open ONE graph per call for such a host; the registry of databases, their names and states stay in the host. Those belong to graphersal-memory / a future graphersal-server (design `ai/roadmap/memory-daemon.md` sections 6-6.4; plan `ai/serve-mcp/PLAN.md`).

## Extension points

Each point has a core default (what a host gets without it); the crate docs (`lib.rs`) hold the same table, each item's rustdoc explains its point. A new point needs a user decision; never grow a point into the functionality it exists to keep out (a registry of graphs, an admin list/kill endpoint, authentication).

| Point | Core default | Items | CLI dev server |
|---|---|---|---|
| Graph resolver: which context serves a request / MCP connection | one graph | `GraphResolver`, `Server::ready_with`; `OneGraph`, `Server::ready`; MCP over several graphs: one `Arc<Mcp>` in each context (`ContextBuilder::shared_mcp`), a profile per context (`ContextBuilder::mcp_profile`, default the endpoint's; `Context::mcp_profile`), `Context::mcp_connection` for a stream the host routed itself (`Result<Connection, ServeError>`, `ServeError::NoMcp` without an endpoint) | default (`Server::ready`; `ContextBuilder::mcp`, the endpoint's own profile) |
| Run observer + cancel handle: every run's start/end (client key, alias, `RunKind` Query/Layout/Tool/Other, text head `RUN_TEXT_HEAD_CHARS`, identity, start time, duration) with a `RunHandle` that cancels it | none | `RunObserver`, `Runs::with_observer`, `RunInfo`, `RunHandle` | none |
| Request filter: sees each request the checks accepted, before routing (after the lifecycle answers), refuses it or attaches an identity (`Request::set_identity`) | none beyond the context's `HostCheck` (`HostCheck::check`: loopback/Host/Origin), which ALWAYS runs first and cannot be replaced or skipped by a filter (user decision 2026-11-09; a relaying host forwards the original `Host` or configures its own `HostRules`) | `RequestFilter`, `ContextBuilder::filter` | none |
| Extra routes: `/api/` endpoints the core does not answer | `404 unknown endpoint` | `Hooks::route` (+ `add_info`, `add_process_statistics`), `ContextBuilder::hooks` | `CliHooks`: AI Chat `/api/ai/conversations*`, `ai`/`embedders`/`modelsNote`, `process.models`/`process.aiChat` |
| Activity / lifecycle hooks: ready, stopping, activity, background work | none | `LifecycleHooks`, `Server::with_hooks`, `Server::idle_for` (probes and 503s are no activity); `Context::background_runs` (`Result<usize, ServeError>`: scheduled-job runs handed to the job workers, queued or running, until each result is back in the session; per context) | none (the CLI only calls `ready`/`stop`) |
| Allow-list mode of the HTTP API (user decision 2026-11-13, stage E3): the context answers only `GET /api/info` (`apiMode: "allow-list"`), `GET /api/changes` and `POST /api/query` for the selected saved queries, under the host's access policy | every endpoint; `POST /api/query` runs any saved query under the playground's authorizer | `ContextBuilder::api_allow_list(SavedQuerySelection, AccessPolicy)` (selection: `graphersal_session::queries::SavedQuerySelection`, policy: `graphersal::auth::AccessPolicy`, authorizer: `graphersal_session::authorizer_for(read_only, Some(&policy))`), `Context::is_allow_list`; every other `/api/` route (the host's extra routes too), `/api/openapi.json` and `/mcp` = 403 `<METHOD> <path> is not offered by this server: it answers only GET /api/info, GET /api/changes and POST /api/query (allow-list mode)`, an unselected or unknown saved query = 403 `the saved query "<name>" is not offered by this server`; static files and `/openapi.json` stay served; `HostCheck` and the request filter run first; `mcp` of info/changes is `null`; no bound params (decision 3.5B); `Context::mcp_connection` is not affected (a host-routed stream) | none (graphersal-memory's daemon relay is the consumer) |
| Executor policy: how jobs reach the session | one session thread, unbounded queue (`Runner::Session`) | `Runner::Queue(Arc<dyn JobQueue>)`, `JobQueue::{submit, status, scheduled_jobs_refusal}` (default text `SCHEDULED_JOBS_REFUSAL`), `Busy`/`BusyReason`, `spawn_session`'s `takeover` | reader pool of `--server --read-only` (`impl JobQueue for Pool`, refusal text `NOT_SERVING`) |

Lifecycle (user decision S1b-2): `Server` exists before the graph (created by the host, loading) and answers in `Server::handle`: `GET`/`HEAD /healthz` 200 `{"status":"ok"}`, `/readyz` 200 ready / 503 loading / 503 stopping (stop wins; other methods 405), all before the resolver and the filter, no lock, no session, trace log only; then 503 "still loading" without a resolver (also after a stop: the old order), 503 "the server is stopping" after `stop()`; then the resolver's context through `handle`. `Server::probe(method, url)` answers the probes alone (the CLI's connection cap). The listener, bind, accept loop, conversion, `--max-connections`, signals and banner stay in the host. `ContextBuilder::memory_tracked` (default false; the CLI true) is `GET /api/info` `memoryTracked`.

Host-specific texts still in the core (pinned by tests or by `server_tests.rs`, kept byte-identical): the CLI flag names in the 403 of `HostCheck::unknown_host_message` (`--allowed-host`, `--host`; a host replaces them with `HostCheck::with_hint(text)`: `unknown Host: <hint>`, and the cross-origin 403 gains ` (<hint>)`; default none = the CLI texts), `the MCP endpoint is off: start the server with --mcp`, `(--graph <file>)` of `POST /api/save`, `--schema FILE` of the save warning, `(--ui-dir)` of `Ui::resolve`.

## Mounting under a URL prefix (plan `ai/graphersal-server/PLAN.md` H3, decision Q3)

A host serving several graphs mounts each `Context` under `/db/<name>/`. The core does NOT route by prefix (no registry here, crate role): the HOST strips `/db/<name>` when it builds the `Request` (`/db/acme/api/info` -> `/api/info`, `/db/acme/` -> `/`), drops a client's own `X-Graphersal-Graph` and sets it to the name, and its `GraphResolver` picks the context by that header, like the reference resolver does for `/mcp/<name>` (`extension_tests::reference_resolver`). Name map, aliases, the 409 "not loaded" pre-check, the `/db/x` -> `/db/x/` redirect (the playground's URLs are relative: `index.html` has no root-absolute `src`/`href`, `http-engine.js` builds `api/` from `import.meta.url`), the landing page and `/api/admin/*` are the host's. The core adds only: `ContextBuilder::mount_path(Option<String>)` (normalised to `/a/b`, `""`/`/` = root; `Context::mount_path`) = `GET /api/info` `mountPath` + `openapi` `<mount>/openapi.json`, the MCP status `endpoint` `<mount>/mcp` (`mcp.rs` `endpoint_status` overrides `Mcp::status`'s `/mcp`; `/api/info` and `/api/changes`); without a mount every answer is byte-identical. One `HostCheck` per listener (Origin is path-independent) with the host's `with_hint`. Upload: `Request::copy_body_to(out, max)` streams the body into a host sink (64 KiB buffer; 413 `the body is larger than <max> bytes` on a declared length above `max` before reading, or when the read passes `max`, nothing beyond `max` written; 400 read failure, 500 sink failure); a refused request leaves its body unread, so the host's listener drains or closes it (the CLI's `tiny_http` adapter never answers a declared body above `MAX_DECLARED_BODY_BYTES` = 64 MiB). Tests `src/mount_tests.rs` (two contexts under `/db/a/` and `/db/b/` behind a header resolver: no cross-talk, `mountPath`, MCP endpoint and calls per mount, UI index/asset/reset per mount, Host/Origin 403 with the hint on both, the default texts, normalisation, `copy_body_to` above `MAX_BODY_BYTES`, declared/undeclared 413, failures).

## Rules

- No HTTP library, no async runtime (`cargo tree -p graphersal-serve` must show no `tiny_http`/`hyper`/`ureq`/`tokio`). The host converts its requests: keep the boundary types small and owned by this crate.
- Behaviour moves here unchanged: texts of errors (incl. the CLI flag names they mention), status codes, headers. A change shows in the CLI's `server_tests.rs`.
- Logging through `tracing` only (target `graphersal::server`); the host owns stdout/stderr.
- `serde_json::Value` in the public API is on purpose (`JobQueue::status`, `Hooks::add_info`/`add_process_statistics`, `ContextBuilder::presets`, `Request::json_body`, `Response::json`): a JSON-boundary crate like `graphersal-session`, an exception to root rule 8; the crate docs say so.
- No `unwrap` on a request path (root rule 1): store I/O failures (e.g. `api/store.rs` `is_single_file`, the backend's space usage) are `HttpError(500, ..)`.
- Tests (MCP, feature `mcp`, in `extension_tests.rs`): one endpoint over two graphs behind the resolver (shared statistics), two contexts over one session with two profiles (use = read-only policy, develop), `Context::mcp_connection` with an identity reaching the run observer, the request filter's identity reaching MCP runs. The reference multi-graph resolver (S5.3, module `extension_tests::reference_resolver`, book `for_developers/serving_layers.md`; test code only, D5: no pool or catalog in this crate): a `BaseRef`-keyed pool of `LayerBase`s (one `MemDir` store, three marks), a catalog (versions `<name>@<version>`, aliases, kept pins), the host's path rewrite `/mcp/<name>` -> `/mcp` + `X-Graphersal-Graph` (a client's copy dropped), contexts with `.layered(true)` + `.mcp_session_route` + one shared `Arc<Mcp>` + per-context profiles, the name check over `Mcp::verified_session_route`, alias flip / explicit pin / shared base / refusals / retirement (`retire_idle(grace)`, `evict_unused_bases`), each in table and signed mode.
- Tests: `src/api/boundary_tests.rs` (routing, body limit, Host/Origin, cancel, hooks, a refusing queue, MCP through the boundary; a real session thread on the `modern` sample, no HTTP), `src/extension_tests.rs` (one test per extension point: two graphs behind a resolver, observer + cancel handle incl. MCP tool runs, a token filter with identity, extra routes, lifecycle probes/503s/hooks/idle, a host queue with takeover), the job ticker's stop / detach and the context release, `background_runs`, the `ServeError` -> `HttpError` statuses, `src/read_only_tests.rs` (the runtime toggle: an open MCP session + a page refused/answered/allowed again, a write queued before the flip commits, the ticker pauses, initial read-only with the host's help, no toggle = `Unsupported`), `src/mount_tests.rs` (mounting and uploads, section "Mounting"), `src/directory_tests.rs` (feature `mcp`, H4: one `graphersal_mcp::Mcp::handle_directory` endpoint over two real contexts behind a test `GraphDirectory`: `host(route)` = the `Arc<Context>` as `Arc<dyn Host>` + `context.mcp_profile()`; select, write, `graph` override, alias flip, the runtime read-only toggle refusing a write, an unloaded graph's 409-style text), `src/launch_tests.rs` (one launch per `ServedSource` kind, a layer store over a store's base and over a given `LayerBase`, the open notes and refusals; `MemDir` stores, files in the temp dir), plus the moved unit tests of `runs.rs`, `ui.rs`, `api/store.rs`, `api/mod.rs`. Run `cargo test -p graphersal-serve --all-features` (without features the UI and MCP tests are skipped).
