# graphersal-serve

Agent guidance for the hosting core of the dev server: ONE graph, no HTTP library. Publishable, internal, EXPERIMENTAL like `graphersal-session` (`#![warn(missing_docs)]`, no stability promise; Apache-2.0 via the workspace; native only, never wasm32). Not packaged (`include` lists the packaged files). Today's only host is `graphersal --server` (`crates/graphersal-cli/CLAUDE.md`, "Dev server"); the dev server's behaviour (answers, status codes, headers, MCP) is this crate's contract, tested end to end by `crates/graphersal-cli/tests/server_tests.rs`.

**Crate role (user decision 2026-11-09):** a MINIMAL core with extension points, not a server. Never add here: several databases in one process, run administration (list/kill of other clients' runs, issue #32), authentication, quotas, bounded queues or fairness beyond what exists, an HTTP library. Those belong to graphersal-memory / a future graphersal-server (design `ai/roadmap/memory-daemon.md` sections 6-6.4; plan `ai/serve-mcp/PLAN.md`).

## Layout

- `lib.rs`: crate docs and the whole public surface (`pub use` list).
- `http.rs`: the boundary types `Method` (case-sensitive `parse`, `Other(name)`), `Request` (method, request target, headers, declared body length, body reader; `text_body`/`json_body`: `Content-Type: application/json` or 415, `MAX_BODY_BYTES` 16 MiB or 413 both declared and read), `Response` (status, ordered headers, body; `text`/`json` add `Content-Type`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`), `HttpError` (status + message, answered `{"error"}`; private tuple fields inside the crate, `new`/`bad_request` outside).
- `api/mod.rs`: `handle` (sets the thread's client from `X-Graphersal-Client`, `mcp` for `/mcp`; a 503 gets `Retry-After: 1`) and `route` (Host/Origin 403 first, then `/mcp`, `/openapi.json`, static files, `/api/*`; unknown `/api/` endpoints go to `Hooks::route`, else 404), `info`/`changes`, save to file, query helpers, static files. `api/store.rs` `/api/store*`, `api/layout.rs` `/api/layout*`. **Route arms stay one per line as `(Method::Get, "endpoint")`**: the CLI's `server_tests.rs` `the_openapi_description_matches_the_router` reads the routes from these two files and checks them against `openapi.json` (this crate's root); a new or changed endpoint updates `openapi.json`.
- `context.rs`: `Context` (built by `Context::builder(Runner, HostCheck)`: runs, UI, source/schema files, presets, read-only, Store, commit position, MCP, hooks), `Context::call` (the job queue + change feed + workload channel), `call_fallible` (422), `spawn_session` (the session thread: 64 MiB stack, `(playground, technical)` thread default, setup closure, optional `takeover` for a host queue's first worker, panics caught and logged through `tracing`), `start_job_ticker` (5 s), `Runner` (`Session(Sender<Job>)` | `Queue(Arc<dyn JobQueue>)`), `JobQueue` + `Busy`/`BusyReason` (the read-only serving mode's pool; a queue context answers jobs/* 409 and adds `serving` to `/api/info`), `Hooks` (S1a seam: `add_info`, `add_process_statistics`, `route`; S1b formalizes the extension points), `ServeError`, the change feed and the thread-local client.
- `runs.rs`: the run registry (one `CancelToken` per run, registered before the job is queued; cancel by alias, by client, all). Moved unchanged from the CLI with its tests.
- `job_workers.rs`: one worker thread per job group for the scheduled jobs (issue #26).
- `host_check.rs`: `Exposure`, `HostRules` (borrowed rules: loopback exact names + port; network any port, IP/localhost/dotless/`--host` name; allowed names on any port, `http(s)` origins) and `HostCheck` (owned, with port and URL; the 403 texts). Where to listen stays the host's (CLI `bind.rs`).
- `ui.rs`: `Ui` (a UI directory over the embedded copy; traversal refused); embedded table from `build.rs` (feature `ui-assets`; reads `../../playground` in a checkout, else `ui/`: a git-ignored copy that `prepare-package.sh` makes before `cargo package`/`publish`; entries `index.html`, `css/`, `js/`, `assets/`, `reset/` = `include` = the script's list; no symlinks in the repository, user decision 2026-11-09); its test (with the feature) fails when the embedded set differs from `playground/`.
- `mcp.rs`: `POST /mcp`, `/api/mcp/stats`, `impl Executor/Host for Context`, `current_client` (feature `mcp`; without it the endpoint answers 404 and `Mcp` is an empty enum).

## Rules

- No HTTP library, no async runtime (`cargo tree -p graphersal-serve` must show no `tiny_http`/`hyper`/`ureq`/`tokio`). The host converts its requests: keep the boundary types small and owned by this crate.
- Behaviour moves here unchanged: texts of errors (incl. the CLI flag names they mention), status codes, headers. A change shows in the CLI's `server_tests.rs`.
- Logging through `tracing` only (target `graphersal::server`); the host owns stdout/stderr.
- Tests: `src/api/boundary_tests.rs` (routing, body limit, Host/Origin, cancel, hooks, a refusing queue, MCP through the boundary; a real session thread on the `modern` sample, no HTTP), plus the moved unit tests of `runs.rs`, `ui.rs`, `api/store.rs`, `api/mod.rs`. Run `cargo test -p graphersal-serve --all-features` (without features the UI and MCP tests are skipped).
