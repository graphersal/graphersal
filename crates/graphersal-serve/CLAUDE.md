# graphersal-serve

Agent guidance for the hosting core of the dev server: ONE graph, no HTTP library. Publishable, internal, EXPERIMENTAL like `graphersal-session` (`#![warn(missing_docs)]`, no stability promise; Apache-2.0 via the workspace; native only, never wasm32). Not packaged (`include` lists the packaged files). Today's only host is `graphersal --server` (`crates/graphersal-cli/CLAUDE.md`, "Dev server"); the dev server's behaviour (answers, status codes, headers, MCP) is this crate's contract, tested end to end by `crates/graphersal-cli/tests/server_tests.rs`.

**Crate role (user decision 2026-11-09):** a MINIMAL core with extension points, not a server. Never add here: several databases in one process, authentication, quotas, bounded queues or fairness beyond what exists, an HTTP library. Exception: the run administration (list/kill of other clients' runs, issue #32) moved INTO this crate with task I32 (plan `ai/after-0.7.0/PLAN.md`), off by default, so every host (the CLI, graphersal-server per database) gets the same surface; section "Run administration". The launch and open helpers (`launch.rs`, `open.rs`) start or open ONE graph per call for such a host; the registry of databases, their names and states stay in the host. Those belong to graphersal-memory / a future graphersal-server (design `ai/roadmap/memory-daemon.md` sections 6-6.4; plan `ai/serve-mcp/PLAN.md`).

## Extension points

Each point has a core default (what a host gets without it); the crate docs (`lib.rs`) hold the same table, each item's rustdoc explains its point. A new point needs a user decision; never grow a point into the functionality it exists to keep out (a registry of graphs, authentication); the run administration is no extension point but a core surface (section "Run administration").

Lifecycle (user decision S1b-2): `Server` exists before the graph (created by the host, loading) and answers in `Server::handle`: `GET`/`HEAD /healthz` 200 `{"status":"ok"}`, `/readyz` 200 ready / 503 loading / 503 stopping (stop wins; other methods 405), all before the resolver and the filter, no lock, no session, trace log only; then 503 "still loading" without a resolver (also after a stop: the old order), 503 "the server is stopping" after `stop()`; then the resolver's context through `handle`. `Server::probe(method, url)` answers the probes alone (the CLI's connection cap). The listener, bind, accept loop, conversion, `--max-connections`, signals and banner stay in the host. `ContextBuilder::memory_tracked` (default false; the CLI true) is `GET /api/info` `memoryTracked`.

Host-specific texts still in the core (pinned by tests or by `server_tests.rs`, kept byte-identical): the CLI flag names in the 403 of `HostCheck::unknown_host_message` (`--allowed-host`, `--host`; a host replaces them with `HostCheck::with_hint(text)`: `unknown Host: <hint>`, and the cross-origin 403 gains ` (<hint>)`; default none = the CLI texts), `the MCP endpoint is off: start the server with --mcp`, `the run administration is off: start the server with --admin-runs`, `(--graph <file>)` of `POST /api/save`, `--schema FILE` of the save warning, `(--ui-dir)` of `Ui::resolve`.

## Per-request read-only (plan `ai/graphersal-server-access/PLAN.md` A3)

A host marks ONE request read-only (`Request::mark_read_only`, one-way; `is_read_only`), in its router or its request filter; the core never decides who gets it (no authentication here). `api::handle` copies the mark into the thread's `Client` (`read_only`, reset every request like `identity`; `context::request_read_only()` reads it, `false` on a thread without a request). On a marked request:
- `POST /api/execute` runs under `authorizer_for(true, None)` (= `read_only_authorizer`), `POST /api/query` under `authorizer_for(true, policy)` (allow-list: `fixed_read_only() || mark`); a write is the engine's `Permission denied` inside the 200 answer. Unmarked: `authorizer_for(false, None)` = `playground_authorizer()`, unchanged.
- Every route classified `Write` answers `409` `"{READ_ONLY_HEADLINE}. {READ_ONLY_REQUEST_HELP}"` (`Context::request_read_only_refusal`) in `route` BEFORE the match (so before the queue/toggle refusals and `own_store`). ONE table: `api/access.rs` `route_access(method, endpoint) -> Option<RouteAccess::{Read, Query, Write}>` (exact method; a wrong method stays 405, an unknown endpoint goes to the host's extra routes, which read `request.is_read_only()` themselves). `Write` = every commit route (schema/set|patch, element/update|create|delete, advise/apply, queries/define|drop|move, catalog/load, compression/define|drop|drop-many|recompress, indexes/create|drop), the non-commit writes (jobs/*, save, store/checkpoint|mark|rollback|attic/restore|attic/remove|compact), plus store/fork, store/attic/fork, store/backup (directories on the server), store/view, store/live (the shared session's view), advise/dismiss|restore (the workload sidecar), admin/runs/cancel (another client's run; provisional). Downloads (export incl. gsnap, store/snapshot), layout, store/verify, advise (POST) are `Read`. Its tests walk every `(Method::Get|Post, "..")` arm of `api/mod.rs`, `api/store.rs`, `api/admin.rs` and every endpoint of the two 405 arms: a new route must be added to the table. The runtime toggle's commit hook is NOT reused per request (graph-wide; registering it turns on change capture).
- `/mcp` (`mcp.rs` `route`): the context's profile `.with_read_only(true)` (graphersal-mcp `Profile::with_read_only`) for that request: reading tools only, a writing query refused; the same MCP session writes again on an unmarked request. `endpoint_status`, `/api/mcp/stats` and `graph_info` `mcpReadOnly` (`profile_read_only`) also say read-only for a marked request.
- `GET /api/info` and `GET /api/changes` `readOnly` = `is_read_only() || mark`.
- Unmarked requests (the CLI never marks) answer byte-identically. Tests `src/read_mark_tests.rs` (one context, a marked and an unmarked request per class: execute, saved query, commit routes, store/jobs routes, fork/backup/view on a store in the temp dir, advisor marks, info/changes, a request filter marking by header, MCP with one session) and `api/access.rs` unit tests.

## File root (plan `ai/graphersal-server-access/PLAN.md` A6)

`ContextBuilder::file_root(Option<PathBuf>)` (default `None` = any path, the CLI byte-identical; `Context::file_root()`), code `src/file_root.rs`, tests `src/file_root_tests.rs` (+ a unit test). With a root: `jobs/define` runs under `AccessPolicy::allow_all().with_file_root(root)` (the engine's `resolve_file`: relative under the root, `..`/symlinks resolved; refusal in the in-band field errors, the engine's text names the root path); `catalog/load` is checked in `api/mod.rs` BEFORE the session call by `file_root::check_catalog` (parses with `catalog_from_json`; a parse failure falls through to the load's own error) = public `jobs_outside_file_root(definitions, root) -> Vec<JobOutsideFileRoot>` (every File effect of every JOB, plus a backup's action path when it has no File effect, since the Store's runner then uses that path as written; refused: relative, any `..` component, or `resolve_file` denies) -> `403` "nothing was loaded: ..." (refuse, not rewrite); `store/fork`, `store/attic/fork`, `store/backup` resolve a requested `dir` through `api/store.rs` `requested_dir` -> `file_root::resolve_in_root` (relative = under the ROOT, not next to the store; `403` "'<dir>' is outside the server's file root: paths must lie inside the server's file root (...)", the root path is not echoed; missing root `500`); the default dir next to the store is unchanged even when the store lies outside the root. The check happens at request time (a symlink planted later inside the root is not seen). Stored jobs of a loaded store are the host's to check with `jobs_outside_file_root` (B12).

## Run administration (issue #32, task I32)

Off by default; `ContextBuilder::admin_runs(token: Option<String>)` turns it on per context (empty token = none; `Context::admin_runs_enabled`); the CLI's `--admin-runs [--admin-runs-token]`. Code `src/api/admin.rs` (checks + answers), route arms in `api/mod.rs` (one per line, for the openapi test), registry side in `runs.rs`.
- `GET /api/admin/runs` -> `{runs: [{id, client, alias, kind, state, cancelled, startedAtMs, durationMs, text, identity, mount}], textHeadChars}` (oldest first; `kind` `RunKind::name`, `state` `RunState::name` `queued`/`running`; `text` = `RUN_TEXT_HEAD_CHARS` head). `POST /api/admin/runs/cancel` `{"id": n}` -> `{cancelled}` (`Runs::cancel_run_in(id, mount)`), 400 without a numeric id, other methods 405 (only while on). Off: both (any method) 404 `admin::OFF` = "the run administration is off: start the server with --admin-runs" (never "unknown endpoint": the CLI's openapi test calls every described route; a host-specific text like the MCP one). Token: header `X-Graphersal-Admin-Token` (not `Authorization`: a host's request headers may carry its own bearer), compared in constant time; missing/wrong 403 (texts in `admin.rs`, the token never echoed, `AdminRuns`'s `Debug` hides it). Allow-list mode refuses both (403) through `allow_listed`. `HostCheck` and the request filter run first (a host authorizes admins by identity there).
- `GET /api/info` `adminRuns: {tokenRequired}` only while on (absent otherwise: answers unchanged). The playground shows its Runs badge from it (`playground/CLAUDE.md`).
- Scope: a context lists and kills only runs whose `RunInfo::mount` equals its `mount_path` (every run carries the registering context's mount: `Context::register_run`, the MCP `Host` impl); a host's cross-graph view calls `Runs::list` / `Runs::cancel_run` directly (all runs). `Runs::start`/`register` register mount `None`.
- `Runs` now always keeps each run's `RunInfo` (also without an observer) plus a running flag. State: `start_with` pushes the run's flag onto a thread-local list (`runs::PENDING`); `Context::call` takes the not-yet-running flags of its thread (`pending_runs`) and its job wrapper sets them when the job starts (`mark_running`): a run is `running` once the first session job its registering thread queued afterwards has started (every registration site queues exactly one job). `end` removes the flag on the ending thread; a flag ended elsewhere is pruned by `Arc::strong_count`.
- Public: `Runs::list() -> Result<Vec<RunEntry>, ServeError>`, `Runs::cancel_run(id) -> Result<bool, ServeError>`, `RunEntry` (`info`, `state`, `duration`, `is_cancelled`), `RunState` (`#[non_exhaustive]`), `RunKind::name`, `RunInfo::mount`, `ContextBuilder::admin_runs`, `Context::admin_runs_enabled`. No MCP tool (an operator's act, not an agent's).
- Tests `src/api/admin_tests.rs` (off = 404 and no info field; another client's running + queued run listed, text head, kill queued then running, own `/api/cancel` reaches neither, ended run false, 400/405; token 403/200; allow-list 403; mount scoping), `runs.rs` unit tests (list/state/cancel by id, pending flags), CLI `server_tests.rs` `the_run_administration_lists_and_kills_other_clients_runs`.

## Protocol marker, host name, dev flag (user decision 2026-11-22, task P6)

Every `GET /api/info` of every context carries `"protocol": "graphersal/1"` (`api/mod.rs` `PROTOCOL`, re-exported): the playground recognizes a Graphersal host ONLY by it (`playground/js/engine/http-engine.js` `isEngineInfo` / `PROTOCOLS`), never by `server`. A breaking change of the playground HTTP API (a removed/renamed endpoint or field, a changed meaning) bumps the number, and the playground's `PROTOCOLS` lists what it speaks; additions do not bump it. `server` is only the host's name: `ContextBuilder::server_name` (default `DEFAULT_SERVER_NAME` = `graphersal-dev`, the CLI's; the former `SERVER_ID` was renamed to it in P6). `dev` is explicit: `ContextBuilder::dev(bool)`, default `false`; the CLI sets `true`; the playground's DEV SERVER badge reads `info().dev`. The MCP `serverInfo.name` is separate (`graphersal-mcp` `McpConfig::server_name`).

## Mounting under a URL prefix (plan `ai/graphersal-server/PLAN.md` H3, decision Q3)

A host serving several graphs mounts each `Context` under `/db/<name>/`. The core does NOT route by prefix (no registry here, crate role): the HOST strips `/db/<name>` when it builds the `Request` (`/db/acme/api/info` -> `/api/info`, `/db/acme/` -> `/`), drops a client's own `X-Graphersal-Graph` and sets it to the name, and its `GraphResolver` picks the context by that header, like the reference resolver does for `/mcp/<name>` (`extension_tests::reference_resolver`). Name map, aliases, the 409 "not loaded" pre-check, the `/db/x` -> `/db/x/` redirect (the playground's URLs are relative: `index.html` has no root-absolute `src`/`href`, `http-engine.js` builds `api/` from `import.meta.url`), the landing page and the server-root `/api/admin/*` are the host's (a mounted context's own run administration answers at `/db/<name>/api/admin/runs`, section "Run administration"). The core adds only: `ContextBuilder::mount_path(Option<String>)` (normalised to `/a/b`, `""`/`/` = root; `Context::mount_path`) = `GET /api/info` `mountPath` + `openapi` `<mount>/openapi.json`, the MCP status `endpoint` `<mount>/mcp` (`mcp.rs` `endpoint_status` overrides `Mcp::status`'s `/mcp`; `/api/info` and `/api/changes`); without a mount every answer is byte-identical. One `HostCheck` per listener (Origin is path-independent) with the host's `with_hint`. Upload: `Request::copy_body_to(out, max)` streams the body into a host sink (64 KiB buffer; 413 `the body is larger than <max> bytes` on a declared length above `max` before reading, or when the read passes `max`, nothing beyond `max` written; 400 read failure, 500 sink failure); a refused request leaves its body unread, so the host's listener drains or closes it (the CLI's `tiny_http` adapter never answers a declared body above `MAX_DECLARED_BODY_BYTES` = 64 MiB). Tests `src/mount_tests.rs` (two contexts under `/db/a/` and `/db/b/` behind a header resolver: no cross-talk, `mountPath`, MCP endpoint and calls per mount, UI index/asset/reset per mount, Host/Origin 403 with the hint on both, the default texts, normalisation, `copy_body_to` above `MAX_BODY_BYTES`, declared/undeclared 413, failures).

## Rules

- No HTTP library, no async runtime (`cargo tree -p graphersal-serve` must show no `tiny_http`/`hyper`/`ureq`/`tokio`). The host converts its requests: keep the boundary types small and owned by this crate.
- Behaviour moves here unchanged: texts of errors (incl. the CLI flag names they mention), status codes, headers. A change shows in the CLI's `server_tests.rs`.
- Logging through `tracing` only (target `graphersal::server`); the host owns stdout/stderr.
- `serde_json::Value` in the public API is on purpose (`JobQueue::status`, `Hooks::add_info`/`add_process_statistics`, `ContextBuilder::presets`, `Request::json_body`, `Response::json`): a JSON-boundary crate like `graphersal-session`, an exception to root rule 8; the crate docs say so.
- No `unwrap` on a request path (root rule 1): store I/O failures (e.g. `api/store.rs` `is_single_file`, the backend's space usage) are `HttpError(500, ..)`.
- Tests (MCP, feature `mcp`, in `extension_tests.rs`): one endpoint over two graphs behind the resolver (shared statistics), two contexts over one session with two profiles (use = read-only policy, develop), `Context::mcp_connection` with an identity reaching the run observer, a session of the request filter's identity not borrowable by another identity or anonymous (both ways, `DELETE` too, table and signed: `an_mcp_session_of_the_context_cannot_be_borrowed_by_another_identity`), the request filter's identity reaching MCP runs. The reference multi-graph resolver (S5.3, module `extension_tests::reference_resolver`, book `for_developers/serving_layers.md`; test code only, D5: no pool or catalog in this crate): a `BaseRef`-keyed pool of `LayerBase`s (one `MemDir` store, three marks), a catalog (versions `<name>@<version>`, aliases, kept pins), the host's path rewrite `/mcp/<name>` -> `/mcp` + `X-Graphersal-Graph` (a client's copy dropped), contexts with `.layered(true)` + `.mcp_session_route` + one shared `Arc<Mcp>` + per-context profiles, the name check over `Mcp::verified_session_route`, alias flip / explicit pin / shared base / refusals / retirement (`retire_idle(grace)`, `evict_unused_bases`), each in table and signed mode.
- Tests: `src/api/boundary_tests.rs` (routing, body limit, Host/Origin, cancel, hooks, a refusing queue, MCP through the boundary; a real session thread on the `modern` sample, no HTTP), `src/extension_tests.rs` (one test per extension point: two graphs behind a resolver, observer + cancel handle incl. MCP tool runs, a token filter with identity, extra routes, lifecycle probes/503s/hooks/idle, a host queue with takeover), the job ticker's stop / detach and the context release, `background_runs`, the `ServeError` -> `HttpError` statuses, `src/read_only_tests.rs` (the runtime toggle: an open MCP session + a page refused/answered/allowed again, a write queued before the flip commits, the ticker pauses, initial read-only with the host's help, no toggle = `Unsupported`), `src/mount_tests.rs` (mounting and uploads, section "Mounting"), `src/directory_tests.rs` (feature `mcp`, H4: one `graphersal_mcp::Mcp::handle_directory` endpoint over two real contexts behind a test `GraphDirectory`: `host(route)` = the `Arc<Context>` as `Arc<dyn Host>` + `context.mcp_profile()`; select, write, `graph` override, alias flip (the session follows the alias), the runtime read-only toggle refusing a write, an unloaded graph's 409-style text), `src/launch_tests.rs` (one launch per `ServedSource` kind, a layer store over a store's base and over a given `LayerBase`, the open notes and refusals; `MemDir` stores, files in the temp dir), plus the moved unit tests of `runs.rs`, `ui.rs`, `api/store.rs`, `api/mod.rs`.
