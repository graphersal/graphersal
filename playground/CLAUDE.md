# Playground

Agent guidance for the static browser playground (Vue, no bundler). It runs `graphersal-wasm` in a Web Worker; `playground/build.sh` builds it into `playground/pkg/` (git-ignored, goes stale: rebuild after engine/DSL/session changes). The dev server embeds `index.html`, `css/`, `js/`, `assets/`, `reset/` only. See `playground/README.md`: its "Graph drawing" section holds the measured Cytoscape tuning and layout timings.

- Top bar **Catalog ▾** (`js/components/catalog.js`, models `js/compression.js`, `js/indexes.js`, `js/saved-queries.js`, `components/saved-queries.js`) lists the catalog's kinds with counts, opens their managers (Saved queries, Compression, Property indexes, Scheduled jobs: `JobsManager`, model `js/jobs.js`, `tests/jobs.test.mjs`, store actions `refreshJobs`/`defineUserJob`/`dropUserJob`/`switchJob`/`scheduleSystemJob`/`runJobNow`; its menu item is added in `CatalogMenu`, not in `catalogMenuItems`) and holds the one catalog file (`graphersal-catalog-<stamp>.json`). Saved queries are managed and run only there (the Query panel has no Saved menu); the run form writes `g.query(..)` into a tab. The editor's Rhai / GQL switch (`language` in the spec only for GQL; GQL highlighting `js/editor/gql-language.js` over the pure tokenizer `js/editor/gql-tokens.js`); the tab menu's "Save as query…" (`saveTabAsQuery` -> `openCatalog('save-as-query')`, model `draftFromScript`/`parseGqlCall`: one `g.gql(..)` call becomes a GQL draft with its `$params`).
- Top bar **Optimize** (`js/components/optimize.js`, pure model `js/optimize.js`, `tests/optimize.test.mjs`; `openOptimize()`/`optimizeApplied()` in `store.js`): one dialog, tabs Recommendations (engine `advise(spec)`, Apply = `applyRecommendation(id, spec)`, Copy command, Snooze 7 days / Dismiss, sections Applied (outcomes) and Dismissed (Restore), "Every candidate"), Workload (`workloadReport(tier)`: lists x window x channel, sparkline per row from the window's tier, a row opens an inline-SVG detail chart with the tier switch; no chart library), Memory (`memoryReport({})`: totals, properties, labels).
- Store: every Store menu/dialog action (`store-menu.js`) runs through `runStoreTask` (`js/store.js`, `state.storeTask`): one at a time, shown on its button (`components/store-task-label.js`), on the top-bar Store button and in a live region (texts `STORE_TASKS` in `js/store-model.js`). The WebAssembly playground shows it on its store in memory too.
- Store menu **Models** section (`store-model.js` `modelRows`, from `GET /api/store` `models`/`missingModels`) and, when the store keeps models, a second snapshot download **.gsnap without models** (`snapshotUrl(commit, false)` = `&models=without`; wasm `storeSnapshotWith`; `snapshotFileName`).
- Highlighter token classes: `js/editor/token-classes.js` (fallback + what `tokenValues()` reports).
- Query panel "+" opens a Query, a **GQL query** or an **AI Chat** tab (tab kind `ai` in `js/tabs.js`; model + per-tab controller `js/ai-chat.js`: own conversation, `after` cursor and poll loop per tab, `/clear` and `/help` local; view `components/ai-chat.js`; answers through the own safe Markdown renderer `js/markdown.js` + `components/markdown-view.js`, never HTML). Works only with the dev server's `--ai`; read-only in the WebAssembly playground.
- Schema panel infers only on first show and its refresh button (`js/schema/panel-sync.js`): a graph change re-reads only the stored schema and otherwise shows "may be outdated - refresh"; a replaced graph (`state.graphEpoch`) is inferred once when shown.
- Change feed: `js/change-feed.js` polls `GET /api/changes` and reloads on changes it did not make. While they come fast (external changes in `BURST_POLLS` polls within `BURST_WINDOW_MS`), `js/change-burst.js` (pure state machine, `tests/change-burst.test.mjs`) throttles reloads to one per `BURST_REFRESH_MS` (banner `components/change-burst-banner.js`: Refresh now, Pause auto refresh / Resume) until `BURST_QUIET_MS` without one; a view opened or closed elsewhere still reloads at once.
- Graph drawing: model `js/graph-data.js`; drawings go through the renderer interface `js/graph/renderer.js` (two tiers: Cytoscape is Detailed, `js/graph/cytoscape-renderer.js`; sigma.js + graphology on WebGL is Fast, `js/graph/sigma-renderer.js`; cdnjs UMD scripts with SRI injected on first use). **Never call a drawing library from a panel.** `js/graph/tiers.js` picks the tier (size with hysteresis, Auto/Detailed/Fast, no-WebGL fallback) and derives banner and disabled controls from `capabilities`; `js/graph/controller.js` picks the layout (Cytoscape's own up to 200 vertices, else the engine's; always the engine's in Fast) and swaps renderers keeping positions; toolbar Stop cancels layouts via `js/graph/layout-jobs.js`; label colours `js/graph/palette.js`. Result highlight and its Clear/Esc dismissal: `js/graph/highlight.js`. Toolbar: a compact row (Filter split button, Layout, Edit, Clear highlight, Fit, Export) plus the ⚙ Display menu (tier, IDs, edge labels, highlight, vertex size by degree: `js/graph/size-by.js` scale per vertex -> renderer `nodeScale`, degrees requested only when not Off, help); `js/graph/toolbar.js` `toolbarFit` (pure, measured row) moves Layout/Edit/Filter into the menu when narrow. Filter: pure model `js/graph/filter-model.js` (state -> engine `GraphFilter`, op lists by schema type, never sniffed; apply mode/queue; client label filter) + popover `components/graph-filter.js` (anchored under the Filter button at the panel's left edge, clear of the inspector on the right; vertex label swatches from `palette.js` `labelSwatch`, no colour guessed for a label never drawn); persisted per graph (`graph.filter.<kind>:<name>`), the switch disables without deleting; engine filter for whole graph and neighbourhood, by label on the client for results and samples, faded labels in the overview (README "Graph drawing"). The Statistics tab (`js/statistics.js`, `components/statistics-view.js`) has a hidden-when-empty "Process memory" section (`processMemoryRows`: `process.memory` (RSS with peak, live heap, wasm memory), models and the dev server's AI Chat history from `statistics().process`); the inspector rows (`inspectorRows`) show `edges: in N · out M` from the vertex's `inDegree`/`outDegree`; the AI Chat shows `timingText` (the `done` event's `elapsedMs`/`toolMs`) under each answer. Long values (inspector, Results table) collapse through `js/value-view.js` + `components/value-text.js` (setting `valueMaxChars`).
- Query panel **Examples** (`components/examples-panel.js`, model `js/examples-panel.js`; hidden in server mode, `isServerMode()`: the examples are written for the sample graphs): an overlay drawer (never a docked panel), opened by click or a 300 ms hover; plain substring search over titles and scripts, collapsible groups, last opened example and scroll restored (localStorage via `util.js` `storage`). Examples carry `group` and an optional `subgroup` (the GQL group is split): Rust tests (`graphersal-wasm`'s `playground_*examples*`, which filter `group == "GQL"`) and the MCP examples resource read `group` only, so keep `group: "GQL"` on every GQL example; groups and subgroups stay contiguous in the file (checked by `tests/examples-panel.test.mjs`).
- Query tabs have a language: Rhai or **GQL** (`tab.language`/`tab.params` in `js/tabs.js`; model `js/gql-tab.js`: switch rewrite, Parameters JSON reader, run text = the engine's `gql_call_text`, error span; completion `js/editor/gql-complete.js` (pure) + `gql-completion.js` (after `CALL`: the saved GQL queries of `state.savedQueries` as `folder.name`, `gqlProcedureChoices`; tokenizer type `procedure`), functions `js/editor/gql-functions.js` checked against `crates/graphersal/src/gql/parser.rs` `FUNCTIONS` by `tests/gql-complete.test.mjs`; saved-query body parameters `js/editor/param-completion.js`). Examples may carry `lang: "gql"` + `params`; the Rust example tests and MCP's examples resource run them through `gql_call_text`. README "GQL query tabs".
- Scheduled jobs: `js/engine/worker.js` `startJobTicker` sets the browser's zone (`setTimeZone`) and calls `tickJobs(Date.now())` every 5 s between requests (the host drives the engine's scheduler).
- Links: `js/link.js` format `#/play?graph=..&q=..&run=1` (`&lang=gql&params=..` for a GQL tab; the book's run buttons use it).
- Tests: `node --test playground/tests/*.test.mjs`. Serve with `python3 playground/serve.py 8000` (no-store caching).
