# Playground

Agent guidance for the static browser playground (Vue, no bundler). It runs `graphersal-wasm` in a Web Worker; `playground/build.sh` builds it into `playground/pkg/` (git-ignored, goes stale: rebuild after engine/DSL/session changes). The dev server embeds `index.html`, `css/`, `js/`, `assets/`, `reset/` only. See `playground/README.md`: its "Graph drawing" section holds the measured Cytoscape tuning and layout timings.

- Catalog ▸ Compression (`CompressionManager` in `js/components/catalog.js`; model `sortRules`/`groupRules`/`groupCollapsed`/`selectionState`/`toggleNames`/`dropSelection` in `js/compression.js`): sortable columns (default: saved, descending), group by codec/label/nothing (a group of more than `COLLAPSE_ABOVE` rules starts collapsed), a checkbox per rule and group, "Drop selected" = confirm + `dropCompressions(names)` (one commit, one walk); the table never scrolls sideways.
- Top bar **Catalog ▾** (`js/components/catalog.js`, models `js/compression.js`, `js/indexes.js`, `js/saved-queries.js`, `components/saved-queries.js`) lists the catalog's kinds with counts, opens their managers (Saved queries, Compression, Property indexes, Scheduled jobs: `JobsManager`, model `js/jobs.js`, `tests/jobs.test.mjs`, store actions `refreshJobs`/`defineUserJob`/`dropUserJob`/`switchJob`/`scheduleSystemJob`/`runJobNow`; a **running** badge from the entry's `running` plus the page's own unanswered runs (`jobRowsWithRuns`), list reloaded every second while `anyJobRunning`, Run now disabled for a running job only, the rest of the dialog stays usable; its menu item is added in `CatalogMenu`, not in `catalogMenuItems`), the **System journal…** entry (section "Kept by this instance", not a catalog kind: `components/journal.js` `JournalPanel`, pure model `js/journal.js` (opens on a `newest_first` page, follows with `after` through the shared follower while open (newest `JOURNAL_KEEP` kept; `open(record)` scrolls to and highlights a record), `JOURNAL_PAGE_ROWS` rendered, "Show more" renders held rows then pages backwards with `before` = `next_before`), `tests/journal.test.mjs`; engine `journal(spec)` on both engines, store action `journalPage`) and holds the one catalog file (`graphersal-catalog-<stamp>.json`). Saved queries are managed and run only there (the Query panel has no Saved menu); the run form writes `g.query(..)` into a tab. The editor's Rhai / GQL switch (`language` in the spec only for GQL; GQL highlighting `js/editor/gql-language.js` over the pure tokenizer `js/editor/gql-tokens.js`); the tab menu's "Save as query…" (`saveTabAsQuery` -> `openCatalog('save-as-query')`, model `draftFromScript`/`parseGqlCall`: one `g.gql(..)` call becomes a GQL draft with its `$params`).
- Journal notifications (toasts, top right): `components/journal-toasts.js` `JournalToasts` (in the Workspace), pure model `js/journal-toasts.js` (`createToasts`: at most `TOAST_VISIBLE`, "+N more", merge by kind+message, warn/error sticky, others `TOAST_LIFE_MS` paused on hover, injectable clock; `createJournalFollower`: THE one journal poller (store.js `journalFollower()`), starts at the journal's end (`newest_first` limit 1), `after` every 5 s server / 2 s wasm while visible and subscribed, one request in flight, silent backoff, `rebase()` on `graphEpoch`; the open `JournalPanel` subscribes too via `batchAsPage`), `tests/journal-toasts.test.mjs`; setting `settings.journalToasts` (`notice`|`warn`|`error`|`off`); a click = `openJournalAt(record)`.
- Top bar **Optimize** (`js/components/optimize.js`, pure model `js/optimize.js`, `tests/optimize.test.mjs`; `openOptimize()`/`optimizeApplied()` in `store.js`): one dialog, tabs Recommendations (engine `advise(spec)`, Apply = `applyRecommendation(id, spec)`; with more than one recommendation a checkbox each, "Select all" per `advice.groups` entry, nothing ticked by default, "Apply selected" = confirm + `applyRecommendations(ids, spec)` (one commit; model `recommendationGroups`/`toggleGroup`/`selectionSummary`, `tests/optimize-selection.test.mjs`; after a change of compression rules on a store, a note with "Write a snapshot now" until a snapshot holds that commit: `checkpointDue`, book `persistence/optimize.md`), Copy command, Snooze 7 days / Dismiss, sections Applied (outcomes) and Dismissed (Restore), "Every candidate"), Workload (`workloadReport(tier)`: lists x window x channel, sparkline per row from the window's tier, a row opens an inline-SVG detail chart with the tier switch; no chart library), Memory (the process memory bar from `statistics()`, then `memoryReport({})`: totals, properties, labels).
- Process memory bar: ONE component `components/memory-bar.js` (`MemoryBar`, prop `stats` = a `statistics()` answer) in BOTH places that show memory (Profile panel -> Statistics tab, Optimize -> Memory); pure model `js/memory-bar.js` (`memoryBarModel`, `memoryLevel` normal < 70 <= amber <= 90 < red, `queryPeakModel` for the Profile panel's "Peak memory" line from `query_memory`; `tests/memory-bar.test.mjs`, `tests/profile-text.test.mjs`) renders `process.memory.segments` as computed in Rust (`graphersal_session::process::MemoryBar`: graph segments, then `models`, `live_graph`, `store`, `engine`, `other`), never recomputing them; a segment's `parts` go into its tooltip (`partLines`); segment colours are the CSS tokens `--mem-<segment>` (light and dark). The Statistics tab does not repeat the components table (it needs the report's walk): its button opens Optimize -> Memory (`openOptimize('memory')`, `state.optimizeTab`).
- Store: every Store menu/dialog action (`store-menu.js`) runs through `runStoreTask` (`js/store.js`, `state.storeTask`): one at a time, shown on its button (`components/store-task-label.js`), on the top-bar Store button and in a live region (texts `STORE_TASKS` in `js/store-model.js`). The WebAssembly playground shows it on its store in memory too.
- **Download current state** (Store menu) and **Save ▸ Snapshot** (browser engine) go through `saveCurrentSnapshot` (`js/store.js`): a store that keeps models asks first (`components/snapshot-choice-dialog.js`, model `snapshotModelChoice` in `store-model.js`, issue #23); `saveGraph('snapshot', {withModels})`, never `saveGraph('snapshot')` from a menu.
- Store menu **Models** section (`store-model.js` `modelRows`, from `GET /api/store` `models`/`missingModels`) and, when the store keeps models, a second snapshot download **.gsnap without models** (`snapshotUrl(commit, false)` = `&models=without`; wasm `storeSnapshotWith`; `snapshotFileName`).
- Highlighter token classes: `js/editor/token-classes.js` (fallback + what `tokenValues()` reports).
- Query panel "+" opens a Query, a **GQL query** or an **AI Chat** tab (tab kind `ai` in `js/tabs.js`; model + per-tab controller `js/ai-chat.js`: own conversation, `after` cursor and poll loop per tab, `/clear` and `/help` local; view `components/ai-chat.js`; its header's **Export ▾** downloads the tab's transcript as Markdown (questions, final answers, one `answerLine` per turn with time and tool-call count; no steps) / JSON (every step) via the pure `chatToMarkdown`/`chatToJson` (`chatExportModel`, JSON format `graphersal-ai-chat` version 1, documented in the book's AI Chat section: change it only additively or raise the version) and `export.js` `downloadBlob`; the running turn's live "Working for N s" clock: `chat.startedAt` (runtime, set on Send, cleared on done/Stop/gone/`/clear`) + `liveElapsedMs`/`secondsText`/`createClock` in the model, the view's interval stops with the turn and on unmount; answers through the own safe Markdown renderer `js/markdown.js` + `components/markdown-view.js`, never HTML). Works only with the dev server's `--ai`; read-only in the WebAssembly playground.
- Schema panel infers only on first show and its refresh button (`js/schema/panel-sync.js`): a graph change re-reads only the stored schema and otherwise shows "may be outdated - refresh"; a replaced graph (`state.graphEpoch`) is inferred once when shown.
- Change feed: `js/change-feed.js` polls `GET /api/changes` and reloads on changes it did not make. While they come fast (external changes in `BURST_POLLS` polls within `BURST_WINDOW_MS`), `js/change-burst.js` (pure state machine, `tests/change-burst.test.mjs`) throttles reloads to one per `BURST_REFRESH_MS` (banner `components/change-burst-banner.js`: Refresh now, Pause auto refresh / Resume) until `BURST_QUIET_MS` without one; a view opened or closed elsewhere still reloads at once.
- Graph drawing: model `js/graph-data.js`; drawings go through the renderer interface `js/graph/renderer.js` (two tiers: Cytoscape is Detailed, `js/graph/cytoscape-renderer.js`; sigma.js + graphology on WebGL is Fast, `js/graph/sigma-renderer.js`; cdnjs UMD scripts with SRI injected on first use). **Never call a drawing library from a panel.** `js/graph/tiers.js` picks the tier (size with hysteresis, Auto/Detailed/Fast, no-WebGL fallback) and derives banner and disabled controls from `capabilities`; `js/graph/controller.js` picks the layout (Cytoscape's own up to 200 vertices, else the engine's; always the engine's in Fast) and swaps renderers keeping positions; toolbar Stop cancels layouts via `js/graph/layout-jobs.js`; label colours `js/graph/palette.js`. The drawing never makes the panel scroll: `.cy-host` clips (renderers round canvases up to whole pixels) and `js/graph/resize-guard.js` resizes the renderer only on a whole-pixel change (else classic Windows scrollbars flicker in a resize loop). Result highlight and its Clear/Esc dismissal: `js/graph/highlight.js`. Toolbar: a compact row (Filter split button, Layout, Edit, Clear highlight, Fit, Export) plus the ⚙ Display menu (tier, IDs, edge labels, highlight, vertex size by degree: `js/graph/size-by.js` scale per vertex -> renderer `nodeScale`, degrees requested only when not Off, help); `js/graph/toolbar.js` `toolbarFit` (pure, measured row) moves Layout/Edit/Filter into the menu when narrow. Filter: pure model `js/graph/filter-model.js` (state -> engine `GraphFilter`, op lists by schema type, never sniffed; apply mode/queue; client label filter) + popover `components/graph-filter.js` (anchored under the Filter button at the panel's left edge, clear of the inspector on the right; vertex label swatches from `palette.js` `labelSwatch`, no colour guessed for a label never drawn); persisted per graph (`graph.filter.<kind>:<name>`), the switch disables without deleting; engine filter for whole graph and neighbourhood, by label on the client for results and samples, faded labels in the overview (README "Graph drawing"). The Statistics tab (`js/statistics.js`, `components/statistics-view.js`) has a hidden-when-empty "Process memory" section (`processMemoryRows`: `process.memory` (RSS with peak, live heap, wasm memory), models and the dev server's AI Chat history from `statistics().process`); the inspector rows (`inspectorRows`) show `edges: in N · out M` from the vertex's `inDegree`/`outDegree`; the AI Chat shows `timingText` (the `done` event's `elapsedMs`/`toolMs`) under each answer. Long values (inspector, Results table) collapse through `js/value-view.js` + `components/value-text.js` (setting `valueMaxChars`).
- Query panel **Examples** (`components/examples-panel.js`, model `js/examples-panel.js`; profile key `examples`, `full`: WebAssembly only, the examples are written for the sample graphs): an overlay drawer (never a docked panel), opened by click or a 300 ms hover; plain substring search over titles and scripts, collapsible groups, last opened example and scroll restored (localStorage via `util.js` `storage`). Examples carry `group` and an optional `subgroup` (the GQL group is split): Rust tests (`graphersal-wasm`'s `playground_*examples*`, which filter `group == "GQL"`) and the MCP examples resource read `group` only, so keep `group: "GQL"` on every GQL example; groups and subgroups stay contiguous in the file (checked by `tests/examples-panel.test.mjs`).
- Query tabs have a language: Rhai or **GQL** (`tab.language`/`tab.params` in `js/tabs.js`; model `js/gql-tab.js`: switch rewrite, Parameters JSON reader, run text = the engine's `gql_call_text`, error span; completion `js/editor/gql-complete.js` (pure) + `gql-completion.js` (after `CALL`: the saved GQL queries of `state.savedQueries` as `folder.name`, `gqlProcedureChoices`; tokenizer type `procedure`), functions `js/editor/gql-functions.js` checked against `crates/graphersal/src/gql/parser.rs` `FUNCTIONS` by `tests/gql-complete.test.mjs`; saved-query body parameters `js/editor/param-completion.js`). Examples may carry `lang: "gql"` + `params`; the Rust example tests and MCP's examples resource run them through `gql_call_text`. README "GQL query tabs".
- Scheduled jobs: `js/engine/worker.js` `startJobTicker` sets the browser's zone (`setTimeZone`) and calls `tickJobs(Date.now())` every 5 s between requests (the host drives the engine's scheduler).
- Links: `js/link.js` format `#/play?graph=..&q=..&run=1` (`&lang=gql&params=..` for a GQL tab; the book's run buttons use it).
- Top-bar **MCP** badge (dev server with `--mcp`) is a button: the **MCP usage** dialog (`components/mcp-stats.js` `McpStatsDialog`, pure model `js/mcp-stats.js` `mcpStatsModel`, `tests/mcp-stats.test.mjs`; engine `mcpStats()` = `GET /api/mcp/stats`, http engine only), loaded on open and by Refresh, no polling.
- **UI profiles** (EXPERIMENTAL; book `users_guide/web_playground.md` "UI profiles"): pure model `js/ui-profiles.js` (`tests/ui-profiles.test.mjs`: format, `validateProfile` naming every problem, `resolveProfile`, `createUi(profile, {server})` with `can(key)` over `CAN_KEYS` (values true/false/'wasm'/'server', missing = false, unknown key = false + one warning), the routes `routeHash`/`tabRouteFromHash`/`requestedProfile`). Built-ins `full` (= the playground as it always was: one `builtin: 'workspace'` tab, no tab row) and `demo` (`js/profiles/demo/hello.js`). Delivery: `info().uiProfile` (dev server `--ui-profile`, `ContextBuilder::ui_profile`; `HttpEngine.info` passes it on) or the wasm link parameter `profile=` (built-ins; kept in every hash `router.js` `hashOf` writes; another one reloads the page); `store.js` `applyProfile` sets `state.ui`/`state.profileError` (`checkApiMode(profile, info.apiMode)`: a server in allow-list mode (`info().apiMode === 'allow-list'`, `ContextBuilder::api_allow_list`) answers only info/changes/query, so a profile with the workspace is an error there; a no-workspace profile calls only `GET /api/info` at boot, then `POST /api/query`) (a boot-style error page in `main.js`, never another profile). Components ask `can('<key>')` (store.js) for UX; `isServerMode()` stays for ENGINE facts (one served graph, its files, its change feed, the journal cadence, texts naming the server). A profile without the workspace never attaches the served graph. Module tabs: `components/profile-tab.js` (`defineAsyncComponent(() => import(files + module))`, keep-alive, error card on load/render failure) with props `api` (`js/profile-api.js`, pure, `tests/profile-api.test.mjs`; `query` = store.js `profileQuery` = engine `runSavedQuery(name, params)`: dev server `POST /api/query`, wasm worker `runSavedQuery`; a server refusal becomes `{ok: false, error}`) and `params`; `api.card(label, row, options)` renders `components/profile-card.js` (`ProfileCard`, render function, text nodes only; Markdown through `MarkdownView`, field values through `ValueText`/`valueMaxChars`; action errors become error toasts; CSS `.profile-card*` on the theme tokens, `tone-<tone>` badges, one column under 520px) over the pure model `js/profile-cards.js` (`tests/profile-cards.test.mjs`: template keys `title`/`subtitle`/`badges`/`body`/`excerpt`/`fields`/`actions`, parts `{field, title, text, prefix, format, tone, when, unless}`, field paths with element-properties-first lookup and one-item-list unwrap, missing = absent/null/''/[] renders nothing, `cardTemplateProblems`/`cardsProblems` (called by `validateProfile`), `checkCardOptions` (called by `api.card`: `variant` full|compact, `selected`, `onOpen`, `actions`, `onAction`), `cardModel`). Templates are JSON (no callbacks): buttons show only with the module's `onAction`. `full` has no cards; `demo` has a `person` card (its Hello tab: compact list + opened full card, one action). Graph views (E5): `api.graph(data, options)` renders `components/profile-graph.js` (`ProfileGraph`, render function) over the pure model `js/profile-graph.js` (`tests/profile-graph.test.mjs`: profile key `graph` = `{nodes, edges, classes, legend, legendLabels}` checked by `graphSpecProblems` (called by `validateProfile`), `checkGraphData` (`GraphDataError` naming every problem), `resolveNodeStyle`/`resolveEdgeStyle` (defaults < `"*"` < label < classes (element's, then `styleOf`'s; profile class else `BUILTIN_CLASSES` faded/bold/dashed) < `styleOf` keys), `styledView` = a compact graph view + `nodeStyle`/`edgeStyle`/`edgeName` columns, `legendEntries`, `mergeGraph` (= `api.mergeGraph`; an added edge may end at a base node), `carryPositions` (kept vertices stay, new ones next to their neighbours, deterministic), `highlightIds`, `selectionOf`, `checkGraphOptions`). It draws through the Graph panel's renderers and `GraphController` (no second renderer): `toCyElements` gives styled views the class `styled` + style data (`node.styled`/`edge.styled` rules in `cytoscape-renderer.js`), sigma colours/sizes them (no shapes/dashes); optional renderer method `zoomBy`; `GraphController` option `tuning` (allow-list mode: no engine layout, `cose` up to `NO_ENGINE_COSE_MAX`). Views without styles (the Graph panel's) are drawn exactly as before. `demo` has a `graph` key and a Graph tab (`js/profiles/demo/graph.js`: saved queries `demo_graph`/`demo_neighbours`, expand merges, `styleOf` classes, side card with an action). Profile key `version` (optional, the product's version): the header shows `v<version>` (`build-info.js` `versionLabel(engine, build, profile)`, engine version in the tooltip). Host request headers (EXPERIMENTAL): `window.GRAPHERSAL_ENGINE = {headers}` set by a classic script before the modules, read once by `HttpEngine.detect`/constructor (`hostHeaders`: valid tokens only, never the engine's own `Accept`/`Content-Type`/`X-Graphersal-Client`, problems name the header never the value), sent with every engine request; `snapshotUrl` answers null then (links cannot carry headers); book "Request headers of a host". CDN files carry SRI everywhere (lazy ones through `js/cdn-script.js`; mermaid is cdnjs's single-file build); the test checks it.
- Tests: `node --test playground/tests/*.test.mjs`. Serve with `python3 playground/serve.py 8000` (no-store caching).
