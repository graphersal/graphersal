# py-graphersal (Python package `graphersal`)

Agent guidance for the PyO3/maturin binding (`abi3-py310`, `publish = false`). Build/test commands are in the root `CLAUDE.md` and `README.md` here.

- `Graph.from_graphml`/`from_graphson` take `schema=`/`mode=` (set on the empty graph first, then the file imported as one unit); `graph.import_graphml`/`import_graphson` import into a live graph as one unit (no `policy=`: they wrap `GraphImport`, not the script entry). Scripts allow everything; `policy=AccessPolicy..` per call.
- Scripts evaluate on a 64 MiB stack thread (`script_thread.rs`). The extension installs the `alloc-tracking` allocator in `lib.rs`; as a `cdylib` it counts only its Rust heap, never Python objects, so the process memory ceiling (on by default; `graphersal.set_memory_limit(limit, headroom=)`/`memory_limit()` in `lib.rs`, the ONLY way to set it: no constructor takes `memory_limit=`; `Graph.load` and every Store open are checked by the engine itself in `persist::load_snapshot`) must leave room for the Python side. The per-query limit: `graph.set_limits(max_materialized_bytes=)`, read back with `graph.limits()` (`GraphLimits`, put on every source of the graph's scripts through `script::with_traversal_presets`; `0` = unlimited).
- Embedding models (0.5.0: no external embedder; `src/embedder.rs`, `Embedder`, `Model2Vec`, `embedders=`/`default_embedder=`, `register_embedder` removed): the engine serves the models of the graph's database (a Store's catalog; a `.gsnap`'s packed blobs through `persist::read_snapshot_file` in `Graph.load`, its `SnapshotLoadReport::notes` as `UserWarning`s) plus `hash-ngram/1`; scripts get them through the eval entry points (no scope). `Store.import_model(source)` / static `Store.import_model_into(path, source)` (`persist::ModelCache` lookup: a cached repository first, else a directory), `store.set_default_model(repo)`; an open of a store with models but no default is a `UserWarning` (the CLI's note). Feature `model2vec` (default) = the engine can load the database's models.
- **GIL rule:** no binding path waits for a graph lock while holding the GIL (every lock inside `py.detach`): another Python thread may hold the lock (a long query, an atomic script). No Python code runs under a graph lock any more (no Python embedders).
- Store: `graphersal.Store` (`create_file/open_file/convert/upgrade`, `prune/compact/compaction_advice`; `err.cause` = `StoreFailure::name()`). Embedding models: `store.models()`, `store.import_model`, `store.export(path, without_models=)`; `Store.open/open_file/open_backup` go through `wrap_opened` (the no-default note) (tests `tests/test_store_models.py`).
- Temporal (`src/temporal.rs`, module doc = the mapping table): stdlib `datetime` types to the microsecond; a value with digits below it -> `pandas.Timestamp` (datetime/localdatetime) / `pandas.Timedelta` (duration without months within an int64 of ns; else `Interval`, which holds ns: `nanos`, `micros` raises), pandas imported lazily (optional extra `graphersal[pandas]` in `pyproject.toml`, never a hard dependency; missing -> `ImportError` naming the extra); a time of day with ns -> `ValueError`. The type depends on the value only. Parameters read `nanosecond`/`nanoseconds` of the pandas types, `pytz` `zone` names, refuse `NaT`. Tests `tests/test_temporal_pandas.py` run in both environments (skip markers): run pytest once with and once without pandas installed.
